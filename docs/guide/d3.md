## The lift q*

`Lift` computes the paper's lift q*(s) once, offline: at each of 2001 grid nodes, the configuration over γ(s) nearest the rest posture q_r, stored with q*′ in a periodic cubic Hermite spline that `eval` reads at 1 kHz. This section also covers the two Newton solvers in `lift.cpp`, the minimum check and the diagnostics.

### The problem being solved

At each s, q*(s) solves

```latex
\min_q\ \tfrac12\|q - q_\mathrm r\|^2 \quad\text{subject to}\quad \Pi(q) = \gamma(s)
```

The constraint's derivative in body coordinates is J_b(q), so the Lagrange condition is q − q_r ∈ range(J_bᵀ). Equivalently, the component of q − q_r in ker J_b vanishes: (I − J⁺J)(q − q_r) = 0, where J⁺ = Jᵀ(JJᵀ)⁻¹ is the pseudoinverse and I − J⁺J the orthogonal projector onto ker J. For r = 1 that kernel is span x(q), so I − J⁺J = x xᵀ and the condition is the scalar h(q) = x(q)ᵀ(q − q_r) = 0.

The class and its interface:

```cpp
// include/se3pf/lift.hpp:62-85

        public:

            // wrapped into [0, L). A non-finite s gives NaN entries (the controller's allFinite checks catch them).
            void eval(double s, Vec7& q, Vec7* dq = nullptr) const;

            double length() const { return L_; }
            int gridIntervals() const { return n_; }
            const Vec7& restPosture() const { return qr_; }
            // q*(s_k) for k = 0, ..., n; node n is node 0 (the spline's convention)
            const std::vector<Vec7>& nodes() const { return nodes_; }
            const LiftDiagnostics& diagnostics() const { return diag_; }

        private:
            double L_;
            int n_;
            Vec7 qr_;
            std::vector<Vec7> nodes_;

```

- `explicit` forbids implicit conversion. Without it, a function taking `const Lift&` would accept a `ConingCircle` and silently build a 2001-node lift from it.
- The default arguments `= PandaArm::restPosture()` and `= 2000` are evaluated at each call site, so `Lift(path)` is the paper's lift.
- Every accessor is a `const` member function: callable through a `const Lift&`, and guaranteed not to change the object.
- `nodes()` returns `const std::vector<Vec7>&`: a read-only view of the stored nodes, with no copy.
- The members are initialized in their declaration order, `L_`, `n_`, `qr_`, `nodes_`, `q_`, `diag_`, whatever order the constructor's list uses.

### The pose error e

```cpp
// src/lift.cpp:24-36
        // Pose error e = Log_I(g^-1 target)^vee of the product metric: (log R, p) of the relative pose, in the flange
        // frame. If FK(q + dq) = FK(q) exp((J_b dq)^), then e falls by J_b dq to first order near e = 0, so Newton's
        // methods solve J_b dq = e. Any chart of SE(3) with that property (the SE(3) log, too) has the same root
        // FK(q) = target, and so gives the same lift; only the iterates differ. Written out here instead of calling
        // Metric::Log, because the lift needs no metric: the root does not depend on the chart, and this closed
        // form is the same for every product-type W.
        Vec6 poseError(const Pose& g, const Pose& target)
        {
            const Pose rel = inverse(g) * target;
            Vec6 e;
            e << logSO3(Matrix3d(rel.block<3,3>(0,0))), rel.block<3,1>(0,3);
            return e;
        }
```

e = (log R_rel, p_rel), where (R_rel, p_rel) = g⁻¹ · target is the target seen from the current flange frame. This is the Log_I of the product-type metric, which is (log R, p) for every w_R, w_p. It is not the SE(3) logarithm, which would mix p through the inverse left Jacobian of SO(3).

Why any such chart works: Newton's methods only need e to fall by J_b Δq to first order. Every chart with that property has the same root FK(q) = target, so the lift does not depend on the chart or on W; only the iterates differ.

C++ points: `rel.block<3,3>(0,0)` is a fixed-size view into the 4 × 4 matrix (no copy); `Matrix3d(...)` turns it into a real matrix for `logSO3`, which takes `const Matrix3d&`. `e << a, b;` stacks two 3-vectors with the comma initializer.

### The projected Newton step

Each node of the lift is solved by

```latex
\Delta q = J^{+}e + \bigl(I - J^{+}J\bigr)(q_\mathrm r - q),\qquad J = J_b(q),\quad J^{+} = J^\top(JJ^\top)^{-1}
```

The first term is the minimum-norm Newton step for the pose: J Δq = e. The second moves q towards q_r inside ker J, which changes the pose only to second order, because J(I − J⁺J) = 0.

```cpp
// src/lift.cpp:45-59
        // One node of the lift: projected Newton steps from q until the stopping rule holds (Offline: the lift q*).
        // Returns the number of updates, or -1 on failure (q is then unspecified).
        int projectedNewton(const Pose& target, const Vec7& qr, Vec7& q)
        {
            for (int k = 0; k <= kMaxLiftUpdates; ++k) {
                Mat67 J = Mat67::Zero();
                const Pose g = PandaArm::output(q, &J);
                const Vec6 e = poseError(g, target);

                // J^+ y = J^T (J J^T)^-1 y; J J^T is symmetric positive definite while J has full rank.
                const LLT<Mat6> JJt(J * J.transpose());
                if (JJt.info() != Success)
                    return -1;
                const Vec7 d = qr - q;
                const Vec7 nullStep = d - J.transpose() * JJt.solve(Vec6(J * d));  // (I - J^+ J)(q_r - q)
```

The second half applies the step:

```cpp
// src/lift.cpp:61-72
                // nullStep = 0 is the Lagrange condition: q - q_r is in the range of J^T.
                if (e.norm() < kTol && nullStep.norm() < kTol)
                    return k;
                if (k == kMaxLiftUpdates)
                    break;
                const Vec7 dq = J.transpose() * JJt.solve(e) + nullStep;
                if (!dq.allFinite())
                    return -1;
                q += dq;
            }
            return -1;
        }
```

How the code realizes the formula:

- `LLT<Mat6> JJt(J * J.transpose())` is a Cholesky factorization of the 6 × 6 matrix JJᵀ, which is symmetric positive definite while J has rank 6. Cholesky is the cheapest stable factorization for such a matrix. `JJt.info() != Success` reports a failed factorization, which means rank loss: the function returns −1.
- J⁺ is never formed. `J.transpose() * JJt.solve(e)` is J⁺e, and `d - J.transpose() * JJt.solve(Vec6(J * d))` is (I − J⁺J)d with d = q_r − q. `Vec6(J * d)` evaluates the product expression into a concrete vector before the solve.
- JJᵀ squares the condition number of J. That is harmless here: σ_min(J_b) ≥ 0.207 along the lift.
- `nullStep` is computed before the stopping test, because the test needs it, and its norm equals ‖(I − J⁺J)(q − q_r)‖.
- The loop runs k = 0, ..., 100 inclusive. At k = 100 it tests convergence a last time and then stops without updating. It returns the number of updates, or −1 if JJᵀ is not positive definite, a step is not finite, or 100 updates do not converge. The integer return carries both the success flag and the count, which `LiftDiagnostics` records.

Why the convergence is linear: the step is Newton for the pose but only a fixed-point iteration for the Lagrange condition. It ignores how the null space turns as q moves (the Dxᵀ(q − q_r) term of ∇h below), so the null-space residual shrinks by a constant factor per update instead of squaring. Measured from q_r at s = 0, after the first two updates that factor is about 0.05: 5.2e-2, 3.5e-3, 1.7e-4, 8.4e-6, 4.3e-7, 2.2e-8, ..., 1.5e-13 after update 11.

At a later node the first update mostly moves the flange; it leaves a null-space residual between 1e-7 and 3e-4, which then contracts by a factor that varies along the path, from 0.025 (node 1047) to 0.18 (node 540). At node 225, for example, the residual is 3.9e-5 after the first update and falls by 0.083 per update, so it passes 1e-12 after 8 more: 9 in all. Over nodes 1 to 2000 the counts run from 4 to 13, with median 9.

### The stopping rule and the Lagrange condition

The solver stops when ‖e‖ < 1e-12 and ‖(I − J⁺J)(q − q_r)‖ < 1e-12 (`kTol`). The first condition puts the flange on γ(s); the second is the Lagrange condition, so q is a critical point of ‖q − q_r‖² on the self-motion over γ(s). It need not be a minimum, which is why `minimumCheck` exists.

1e-12 sits about four orders above the round-off of one forward-kinematics evaluation (about 1e-16) and is reachable in a few extra linear-rate updates. It makes the closure gap measurable at the 1e-13 level.

### Continuation over 2000 nodes

```cpp
// src/lift.cpp:142-166
    Lift::Lift(const Path& path, const Vec7& restPosture, int gridIntervals)
        : L_(path.length()), n_(gridIntervals), qr_(restPosture)
    {
        if (n_ < 4)
            throw std::invalid_argument("Lift: need at least 4 grid intervals (fourth-order differences)");
        const double h = L_ / n_;

        // Continuation: node 0 from q_r (a large first step, about 0.97 rad on the paper's path), every later node
        // from the previous solution (steps of about 0.002 rad), so the lift stays on one branch.
        std::vector<Vec7> Q(n_ + 1, Vec7::Zero());
        std::vector<int> updates(n_ + 1, 0);
        Vec7 q = qr_;
        for (int k = 0; k <= n_; ++k) {
            const double s = k * h;
            updates[k] = projectedNewton(path.pose(s), qr_, q);
            if (updates[k] < 0)
                throw std::runtime_error("Lift: Newton's method failed at s = " + std::to_string(s) +
                                         " (is the path reachable?)");
            // Inside the joint limits at every node; a NaN margin fails too.
            int joint = -1;
            if (!(PandaArm::jointMargin(q, &joint) >= 0.0))
                throw std::runtime_error("Lift: joint " + std::to_string(joint) +
                                         " (zero-based) left its range at s = " + std::to_string(s));
            Q[k] = q;
        }
```

- The grid is s_k = k h, h = L/n = 0.77008765/2000 = 3.85e-4, the same 2000 intervals as the tube's normal frame (`Tube`'s default `gridIntervals`).
- Node 0 starts from q_r. FK(q_r) is 0.255 m and 0.25 rad from γ(0), so the first update is large: |Δq| = 0.966 rad (the "0.97 rad" of the design doc), and q*(0) ends 0.988 rad from q_r after 11 updates. The projected step needs no step cap here.
- Every later node starts from the previous solution: `q` carries over between iterations of the loop. Node-to-node steps average 0.00167 rad and peak at 0.00203 rad, which is max ‖q*′‖ · h = 5.28 × 3.85e-4.
- Why continuation: the self-motion manifold over each γ(s) is a closed curve, and ‖q − q_r‖² has several critical points on it. Starting from the previous solution keeps the iteration on one smoothly varying branch. Restarting every node from q_r would be slower (12 updates typical, 17 at most, measured) and could jump branches.
- Node n (s = L) is solved too, so the branch can be tested for closure.
- Inside the loop, the joint check `!(PandaArm::jointMargin(q, &joint) >= 0.0)` rejects a node outside the joint range, or with a NaN margin. It checks the range itself (margin ≥ 0), not the hardware margin of 0.10 rad.

C++ points: `std::vector<Vec7> Q(n_ + 1, Vec7::Zero());` allocates 2001 vectors on the heap, which is fine offline. In `"Lift: ... s = " + std::to_string(s)`, a string literal (a `const char*`) plus a `std::string` calls the standard `operator+` for strings, so the whole message is one `std::string` naming the failing s.

### q*′ by fourth-order central differences

The spline needs q*′ at the nodes. The code takes the fourth-order periodic stencil

```latex
q^{\star\prime}_k \approx \frac{q_{k-2} - 8\,q_{k-1} + 8\,q_{k+1} - q_{k+2}}{12\,h},\qquad \text{approximation} - \text{exact} = -\tfrac{h^4}{30}\,q^{\star(5)} + O(h^6)
```

```cpp
// include/se3pf/spline.hpp:61-73
            static std::vector<T> centralDifferences(const std::vector<T> &y, double L)
            {
                const int n = static_cast<int>(y.size()) - 1;
                if (n < 4)
                    throw std::invalid_argument("PeriodicHermite::centralDifferences: need at least 5 samples");
                const double h = L / n;
                auto at = [&](int k) -> const T & { return y[((k % n) + n) % n]; };
                std::vector<T> d(y.size());
                for (int k = 0; k < n; ++k)
                    d[k] = (1.0 / (12.0 * h)) * (at(k - 2) - 8.0 * at(k - 1) + 8.0 * at(k + 1) - at(k + 2));
                d[n] = d[0];
                return d;
            }
```

- The index `((k % n) + n) % n` wraps around the circle. In C++ the `%` of a negative number is negative (it truncates towards zero), so `(-1) % n` is −1; adding n makes it n − 1, and the outer `% n` maps k + 1 = n and k + 2 = n + 1 back to 0 and 1.
- `auto at = [&](int k) -> const T & { ... };` is a lambda that captures `y`, `n` by reference and returns a reference to a node, so no node is copied.
- Accuracy against the exact derivative from the implicit function theorem (below): 1.6e-9 at worst over all 2000 nodes (node 853); the test samples 44 nodes and sees 1.4e-9. The second-order stencil (q_(k+1) − q_(k−1))/2h is off by up to 1.9e-5. An error near 1e-5 in that test therefore means a wrong stencil.

The exact derivative differentiates FK(q*(s)) = γ(s) and h(q*(s)) = 0:

```latex
\begin{bmatrix} J_b(q^\star) \\ \nabla h(q^\star)^\top \end{bmatrix} q^{\star\prime} = \begin{bmatrix} \zeta_\gamma(s) \\ 0 \end{bmatrix},\qquad \nabla h = Dx(q)^\top (q - q_\mathrm r) + x(q)
```

The code does not use it, because it needs Dx, the 7 × 7 Jacobian of the kernel vector: 14 more kernel vectors (98 determinants) per node, and more code to get wrong. The fourth-order differences are accurate to 1e-9, which is enough: q*′ enters dβ, and through it A.

### minimumCheck: is q* a minimum?

The stopping rule finds a critical point of f(q) = ‖q − q_r‖² on the self-motion, which could be a maximum. At every node, `minimumCheck` moves along the self-motion in both directions, by δ in the coordinate xᵀq, and takes a second difference.

```cpp
// src/lift.cpp:74-85
        // f(q+) - 2 f(q*) + f(q-) for f(q) = |q - q_r|^2, with q+- the configurations with pose FK(q*) on the
        // self-motion through q*, at x^T q = x^T q* +- delta (minimumCheck). NaN if q+ or q- is not found.
        double secondDifference(const Vec7& qs, const Vec7& qr, double delta)
        {
            Mat67 J = Mat67::Zero();
            const Pose target = PandaArm::output(qs, &J);  // = gamma(s_k) to 1e-12: the same self-motion
            const Vec7 x = kernelVector(J);
            Vec7 qp = qs, qm = qs;
            if (!constrainedIK(target, x, x.dot(qs) + delta, qp) || !constrainedIK(target, x, x.dot(qs) - delta, qm))
                return std::numeric_limits<double>::quiet_NaN();
            return (qp - qr).squaredNorm() - 2.0 * (qs - qr).squaredNorm() + (qm - qr).squaredNorm();
        }
```

- q₊ and q₋ have the same pose FK(q*(s_k)) and lie on the hyperplanes xᵀq = xᵀq*(s_k) ± δ, x = x(q*(s_k)). `constrainedIK` (below) finds them, starting from q*(s_k).
- The target is FK(q*(s_k)) rather than γ(s_k): the two agree to 1e-12, and the function then needs no path.
- Why not simply q* ± δx: f is quadratic, so its second difference along any straight line is 2δ² = 5e-3, whatever q* is. The projected points follow the curved self-motion, and that curvature is what decides minimum against maximum. The paper's lift gives a smallest value of 4.1028e-3 at s = 0.206383: positive everywhere (a minimum), and visibly different from 5e-3.

```cpp
// src/lift.cpp:216-238
    double minimumCheck(const Lift& lift, double delta, double* where)
    {
        const std::vector<Vec7>& Q = lift.nodes();
        const int n = lift.gridIntervals();
        const double h = lift.length() / n;
        double smallest = std::numeric_limits<double>::infinity();
        double at = 0.0;
        for (int k = 0; k < n; ++k) {
            const double d2 = secondDifference(Q[k], lift.restPosture(), delta);
            if (std::isnan(d2)) {  // no later node can make the check pass
                smallest = d2;
                at = k * h;
                break;
            }
            if (d2 < smallest) {
                smallest = d2;
                at = k * h;
            }
        }
        if (where != nullptr)
            *where = at;
        return smallest;
    }
```

- It returns the smallest second difference over the nodes, and its s through the optional `where`.
- If `constrainedIK` fails at some node, `secondDifference` returns NaN and the loop stops there: no later node can make the check pass, and NaN fails every comparison such as `d2 > 0`. With δ = 100 rad that happens at the first node, because 50 updates of at most 0.2 rad cannot move xᵀq by 100.
- Cost: 2n = 4000 constrained solves, about 13 ms in Release on a loaded machine (the header says about 10 ms; about 2 s in Debug). That is why it is a free function and not part of the constructor: the controller does not need it. The tests call it twice, with δ = 0.05 for the check and δ = 100 for the fail-closed case, which stops at the first node.

### constrainedIK: Newton on the square system [J_b; pᵀ]

`constrainedIK` solves FK(q) = target together with one linear condition pᵀq = b. Six equations fix the pose; the seventh picks one point of the one-dimensional self-motion manifold. The system is square, so this is ordinary Newton with quadratic convergence:

```latex
\begin{bmatrix} J_b(q) \\ p^\top \end{bmatrix}\Delta q = \begin{bmatrix} e \\ b - p^\top q \end{bmatrix},\qquad \Delta q \leftarrow \Delta q\,\min\Bigl(1, \frac{0.2}{\|\Delta q\|}\Bigr)
```

```cpp
// src/lift.cpp:103-120
    bool constrainedIK(const Pose& target, const Vec7& p, double b, Vec7& q, int* iterations)
    {
        Vec7 qk = q;  // the iterate; q is written only on success
        for (int k = 0; k <= kMaxSquareUpdates; ++k) {
            Mat67 J = Mat67::Zero();
            const Pose g = PandaArm::output(qk, &J);
            const Vec6 e = poseError(g, target);
            const double c = b - p.dot(qk);
            if (!e.allFinite() || !std::isfinite(c))
                return false;
            if (e.norm() < kTol && std::abs(c) < kTol) {
                q = qk;
                if (iterations != nullptr)
                    *iterations = k;
                return true;
            }
            if (k == kMaxSquareUpdates)
                break;
```

The update, with the step cap:

```cpp
// src/lift.cpp:122-137
            // [J_b; p^T] dq = (e, b - p^T q): six rows move the flange onto the target, the seventh moves q onto
            // the hyperplane, which picks one point of the self-motion manifold.
            Mat7 A;
            A << J, p.transpose();
            Vec7 rhs;
            rhs << e, c;
            Vec7 dq = A.partialPivLu().solve(rhs);  // a singular A gives inf or NaN, caught below
            const double size = dq.norm();
            if (!std::isfinite(size))
                return false;
            if (size > kMaxStep)
                dq *= kMaxStep / size;
            qk += dq;
        }
        return false;
    }
```

- `Vec7 qk = q;` works on a copy. `q` is written only on success, so a caller's guess survives a failure untouched. The same "commit or leave unchanged" pattern is used by `startConfiguration`; `projectedNewton` does without it, because the lift constructor throws when it fails.
- `int* iterations = nullptr` is optional; on success it receives the number of updates (0 if `q` already solved the system).
- `A << J, p.transpose();` stacks the 6 × 7 Jacobian and the 1 × 7 row with the comma initializer.
- `partialPivLu()` is LU with partial pivoting, Eigen's standard solver for a general square matrix. It does not detect singularity: a singular system gives inf or NaN, caught by `!std::isfinite(size)`, or huge finite values, which the cap shrinks and which then fail to converge.
- The cap of 0.2 rad (`kMaxStep`) keeps a far start from overshooting: Newton converges only locally, and a full step from 1 rad away can overshoot into another region of the self-motion. Near the solution the cap is inactive and convergence is quadratic.
- It returns `false` if e or the constraint residual is not finite, a step is not finite, or 50 updates do not converge.

Measured: 5 updates for the paper's start from q*(0.1), 4 for the self-motion start, 6 from q_r onto γ(0.3) with the coupling q_3 = q_1. Users: `startConfiguration` (every run's start), `minimumCheck` (q₊ and q₋) and the tests.
