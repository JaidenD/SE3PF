## The Panda example

`PandaExample` builds the paper's whole Panda setup once and owns every part, and `simulate` runs the closed loop at the joint-acceleration level and summarizes it. The runs reproduce the paper's numbers: max ||ξ| − design| 2.434e-5 [paper 2.4e-5], with a control step of about 12 µs [paper 27 µs].

### The members, in construction order

```cpp

            Metric metric_;
            Matrix3d R0_;
            ConingCircle path_;
            Tube tube_;
            Lift lift_;

            LiftRedundancy beta_;
            CouplingRedundancy coupling_;
            Vec7 paperStart_;
            Vec7 selfMotionStart_;
```

```cpp
// src/panda_example.cpp:31-44
    // Members are initialized in the order of their declaration, which is the order of the list below.
    PandaExample::PandaExample(double l)
        : metric_(exampleMetric(l)),
          R0_(restAttitude()),
          path_(R0_, center(), radius, cone, metric_),
          tube_(path_, metric_),
          lift_(path_, PandaArm::restPosture()),
          kernel_(lift_),
          beta_(lift_, kernel_),
          coupling_(),
          paperStart_(start(beta_, xi0(), 0.0)),
          selfMotionStart_(start(beta_, Vec5::Zero(), selfMotionBeta0))
    {
    }
```

| Member | Type | Built from | Paper object |
| --- | --- | --- | --- |
| `metric_` | `Metric` | `exampleMetric(l)` = `Metric::product(l * l, 1.0)` | W = diag(ℓ² I, I), ℓ = 0.1 m |
| `R0_` | `Matrix3d` | `restAttitude()` = rotation of FK(q_r) | R₀ of the coning circle |
| `path_` | `ConingCircle` | R₀, center, radius, cone, W | γ, by arc length in W |
| `tube_` | `Tube` | `path_`, `metric_` (keeps a reference to `path_`) | N, Ψ, Ψ⁻¹, J_Ψ |
| `lift_` | `Lift` | `path_`, q_r, 2000 intervals | q* (Assumption 1) |
| `kernel_` | `KernelFrame` | `lift_` | X (Lemma 3) |
| `beta_` | `LiftRedundancy` | references to `lift_`, `kernel_` | β = Xᵀ(q − q*) |
| `coupling_` | `CouplingRedundancy` | nothing | β = q₃ − q₁ (comparison) |
| `paperStart_` | `Vec7` | `start(beta_, xi0(), 0.0)` | q₀ with Π(q₀) = Ψ(0.1, ξ₀), β = 0 |
| `selfMotionStart_` | `Vec7` | `start(beta_, Vec5::Zero(), 0.2)` | q₀ with Π(q₀) = γ(0.1), β = 0.2 |

The C++ rule behind this order: members are always initialized in the order they are declared in the class, whatever order the constructor's list uses. GCC warns when the two orders differ (`-Wreorder`, part of the project's `-Wall`, and an error under the CI's `-Werror`). The order matters because `tube_` refers to `path_`, `kernel_` reads `lift_`, and the start configurations call the member function `start`, which reads `lift_` and `tube_`.

Calling a member function from the initializer list is legal as long as it touches only members already built. If `paperStart_` were declared above `lift_`, `start` would read an unconstructed lift: undefined behaviour. `-Wreorder` would flag the list that no longer matches, but if the list were reordered as well, nothing would.

### The two helpers: W and R₀

```cpp
// src/panda_example.cpp:14-29
    namespace {
        // W = diag(l^2 I, I), checked first: every later member depends on it.
        Metric exampleMetric(double l)
        {
            if (!(l > 0.0))
                throw std::invalid_argument("PandaExample: need l > 0");
            return Metric::product(l * l, 1.0);
        }

        // R0 = the flange attitude at the rest posture (approach axis pointing down)
        Matrix3d restAttitude()
        {
            const Pose g = PandaArm::output(PandaArm::restPosture(), nullptr);
            return g.block<3,3>(0,0);
        }
    }  // namespace
```

- `exampleMetric` checks ℓ first, because every later member depends on W. `!(l > 0.0)` also rejects NaN, for which `l <= 0.0` would be false. It throws `std::invalid_argument`.
- `restAttitude` takes the rotation block of FK(q_r): rows (c, −c, 0), (−c, −c, 0), (0, 0, −1) with c = √½, the flange's z-axis pointing down. R₀ = FK(q_r) centres the path's attitudes on one the arm reaches comfortably, and computing it from the arm, not typing it, keeps it exact.
- `Metric::product(l * l, 1.0)` gives w_R = 0.01, w_p = 1: one radian counts as 0.1 m in every length, so s, L, ξ and ν_d mix metres and tenths of radians.

### The path and run parameters

### Gains, reference, designed response, duration

```cpp
// src/panda_example.cpp:56-78
    Gains PandaExample::gains()
    {
        Gains g = Gains::fromLambda(lambda);  // K_p = 16, K_d = 8 (and K_p,beta, K_d,beta, set again below)
        g.kt = kt;
        g.KpBeta = KpBeta;
        g.KdBeta = KdBeta;
        return g;
    }

    TangentialReference PandaExample::reference()
    {
        return TangentialReference::constantVelocity(nuD);
    }

    double PandaExample::designedResponse(double y0, double t)
    {
        return y0 * (1.0 + lambda * t) * std::exp(-lambda * t);
    }

    double PandaExample::duration(RunKind which) const
    {
        return which == RunKind::Paper ? T : tube_.length() / nuD;
    }
```

- `gains()`: `Gains::fromLambda(4)` puts the transverse and redundancy poles at −4 (K_p = K_p,β = λ² = 16, K_d = K_d,β = 2λ = 8), then sets k_t = 5. The two β gains are set again explicitly, so the example's values do not depend on `fromLambda`'s internals.
- `reference()`: `TangentialReference::constantVelocity(0.08)` wraps a lambda that captures ν_d by value in a `std::function`. Building it may allocate, so it happens before the loop; calling it does not.
- `designedResponse(y0, t)`: the solution of the critically damped ÿ = −λ²y − 2λẏ with y(0) = y₀ and ẏ(0) = 0,

```latex
y(t) = y_0\,(1 + \lambda t)\,e^{-\lambda t},\qquad \lambda = 4
```

Each ξ_i obeys the same scalar equation (eq:transverse) with zero initial rate, so ξ(t) = ξ₀ f(t) with f ≥ 0, and |ξ(t)| = |ξ₀|(1 + 4t)e^(−4t). The same holds for β (eq:beta-law). At t = 0.5 s the response is 3e^(−2) y₀; at t = 1 s it is 5e^(−4) y₀ = 0.092 y₀.

- `duration(which)`: 20 s for the paper run, L/ν_d = 9.626096 s (one loop) for the self-motion run.

### Why PandaExample cannot be copied, and the ref-qualified accessors

```cpp
// include/se3pf/panda_example.hpp:60-76
            // The parts. Not on a temporary example (deleted &&-overloads): a controller or a redundancy output
            // keeps a reference to them, which would dangle at the end of the full expression.
            const Metric& metric() const& { return metric_; }
            const Matrix3d& R0() const { return R0_; }
            const ConingCircle& path() const& { return path_; }
            const Tube& tube() const& { return tube_; }
            const Lift& lift() const& { return lift_; }
            const KernelFrame& kernelFrame() const& { return kernel_; }
            const LiftRedundancy& redundancy() const& { return beta_; }      // beta = X^T (q - q*), the paper's
            const CouplingRedundancy& coupling() const& { return coupling_; }  // beta = q_3 - q_1
            const Metric& metric() const&& = delete;
            const ConingCircle& path() const&& = delete;
            const Tube& tube() const&& = delete;
            const Lift& lift() const&& = delete;
            const KernelFrame& kernelFrame() const&& = delete;
            const LiftRedundancy& redundancy() const&& = delete;
            const CouplingRedundancy& coupling() const&& = delete;
```

The copy constructor and copy assignment are `= delete` (`include/se3pf/panda_example.hpp:34-35`). A copy would copy `tube_`'s reference member as a reference to the original's `path_`, and `beta_`'s references to the original's lift and kernel frame. Once the original died, the copy would read freed memory. Declaring the copy constructor (even as deleted) also suppresses the implicit move constructor, so the class is not movable either. Build it once and pass it by `const&`.

Each accessor that hands out a part someone keeps a reference to has two overloads:

- `const Tube& tube() const&` applies when the object is an lvalue, a named example that lives on.
- `const Tube& tube() const&& = delete` applies when the object is an rvalue, a temporary. `Controller<PandaArm> c(PandaExample().tube(), ...)` then fails to compile instead of leaving `c` with a reference to a tube that died at the semicolon.

The `&` and `&&` after the parameter list are ref-qualifiers: they select on the value category of the object, the way `const` selects on its constness. C++ requires that if one overload of a name has a ref-qualifier, all overloads with the same parameters do, which is why the live version is spelled `const&` instead of plain `const`.

The limit of this protection: `R0()`, `paperStart()` and `selfMotionStart()` are not ref-qualified, because nothing in the library stores them. `Vec7 q = PandaExample().paperStart();` copies the value and is safe; `const Vec7& q = PandaExample().paperStart();` would dangle, because lifetime extension applies only when a reference binds to the temporary itself, not to a reference returned by a function.

### simulate: the closed loop

`simulate` is a free function, declared at `include/se3pf/panda_example.hpp:194`:

```cpp
// include/se3pf/panda_example.hpp:194-195
    PandaRun simulate(const PandaExample& example, PandaExample::RunKind which, std::optional<double> T = std::nullopt,
                      double dt = PandaExample::dt);
```

`std::optional<double>` holds either a double or nothing. `std::nullopt` means "use the run's own duration"; `simulate(ex, RunKind::Paper, 1.0)` converts 1.0 into an engaged optional.

```cpp
// src/panda_example.cpp:80-99
    PandaRun simulate(const PandaExample& example, PandaExample::RunKind which, std::optional<double> T, double dt)
    {
        const double duration = T ? *T : example.duration(which);
        // Checks T and dt (finite, T >= 0, dt > 0, T / dt <= maxSteps) before anything is built or allocated.
        const long steps = stepCount(duration, dt, PandaExample::maxSteps);  // the instants k dt <= T

        PandaRun run;
        run.kind = which;
        run.T = duration;
        run.dt = dt;

        Controller<PandaArm> controller(example.tube(), PandaExample::gains(), PandaExample::reference(),
                                        &example.redundancy());

        // The start and the designed responses: |xi| from |xi0| and beta from beta0, both with zero initial rate.
        const bool paper = which == PandaExample::RunKind::Paper;
        Vec7 q = paper ? example.paperStart() : example.selfMotionStart();
        Vec7 qd = Vec7::Zero();
        const double xi0 = paper ? PandaExample::xi0().norm() : 0.0;
        const double beta0 = paper ? 0.0 : PandaExample::selfMotionBeta0;
```

1. `T ? *T : example.duration(which)`: an optional converts to `true` when it holds a value, and `*T` reads it.
2. `stepCount(duration, dt, maxSteps)` (`include/se3pf/controller.hpp:112`) checks T and dt and returns floor(T/Δt + 1e-9). The 1e-9 absorbs rounding: a quotient such as 0.3 / 0.1 evaluates to 2.9999999999999996, and plain `floor` would drop the last instant. With T = 20 s and Δt = 1 ms the run has the 20001 instants t = 0, ..., 20 s. It throws `std::invalid_argument` for a NaN, infinite or negative T, a non-positive or NaN dt, or T/Δt above `maxSteps`, before anything is allocated.
3. The controller is built from the example's tube, gains, reference and `&example.redundancy()`, the address of β.
4. The designed responses start from |ξ₀| = 0.03122 and β₀ = 0 (paper) or from 0 and β₀ = 0.2 (self-motion).

```cpp

        controller.reset(PandaExample::s0);

        const Pose gamma0 = example.path().pose(PandaExample::s0);
        const Pose g0 = PandaArm::output(q, nullptr);
```

5. The self-motion run starts moving. It solves A(q₀) q̇₀ = (ν_d, 0, ..., 0), so η̇(0) = ν_d (zero speed error), ξ̇(0) = 0 and β̇(0) = 0. The designed response β₀(1 + 4t)e^(−4t) assumes exactly that zero initial rate. Measured: q̇₀ = (−0.00616, −0.14956, 0.13366, −0.12768, −0.17056, −0.04644, 0.22862) rad/s, ‖q̇₀‖ = 0.374. `Vec7(PandaExample::nuD * Vec7::Unit(0))` builds ν_d e₁; `Vec7::Unit(0)` is the first unit vector.
6. `controller.reset(PandaExample::s0)` sets the prediction η̂ = 0.1. A pose Ψ(s₀, ξ) has η = s₀ (Proposition 1), so the first projection starts at its answer.
7. The start error is reported in plain units: the rotation angle |log(R_γᵀR_g)| in degrees and the distance between positions in metres.

The loop:

8. `dqMax` and `ddqMax` are computed once, outside the loop.
9. `run.log.reserve(steps + 1)` allocates every row before the loop. `push_back` within the reserved capacity never reallocates, so the loop allocates nothing. The test checks `capacity() == size()` afterwards: a vector grown row by row would end at a power of two (32768 for 20001 rows).
10. A failed step sets `ok = false`, records the time and leaves the loop; the log keeps the rows before it.
11. `row.q`, `row.qd` are the state at t_k, before the update; `row.qdd` is the command held over [t_k, t_k + Δt).

13. `(qd.cwiseAbs().array() / dqMax.array()).maxCoeff(&joint)`: `.array()` switches Eigen to coefficient-wise arithmetic (in matrix arithmetic a vector cannot be divided by a vector), and `maxCoeff(&joint)` returns the largest ratio with its joint.

```cpp
// src/panda_example.cpp:196-199
            // The arm moves with qdd* held over [t, t + dt): exact for a constant acceleration.
            q += dt * qd + (0.5 * dt * dt) * qdd;
            qd += dt * qdd;
        }
```

14. The held-acceleration update is exact for an acceleration that is constant over the period:

```latex
q_{k+1} = q_k + \Delta t\,\dot q_k + \tfrac12\Delta t^2\,\ddot q^{\star}_k,\qquad \dot q_{k+1} = \dot q_k + \Delta t\,\ddot q^{\star}_k
```

So the only error is the sample-and-hold of q̈* (O(Δt)), not an integration error. `q` is updated first, because it needs the old `qd`.


15. After the loop: the start and final values come from the first and last rows, and the final distance from the lift is q − q*(η) at the last row. `front()` and `back()` of an empty vector are undefined behaviour, hence the guard, although the first step at both starts never fails.
16. `return run;` returns by value. The compiler constructs `run` directly in the caller's object or moves it, so the 20001-row log is never copied.

| `beta`, `betaDesign` | β, β₀(1 + 4t)e^(−4t) |
| `q`, `qd`, `qdd` | q, q̇ at t_k, and q̈* held over the period |
| `sigmaMin` | σ_min(A(q)) |
| `jointMargin` | distance to the nearest joint limit |
| `iterations` | Newton updates of the projection at q |

A row is 304 bytes (37 doubles and an int, padded), so `maxSteps` = 1e7 rows is a 3.04 GB log; the bound turns a mistyped T or dt into an error instead of an allocation failure.

`PandaRun` (`include/se3pf/panda_example.hpp:137`) holds the log and the summary: start errors, max |ξ| and ||ξ| − design|, max |β| and |β − design|, final |ξ|, η̇ and β, smallest joint margin and σ_min(A), largest velocity and acceleration fractions with their joints and times, most Newton updates, the final lift gap, `ok` and `failureTime`. `ok` covers the controller only: the model q̈ = q̈* has no joint limits, so a run can leave the joint range and still be `ok`, and only `minJointMargin < 0` says so.

How to read them:

- The smallest joint margin, 0.3592 rad at joint 4, matches the lift's own margin (0.359175) to 2e-6: it is set by the path, not by the transient.
- In the paper run σ_min(A) is smallest at the start, where the pose is furthest from the path (in the self-motion run it is 0.0541, at t = 9.266 s).
- The first command asks 49 % of joint 5's acceleration limit, because the paper's loop has no ramp on μ. With the quintic ramp on μ over 1 s planned for hardware (`Controller::setRampTime`), the peak drops to 11.5 % (design doc, Hardware; confirmed by the baseline of MuJoCo run C in `docs/MUJOCO.md`).
- max |β| is not zero although β starts at 0 with a designed response of 0. β is nonlinear in q, so holding q̈* over 1 ms excites it at O(Δt), like ξ. Halving Δt halves both: 2.4339e-5 → 1.2165e-5 (ratio 2.0007) and 1.5244e-5 → 7.6229e-6 (ratio 1.9998). If halving Δt did not halve a deviation, the cause would be a bug, not the sampling.
- After one loop of the self-motion run, β has decayed from 0.2 rad to −2.6e-6 and the arm is back on the lift to 1.3e-5, while |ξ| never exceeded 1.24e-6: the redundancy channel moved the joints without moving the flange off the path.

`panda_sim [dir]` builds the example, runs both loops, prints each number next to its expected value and writes `panda_paper.csv`, `panda_self_motion.csv` and `panda_limits.csv` (default directory `out/`). The whole program takes about 0.9 s in Release, CSV writing included.

- `std::filesystem::create_directories(dir)` creates the output directory and any missing parents.
- The `try { ... } catch (const std::exception& e)` around `main`'s body turns every construction error (an unreachable path, a failed start) into a message and exit status 1. A log that cannot be written also exits with status 1 (`apps/panda_sim.cpp:144`).
- Exit status 2 means a run failed or left the joint range: `valid(run)` is `run.ok && run.minJointMargin >= 0.0` (`apps/panda_sim.cpp:53`). The CI script (`tools/ci.sh`) runs `panda_sim` and fails on any nonzero status.
