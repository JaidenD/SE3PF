## The tests

`tests/test_tube.cpp` has 26 test cases, grouped by the tickets TUBE-1 to TUBE-4. Each checks one claim of Lemma 1, Proposition 1 or the radius test, with a tolerance well above the measured error. For every test case, this section says what it proves, how tight it is, and which wrong implementation it catches.

Most entries of the "Mutation it catches" columns were checked by running the tests against a scratch copy of `src/tube.cpp` (or `include/se3pf/spline.hpp`, `src/path.cpp`) with the one-line change applied; the rest follow directly from what the test compares. Measured values come from replaying each test's random inputs (same generator, same seed).

### Running them

```bash
cd /home/jaiden/Desktop/SE3_pathFollowing
./build-ci-release/tests "Tube*,rotationPlanes*,estimateTubeRadius*"   # all 26 test cases of test_tube.cpp
./build-ci-release/tests "Tube*"                       # the 22 Tube test cases (a wildcard also matches the hidden timing test)
./build-ci-release/tests "rotationPlanes*"             # the two SO(5) logarithm tests
./build-ci-release/tests "estimateTubeRadius*"         # the two radius tests (the paper one is [slow], run by default in Release)
./build-ci-release/tests "estimateTubeRadius: the paper*" -s   # -s also prints passing checks with their values
./build-ci-release/tests "Tube: time of one outputs() + JPsi() call (Panda)"   # the hidden timing test, by name
```

All 26 pass in about 2 s in Release (1758 assertions; 1.9 to 2.0 s measured). A `CAPTURE(sci(err))` line prints its values only when a check fails, or with `-s`.

### Fixture and helpers

The three tubes come from `tests/tube_fixture.hpp`, built once per program as function-local statics (see the previous section):

| Function | Path | Metric | L |
| --- | --- | --- | --- |
| `pandaTube()` | coning circle, p₀ = (0.40, 0, 0.45), r = 0.12, α = 0.25, R₀ = rest attitude | W = diag(0.01 I, I), ℓ = 0.1 m | 0.7700876 |
| `pandaTube1()` | the same path | W = I, ℓ = 1 m | 1.7386966 |
| `rigidTube()` | tumbling circle, r = 1 m | W = I | 10.8827962 |

The fixture builds the paths itself, not through `PandaExample` or `RigidBodyExample`, so the tube tests do not depend on the lift or the rigid body. Helpers from `tests/test_helpers.hpp`:

- `maxDiff(a, b)`: the largest absolute entry of a − b, an absolute tolerance that also works against zero (`tests/test_helpers.hpp:35-39`).
- `randn<M>()`, `uniform(a, b)`: random numbers from one generator reseeded with 12345 before every test case (`tests/rng_listener.cpp`), so a failure reproduces when the test runs alone or in random order.
- `sci(x)`: prints a double in scientific notation, since Catch2 would print 3e-12 as 0.0.
- `arcDiff(a, b, L)`: a − b wrapped into (−L/2, L/2]. It accepts η = s + L as equal to s, so tests that use it also check η ∈ [0, L).
- `poseError(a, b, deg, m)`: the rotation angle (degrees) and distance (metres) between two poses.

The top of `test_tube.cpp` adds local helpers:

- `pandaXi0()` and `rigidXi0()`: the start offsets of the two examples.
- `randomXi(r)`: a random ξ with ‖ξ‖ = r.
- `sampledDistance(T, samples, g)`: the brute-force distance from g to a list of path samples.
- `planeRotation(i, j, th)`: a rotation by th in the (i, j) coordinate plane of R⁵.

### Rotations in SO(5): the logarithm of the holonomy

| Test (line) | What it proves | Tolerance (measured) | Mutation it catches |
| --- | --- | --- | --- |
| "rotationPlanes: logarithm and exponential of a rotation in SO(5)" (66) | For H = Q R₀₁(2.5) Qᵀ with random orthogonal Q: one plane, θ = 2.5; Φ skew; exp(Φ) = H; exp is a one-parameter group with exp(−t) = exp(t)ᵀ. With a second plane of angle 1e-5: two planes, both angles right, exp(Φ) = H. An angle of 1e-7 counts as fixed; the identity has no planes; det = −1 throws. | θ 1e-12 (0); skew 1e-15 (0); exp 1e-13 (6.7e-16); group 1e-14 (2.2e-16); inverse 1e-15 (0); second angle 1e-14 (5.5e-17); two-plane exp 1e-9 (1.0e-11) | a fixed-direction threshold of 1e-8 (drops the 1e-5 plane: count 1 instead of 2); a threshold of 0 (a fixed direction enters the π branch and `rotationPlanes` throws "no partner for a rotation by pi"); a missing determinant check (a `runtime_error` instead of `invalid_argument`). It does not catch a sign flip inside `log()`: here `log()` only feeds the skewness check, and `exp()` never calls it |
| "rotationPlanes: a rotation by pi has a logarithm too" (112) | For one plane at π, two planes at π, and π plus 0.7: the right number of planes; exp(Φ) = H; exp(Φ/2) is a rotation whose square is H. A matrix with a lone −1 eigenvalue (det 0.5) throws `std::runtime_error`. | θ₀ = π to 1e-9; exp, orthogonality, square 1e-12 (all at most 7.8e-16) | a partner v that is not a unit vector of the (−1)-eigenspace orthogonal to u: exp(Φ/2) is then not orthogonal or does not square to H; a threshold of 0 (throws, as above) |

The test explains its bound 1e-9 for the two-plane case. The eigenvalue cos(1e-5) is only 5e-11 from 1, so the plane's eigenvectors, and exp(log H), are accurate to about 2ε_mach/θ. Over 100 random Q the error reached 1.03e-10.

Two details of the N′ test are worth understanding. The difference at the nodes uses a step equal to the node spacing. A smaller step would only see the cubic interpolant, whose derivative is consistent with its values whatever D_k is.

The node index `k = (i * 997) % n` uses 997, a prime coprime to 2000, so the 50 nodes spread over the grid. For i = 0 it gives k = 0, where the differences reach back across the seam.

A random direction d tests all six columns at once: an error in any column changes J_Ψ d for almost every d. The FD error, about 1e-9, is the O(h²) truncation plus rounding of order ε_mach/h = 1e-10.

### TUBE-4: the tube-radius estimate

| Test (line) | What it proves | Tolerance (measured) | Mutation it catches |
| --- | --- | --- | --- |
| "estimateTubeRadius: coarse options give the reference value; bad options throw" (666) | With 8 foot points, the ten ±eᵢ only, 100 samples and 8 bisections: 0.124658 (Panda) and 2.122145 (rigid body). `checkPoints = 0` throws `std::invalid_argument`. | 1e-6 | changes to the doubling, the bisection, the probes or the samples (for example another Gram-Schmidt order, which turns the probe directions); missing option checks. It does not catch removing the prefilter (both values stay the same) |
| "estimateTubeRadius: the paper's examples (under 1 s each in Release)" (685) | With the default options: within 10 % of 1.93 (rigid body), 0.125 (Panda) and 0.307 (ℓ = 1 m); each example start lies inside; each estimate takes under 5 s in Release. Tagged `SLOW_IN_DEBUG`: hidden in Debug, run in Release. | 10 % (1.926489, 0.125041, 0.306615 in 0.5 to 0.8 s) | removing the lower-bound prefilter (the rigid body drops to 0.149, and its start no longer lies inside); a much slower implementation |

The coarse test runs everywhere and pins the algorithm to six digits; the paper test runs in Release and pins the paper's numbers. Its reference values come from `RadiusOptions` with `randomDirections = 0`, so they do not depend on the standard library's `std::normal_distribution`.

Two parts of the radius code are not pinned by any test: the extra points beside the foot and the NaN-counts-as-closer rule. Removing either leaves all three estimates unchanged (measured).
