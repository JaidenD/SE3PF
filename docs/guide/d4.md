## Kernel frame, β and start configurations

This part of `lift.cpp` builds the self-motion direction X(s), defines the seventh output β from it, and finds start configurations with a given pose and a given β. The key tool is `kernelVector`, a closed formula for the unit kernel vector of a 6 × 7 matrix whose sign is fixed by the formula itself.

### kernelVector: the generalized cross product

For a 6 × 7 matrix J_b of rank 6, define

```latex
n_j = (-1)^j \det\bigl(J_b \text{ without column } j\bigr),\quad j = 0,\dots,6,\qquad x = \frac{n}{\|n\|}
```

Expanding a 7 × 7 determinant along its first row gives, for every w ∈ R⁷,

```latex
w^\top n = \det\begin{bmatrix} w^\top \\ J_b \end{bmatrix}
```

Three facts about n, each used by the code:

1. J_b n = 0: entry i of J_b n is the determinant with row i of J_b repeated on top, which is zero. So x spans ker J_b.
2. The sign is fixed: det([xᵀ; J_b]) = xᵀn = ‖n‖ > 0. The formula chooses the orientation, not an algorithm.
3. By the Cauchy–Binet formula, ‖n‖² = Σ_j det(M_j)² = det(J_b J_bᵀ), so ‖n‖ = σ₁σ₂⋯σ₆, the product of the singular values (measured: 0.0734768344 both ways at q*(0)). Rank loss makes n = 0, and x becomes 0/0 = NaN.

```cpp
// src/lift.cpp:91-101
    Vec7 kernelVector(const Mat67& Jb)
    {
        Vec7 n = Vec7::Zero();
        for (int j = 0; j < 7; ++j) {
            Mat6 M = Mat6::Zero();  // J_b without column j
            M.leftCols(j) = Jb.leftCols(j);
            M.rightCols(6 - j) = Jb.rightCols(6 - j);
            n[j] = (j % 2 == 0 ? 1.0 : -1.0) * M.determinant();
        }
        return n / n.norm();
    }
```

- `M.leftCols(j) = Jb.leftCols(j)` copies columns 0..j−1, and `M.rightCols(6 - j) = Jb.rightCols(6 - j)` copies columns j+1..6 of J_b into columns j..5 of M. For j = 0 and j = 6 one of the blocks has zero width, which Eigen accepts.
- `M.determinant()` on a 6 × 6 matrix uses an LU factorization internally. All sizes are fixed, so nothing is allocated; the function is still called only offline (kernel frame, minimum check, tests), since the controller reads X from a spline.
- `(j % 2 == 0 ? 1.0 : -1.0)` is the sign (−1)^j.

Why smoothness and periodicity come for free: each n_j is a degree-6 polynomial in the entries of J_b, and J_b(q) is smooth in q, so x(q) is smooth wherever rank J_b = 6. Along the lift, q*(s) is periodic, so X(s) = x(q*(s)) is periodic with X(L) = X(0) exactly. There is no sign to choose and no sign to align.

Why not an SVD or QR null vector: those return a kernel vector whose sign depends on the algorithm's internals, which the library does not promise to keep. On this lift Eigen's JacobiSVD happened to give a consistent sign (0 flips in 2000 steps, measured), but nothing guarantees that for another path or another Eigen version. A flip between two nodes would make X′ huge there and dβ wrong. The formula makes the sign a property of the mathematics.

### KernelFrame: X(s) on the lift's grid

Lemma 3 asks for a smooth periodic frame X(s) of ker J_b(q*(s)). For r > 1 it would be transported along s like the normal frame N, with its holonomy cancelled. For r = 1 a unit vector of a one-dimensional subspace is determined up to sign, and `kernelVector` fixes the sign, so X(s) = x(q*(s)) and no transport is needed.

```cpp
// src/lift.cpp:243-263
    KernelFrame::KernelFrame(const Lift& lift)
    {
        const std::vector<Vec7>& Q = lift.nodes();
        const int n = lift.gridIntervals();
        std::vector<Vec7> X(n + 1, Vec7::Zero());
        for (int k = 0; k <= n; ++k) {
            Mat67 J = Mat67::Zero();
            PandaArm::output(Q[k], &J);
            X[k] = kernelVector(J);
            if (!X[k].allFinite())
                throw std::runtime_error("KernelFrame: J_b(q*) is singular at a node");
        }

        // No sign flips between neighbouring nodes: the formula of kernelVector fixes the orientation.
        minDot_ = 1.0;
        for (int k = 0; k < n; ++k)
            minDot_ = std::min(minDot_, X[k].dot(X[k + 1]));

        std::vector<Vec7> dX = PeriodicHermite<Vec7>::centralDifferences(X, lift.length());
        X_.build(lift.length(), std::move(X), std::move(dX));
    }
```

- X is computed at the lift's 2001 nodes. Node n repeats node 0 exactly (`Q[n_] = Q[0]` in the lift), so X[n] = X[0] exactly: closure is free.
- `minDot_` records min_k X(s_k)ᵀX(s_(k+1)) = 0.9999996643, read back through `minNeighbourDot()`. A sign flip would show as a value near −1.
- X′ at the nodes comes from the same fourth-order periodic differences as q*′. Against the exact derivative Dx(q*) q*′ it agrees to 1.1e-9 (tested to 1e-8).
- The throw for a singular J_b(q*) is a safeguard that no built lift can reach: the lift's Cholesky factorization of J_b J_bᵀ succeeded at every node, so J_b(q*) has rank 6 there.
- `KernelFrame` copies the values into its own spline, so it may be built from a temporary `Lift`. `minDot_ = 0.0` in the class body (`include/se3pf/lift.hpp:117`) is a default member initializer: the value a member gets when the constructor's list does not mention it.

Measured spline quality, at s_k + h/4, h/2, 3h/4 for all k: |X(s) − x(q*(s))| ≤ 2.5e-13, |J_b(q*(s)) X(s)| ≤ 2.8e-13 and |‖X(s)‖ − 1| ≤ 1.0e-13 (tests ask 1e-12).


### The redundancy-output interface

The controller does not know which β it runs with. It holds a `const RedundancyOutput*`, a pointer to an abstract base class:

```cpp
// include/se3pf/redundancy.hpp:9-20
    class RedundancyOutput {
        public:
            virtual ~RedundancyOutput() = default;

            // beta(q) and its differential dbeta (a row, stored as a column), given eta(q) and d eta(q), the first
            // row of J_Psi^-1 J_b, which the controller has already computed.
            virtual void evaluate(const Vec7& q, double eta, const Vec7& deta, double& beta, Vec7& dbeta) const = 0;

            // Among configurations with eta(Pi(q)) = eta, the level set {beta = value} is the hyperplane p^T q = b.
            // Used to find start configurations.
            virtual void levelSet(double eta, double value, Vec7& p, double& b) const = 0;
    };
```

- `virtual ... = 0` declares a pure virtual function: the base class has no implementation, every concrete subclass must provide one, and a call through the base pointer dispatches at run time to the subclass's version (one indirect call).
- `virtual ~RedundancyOutput() = default;` makes deletion through a base pointer call the right destructor. Any class meant to be used through a base pointer needs it.
- The controller is a compile-time template over the system but uses run-time dispatch for β, so switching between `LiftRedundancy` and `CouplingRedundancy` needs no new controller type.

### LiftRedundancy: β and dβ

β is the signed distance from the lift along the self-motion direction (eq:beta-flat). Its differential (eq:dbeta) follows from the chain rule with η = η(q):

```latex
\beta(q) = X(\eta)^\top\bigl(q - q^\star(\eta)\bigr),\qquad \mathrm d\beta(q) = X(\eta)^\top + \Bigl(X'(\eta)^\top\bigl(q - q^\star(\eta)\bigr) - X(\eta)^\top q^{\star\prime}(\eta)\Bigr)\,\mathrm d\eta(q)
```

```cpp
// src/lift.cpp:273-281
    void LiftRedundancy::evaluate(const Vec7& q, double eta, const Vec7& deta, double& beta, Vec7& dbeta) const
    {
        Vec7 qs = Vec7::Zero(), dqs = Vec7::Zero(), X = Vec7::Zero(), dX = Vec7::Zero();
        lift_.eval(eta, qs, &dqs);
        kernel_.eval(eta, X, &dX);
        const Vec7 e = q - qs;
        beta = X.dot(e);                               // eq:beta-flat
        dbeta = X + (dX.dot(e) - X.dot(dqs)) * deta;   // eq:dbeta: q moves directly, and through eta(q)
    }
```

| Code | Paper |
| --- | --- |
| `qs`, `dqs` | q*(η), q*′(η) |
| `X`, `dX` | X(η), X′(η) |
| `e` | q − q*(η) (here a joint-space offset, not the pose error of the solvers) |
| `beta` | β(q) |
| `dbeta` | dβ(q), a row stored as a column `Vec7` |
| `deta` | dη(q), also a row stored as a column |

- `X` alone is the direct dependence of β on q. The bracket times `deta` is the dependence through η(q): when q moves, the closest point η moves, and with it both q*(η) and X(η).
- Everything is a fixed-size local, so `evaluate` does not allocate. It is `const` (it changes nothing) and marked `override`, so the compiler checks that it really overrides the base's signature. Without `override`, a mismatched parameter type would declare a new, unrelated function, and the error would surface far away, as an abstract class that cannot be built.
- `final` on the class (`include/se3pf/lift.hpp:127`) forbids further subclasses. A compiler that knows an object's exact type may then skip the virtual dispatch; the controller calls through a base pointer, so it still dispatches.

### Where dη comes from

Π(q) = Ψ(η, ξ) gives J_b q̇ = J_Ψ(η, ξ) (η̇, ξ̇), so (η̇, ξ̇) = J_Ψ⁻¹J_b q̇, and dη is row 0 of J_Ψ⁻¹J_b. The controller already computes that matrix for the first six rows of A, with one LU factorization of J_Ψ, so it passes row 0 to `evaluate` instead of letting β recompute it:

```cpp
// include/se3pf/controller.hpp:223-239
                // J_Psi^-1 J_b by one LU factorization of J_Psi; the inverse is never formed. Its rows are
                // d eta (row 0) and d xi (rows 1..5).
                const Mat6 JPsi = tube_.JPsi(out.eta, out.xi);
                const Mat<6, n> top = JPsi.partialPivLu().solve(Jb);
                if (!top.allFinite())
                    return false;
                out.A.template topRows<6>() = top;

                // eq:A, last row: d beta, which needs d eta = row 0 of J_Psi^-1 J_b (eq:dbeta)
                if constexpr (n == 7) {
                    const Vec7 deta = top.row(0).transpose();
                    Vec7 dbeta = Vec7::Zero();
                    redundancy_->evaluate(q, out.eta, deta, out.beta, dbeta);
                    out.A.row(6) = dbeta.transpose();
                    if (!std::isfinite(out.beta) || !dbeta.allFinite())
                        return false;
                }
```

`out.A.row(6) = dbeta.transpose();` writes dβ as the last row of A. `if constexpr (n == 7)` is a compile-time branch: for the rigid body (n = 6) the block is not compiled at all, so `Vec7` code never meets a 6-column matrix.

### Why dβ X = +1 on the lift

On the lift, q = q*(η), so q − q*(η) = 0 and the X′ term drops out. X(η) spans ker J_b(q), so J_b X = 0 and dη X, which is row 0 of J_Ψ⁻¹(J_b X), is 0. What remains is dβ X = XᵀX = 1, exactly +1 and not −1. A sign error in the X term would give −1, which a test of |dβ X| = 1 would miss; the test checks +1 to 1e-12 (measured 2.1e-13). Off the lift the X′ term is active: at the test's start configurations it has size up to 0.45, and dβ matches a central difference of β to 9.7e-11.

### Why references, and the deleted constructors

```cpp
// include/se3pf/lift.hpp:127-142
    class LiftRedundancy final : public RedundancyOutput {
        public:
            LiftRedundancy(const Lift& lift, const KernelFrame& kernel) : lift_(lift), kernel_(kernel) {}
            LiftRedundancy(const Lift&& lift, const KernelFrame& kernel) = delete;   // no temporaries
            LiftRedundancy(const Lift& lift, const KernelFrame&& kernel) = delete;
            LiftRedundancy(const Lift&& lift, const KernelFrame&& kernel) = delete;

            void evaluate(const Vec7& q, double eta, const Vec7& deta, double& beta, Vec7& dbeta) const override;

            // p = X(eta), b = X(eta)^T q*(eta) + value
            void levelSet(double eta, double value, Vec7& p, double& b) const override;

        private:
            const Lift& lift_;
            const KernelFrame& kernel_;  // X of Lemma 3 (not the normal frame N of the tube)
    };
```

`LiftRedundancy` stores `const Lift&` and `const KernelFrame&`, not copies: the lift and the kernel frame hold four splines of 2001 `Vec7` values between them (q*, q*′, X, X′), plus the lift's copy of the nodes, and `PandaExample` owns exactly one of each. A reference member, though, is only valid while its object lives.

`LiftRedundancy beta{Lift(path), KernelFrame(lift)};` would compile against the first constructor alone: a temporary binds to a `const&`. The temporaries die at the end of that statement, and `beta` keeps two dangling references; every later call reads freed memory and may still print plausible numbers. The three deleted overloads stop this at compile time (g++: "use of deleted function"). A temporary binds better to `const Lift&&` than to `const Lift&`, so overload resolution picks the deleted overload, and using a deleted function is a compile error. One overload per argument combination covers every case.

The example uses braces on purpose. Written with parentheses, `LiftRedundancy beta(Lift(path), KernelFrame(lift));` creates no object at all: C++ reads `Lift(path)` as a parameter named `path` of type `Lift`, so the line declares a function `beta` (the "most vexing parse"; GCC warns with `-Wvexing-parse`). `LiftRedundancy beta(Lift(path), kernel);` with a named `kernel` is an object again, and fails on the deleted overload as intended.

### levelSet: the hyperplane {β = value}

```cpp
// src/lift.cpp:283-289
    void LiftRedundancy::levelSet(double eta, double value, Vec7& p, double& b) const
    {
        Vec7 qs = Vec7::Zero();
        lift_.eval(eta, qs);
        kernel_.eval(eta, p);
        b = p.dot(qs) + value;  // X^T (q - q*) = value  <=>  X^T q = X^T q* + value
    }
```

For a fixed η, β(q) = value is linear in q: X(η)ᵀq = X(η)ᵀq*(η) + value. So p = X(η) and b = X(η)ᵀq*(η) + value. The hyperplane is the right level set only among configurations whose closest point is that η, which `startConfiguration` ensures by fixing the pose.

### CouplingRedundancy: β = q₃ − q₁

```cpp
// src/lift.cpp:291-301
    void CouplingRedundancy::evaluate(const Vec7& q, double, const Vec7&, double& beta, Vec7& dbeta) const
    {
        beta = q[2] - q[0];
        dbeta = Vec7::Unit(2) - Vec7::Unit(0);
    }

    void CouplingRedundancy::levelSet(double, double value, Vec7& p, double& b) const
    {
        p = Vec7::Unit(2) - Vec7::Unit(0);
        b = value;
    }
```

The coupling is the earlier implementation's seventh output, for a lift with q₃ = q₁ (the coupled six-DOF arm): β = q[2] − q[0] in zero-based indices, dβ = (e₃ − e₁)ᵀ, and the level set p = e₃ − e₁, b = value. It is linear in q and does not depend on η, so the sampled loop cannot excite it at O(Δt). It is kept for comparison runs and tests; `example.start(example.coupling(), ...)` gives a start configuration for it.

C++ point: `double, const Vec7&` with no parameter names. An unnamed parameter is legal and says "deliberately unused"; a named unused parameter would trigger `-Wunused-parameter` (part of the project's `-Wextra`), which the CI build turns into an error with `-Werror`.

### startConfiguration

```cpp
// src/lift.cpp:306-317
    bool startConfiguration(const Tube& tube, const RedundancyOutput& beta, double s0, const Vec5& xi0, double beta0,
                            const Vec7& guess, Vec7& q)
    {
        Vec7 p = Vec7::Zero();
        double b = 0.0;
        beta.levelSet(s0, beta0, p, b);
        Vec7 qk = guess;  // constrainedIK starts from its argument; q is written only on success
        if (!constrainedIK(tube.Psi(s0, xi0), p, b, qk))
            return false;
        q = qk;
        return true;
    }
```

To start at the pose Ψ(s₀, ξ₀) with β = β₀:

1. `beta.levelSet(s0, beta0, p, b)` gives the hyperplane pᵀq = b.
2. `constrainedIK(tube.Psi(s0, xi0), p, b, qk)` solves the pose and the hyperplane together by Newton on [J_b; pᵀ], from `guess` (usually q*(s₀)).
3. On success `q = qk`; on failure it returns `false` and leaves `q` unchanged.

Why this is correct: by Proposition 1, the closest point of Ψ(s₀, ξ₀) is η = s₀ for ξ₀ inside the tube. So X(η) = X(s₀), and the hyperplane computed at s₀ is the level set {β = β₀} of the true β at that pose.

Measured at the four test starts: pose error 3.3e-16, (η, ξ) recovered to 5.5e-14, β to 5.4e-15 (tests ask 1e-10, 1e-9 and 1e-10). The paper's start lies 0.416 rad from q*(0.1) even though β = 0, because the pose itself is off the path (ξ₀ ≠ 0) and every joint adjusts. The self-motion start lies 0.200018 rad from q*(0.1) with β = 0.2: the extra 1.8e-5 is the curvature of the self-motion manifold, along which q leaves the straight line q* + 0.2X.
