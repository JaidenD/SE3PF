## Mutation drills

A mutation drill changes one line, rebuilds, and asks which test catches the change; predicting the answer before you run it is the exercise. Every drill below was applied to a scratch copy, rebuilt in Release, run against the full suite (132 test cases, about 3 s), and reverted; the answers quote the real failing checks.

### How to run a drill

Never mutate the real project: make a drill copy with its own git repository, so `git checkout` reverts any edit. The project sits untracked inside the Desktop repository, so `git init` in the copy is the clean way to get that.

```bash
rsync -a --exclude 'build*' --exclude out --exclude .venv --exclude third_party \
    ~/Desktop/SE3_pathFollowing/ ~/drills/se3pf/
cd ~/drills/se3pf && git init -q && git add -A && git commit -qm baseline
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
    -DFETCHCONTENT_SOURCE_DIR_CATCH2=$HOME/Desktop/SE3_pathFollowing/build/_deps/catch2-src
cmake --build build -j8 && ./build/tests | tail -2      # baseline: All tests passed (259448 assertions in 132 test cases)

# one drill: edit the line, rebuild only the tests, run, read, revert
cmake --build build -j8 --target tests
./build/tests | tail -3                                  # the counts: test cases: 132 | 131 passed | 1 failed
./build/tests -r compact 2>&1 | grep failed | cut -c1-220 | head
git checkout -- src/se3.cpp                              # revert
```

A mutation in a `.cpp` file rebuilds in 2 to 15 s: one object file and the link. One in `include/se3pf/controller.hpp` or `spline.hpp` took 25 to 45 s here, because templates live in headers and every file that includes them must be compiled again.

Catch2 prints a tolerance such as `1e-13` as `0.0`, because it shows doubles in fixed notation with 10 decimals. That is why the tests wrap errors in `CAPTURE(sci(err))` (`tests/test_helpers.hpp:69-76`); in the compact output, read `1.222469997 < 0.0` as "1.2225 is not below 1e-13".

### Answers

1. `ad` without its v̂ block in the right place. Fails only "ad_a b = (hat(a) hat(b) - hat(b) hat(a))^vee" (20 checks, e.g. 1.2225 instead of below 1e-13). Why: no library code calls `ad`; only the general-W geodesic ODEs of milestone 11 would. A function nothing uses is guarded by its own test alone.

1. Γ with exp(ω̂) instead of exp(ω̂)ᵀ. 16 test cases fail: "Gamma is the derivative of Exp_I (eq:Gamma); GammaInv inverts it" (0.6106 > 1e-8, and GammaInv·Gamma off I by 1.02), "Tube: J_Psi against central differences of Psi" (0.313), the four tests that check A against central differences of ȳ (first failing checks 0.17 to 0.71), "LiftRedundancy: dbeta against a central difference of beta off the lift" (0.0094), and the closed loops (rigid pose run: max deviation 0.0447 > 1e-3; Panda: max ||ξ| − design| off by 3.4e-4; halving dt gives ratio 0.97, not 2). Why: Exp_I's translation is v itself, so its body velocity is Rᵀ δv; with R, every J_Ψ column is wrong off the path. "Tube: J_Psi(eta, 0) = [zeta_gamma(eta) | N(eta)]" still passes, because R = I at ξ = 0. The Newton round trips pass too: the projection uses `GammaInv`, which was not touched.

1. ζ_γ′ with +ω̃ × ṽ. 57 test cases fail. One fails directly: "coning circle: unit speed, consistent derivatives, closed" (ζ_γ′ against a central difference of ζ_γ: 2.2154 > 1e-6). The other 56 die on the exception "Tube: the holonomy is not a rotation; the transport is too inaccurate", thrown while building `pandaTube()` or the PandaExample fixture. Why: eq:transport keeps N₀ᵀWζ_γ = 0 only if the ζ_γ′ it uses is the true derivative. With the wrong one, N₀ drifts out of the normal space and H stops being orthogonal, so the guard at `src/tube.cpp:182` throws. The rigid-body tests pass: `TumblingCircle::acceleration` has its own copy of the line (`src/path.cpp:138`).

1. y′ without 1/h on the y_k term. 34 test cases fail: "PeriodicHermite: fourth-order values, third-order derivatives" (the derivative error ratio for n = 100 vs 200 is 0.498 instead of above 7), "PeriodicHermite: closes exactly, wraps s, works for Eigen types" (derivative off by 14.04), "Tube: N' agrees with central differences of N" (33273), "Lift: q*' between the nodes is the derivative of the interpolant" (7300), "KernelFrame: X' against central differences" (2774), every A test, and the closed loops (`run.ok` false). Why: y′ = (dy/dt)(dt/ds) = (dy/dt)/h, and the y_k term lost that factor while the y_{k+1} term on the next line kept it (1/h = 2597 for N on 2000 nodes); N′ enters J_Ψ's first column, so A is wrong everywhere off the path.

1. Second-order node derivatives. 7 test cases fail: "PeriodicHermite::centralDifferences is fourth order" (error ratio 4.0 instead of above 14), "Lift: q*' at the nodes agrees with the implicit-function derivative" (1.88e-5 > 5e-9, the design doc's predicted 1.9e-5), "KernelFrame: X' against central differences" (4.8e-6 > 1e-8), "KernelFrame: X spans ker J_b(q*) between the nodes" (2e-10 > 1e-12), "LiftRedundancy: beta = 0 and dbeta X = +1 on the lift" (1e-10 > 1e-11), "Controller<PandaArm> with the lift's beta: on the lift xi = 0, beta = 0 and A is invertible", and "RedundancyOutput: levelSet is the hyperplane {beta = value}". Why: q*′ and X′ shape the Hermite interpolant between nodes; an O(h²) node slope makes q*(s) miss FK(q) = γ(s) by about 1e-10 between nodes. The closed loops pass: 1e-10 is far below their tolerances.

1. The clamp of the node index removed. No test fails. Why: k = n needs x/h to round to n, and two inputs do that. A tiny negative s, such as −1e-17: `std::fmod` returns it unchanged, and x + L rounds to L exactly, so k = 2000 on all three tubes. And for about 10 % of random (L, n) pairs, for example L = 99.904147494980833 and n = 737, the largest double below L gives k = n too. No test evaluates a spline at such an s: the tests' random s never land within 1e-16 below the seam, and `Tube::wrap` has its own guard for the case (`src/tube.cpp:218`), while `Tube::frame` passes s to `eval` unwrapped. Without the clamp, `eval` then reads `y_[n + 1]`, one past the end of the vector: undefined behaviour that no test here can see.

1. eq:holonomy with the wrong sign. 34 test cases fail: "Tube: the frame closes, N(s_n) = N(s_0) on the node values" (gap 3.09 > 1e-9), "Tube: N' agrees with central differences of N" (4675), "Tube: N^T W N = I and N^T W zeta_gamma = 0" (4.5e-9 > 1e-9, between nodes), the start-pose anchors (25.4265° instead of 25.45°), the round trips (η off by 1.1e-7), and many controller and closed-loop tests. Why: N(L) = N₀(0) H exp(Φ) = N₀(0) H² instead of N₀(0). The node derivatives still use −(1/L) N Φ of eq:frame-ode, so N′ disagrees with N and the interpolant is wrong between nodes; that is why more than the closure test catches it here.

1. A fixed direction for 1 − cos θ < 1e-8. 6 test cases fail: "rotationPlanes: logarithm and exponential of a rotation in SO(5)" (count 1, not 2: the 1e-5 plane, 1 − cos = 5e-11, is dropped), "Tube: holonomy H is a rotation; Phi = log H is skew and has two planes" (logError 7.8e-5 > 1e-10), "Tube: rotation angles of the holonomy" (second angle 0 instead of 8.0e-5), "Tube: the frame closes" (gap 7.8e-4), "Tube: N' agrees with central differences of N" (1.19 at the seam), and "PandaExample: a start for the coupling output" (3.4e-6 from the reference). Why: 1 − cos(8.0e-5) = 3.2e-9 is below 1e-8, so the Panda's small plane counts as fixed and its 8e-5 rad of holonomy is never cancelled. The 20 s closed loops pass: when η crosses the seam (t = 8.576 s and 18.201 s), |ξ| is 3.4e-7, and an 8e-5 rad jump of the frame moves ξ by about 3e-11.

1. Gram–Schmidt on e₆, …, e₁. 17 test cases fail: "Tube: initial frame by Gram-Schmidt on zeta_gamma(0), e_1, ..., e_6, in that order" (1.0 off), the start poses (rigid body 21.163° instead of 25.45°, Panda 9.893° instead of 15.07°), the wrong root from L/2 (6.0406 instead of 5.614), the coarse tube radius (0.12755 instead of 0.124658), the coupled start (0.395 rad off), and the closed-loop anchors (first rigid command 16.48 instead of 14.48 in the velocity run; first Panda command 25.1 % instead of 49.4 %). The holonomy-angle tests pass. Why: any order gives a valid frame N(s)Q (Lemma 1), and H becomes QᵀHQ with the same angles; but ξ₀ is a coordinate vector in the frame, so the start pose Ψ(0.1, ξ₀) moves.

1. Newton without the wrap. 3 test cases fail: "Tube: Psi^-1 round trip and |xi| = dist(g, C) on the Panda tube" (η = −0.0065 < 0), "Tube: Newton converges from guesses offset by +-0.05" (η = 0.7890 > L = 0.7701), and "Tube: Newton steps across the seam s = 0 = L and still returns eta in [0, L)" (η = 0.7801 for s = 0.01). Why: the root is right modulo L, and `frame` wraps internally, so ξ is still right; only the contract "η in [0, L)" breaks. That contract is what lets the controller compare η with η_d and wrap its prediction.

1. J_Ψ without Γ(Nξ) N′ ξ. 16 test cases fail: "Tube: J_Psi against central differences of Psi" (0.111), the four tests that check A against central differences of ȳ (first failing checks 0.008 to 0.014), "LiftRedundancy: dbeta against a central difference of beta off the lift" (0.0027), and the closed-loop anchors (rigid max deviation off by 9.1e-5, outside its 5 % band; Panda max |β| 5.0e-5 at t = 1 s in the first-second run instead of 1.52e-5 at 0.409 s; halving dt no longer halves the β peak; the dt = 0.3 s run fails at 2.7 s instead of 2.1 s). "Tube: J_Psi(eta, 0) = [zeta_gamma(eta) | N(eta)]" passes. Why: moving η also turns the normal frame, at the rate N′ξ. That term vanishes on the path, but at the rigid start (|ξ| = 0.62) it is large enough to move the closed loop's anchors.

1. C ζ with the wrong sign. 5 test cases fail: "RigidBody::coriolis: C zeta = -(J omega x omega, m v x omega), and it does no work" (4.0 off on the hand-made case), "RigidBody::integrate, free motion: energy and momenta conserved" (angular momentum drifts by 1.88; the energy stays conserved), "RigidBody::integrate, closed-form motion of a symmetric body" (ω off by 2.0: (cos t, −sin t, 1)), and two closed loops (pose run: peak at 0.398 s instead of 0.43 ± 0.011 s; velocity run: final |ξ| 4.38e-6 instead of 2.81e-6). Why: both gyroscopic terms are orthogonal to ζ, so the energy cannot see the sign. The closed loop cancels the same wrong C ζ at each sample, so it still converges. But within each 2 ms hold the plant's C(ζ(t))ζ(t) drifts from the held value differently, and the tight anchors move.

1. `minCoeff` without `PropagateNaN`. Fails only "Panda jointMargin fails closed: NaN if any joint is NaN, -inf if a joint is infinite" (18 checks, three for each of joints 2 to 7: `std::isnan(margin)` is false, `margin >= 0.10` holds with 0.7156, and the reported joint is wrong). Why: the default `minCoeff` compares with `<`, and every comparison with NaN is false. So a NaN after the first entry is skipped, and the other joints' margin comes back. A check `margin >= 0.10` would then pass on a corrupted q.

1. Half the null-space step. Fails only "Lift: the paper's lift table": 40 updates at s = 0 (bound 12), 30 typical (bound 10), 37 at most (bound 14). Why: the fixed point is unchanged (same q*, same closure, same margins), so every value test passes. The null-space residual now shrinks by about 0.5 per update instead of 0.05 (Trace 5). Only the iteration-count anchors see a slower solver.

1. The generalized cross product with the opposite sign. 6 test cases fail: "kernelVector: the orientation of the cross product on hand-made matrices" (2.0 off), "kernelVector: a unit vector of ker J_b with the orientation of the generalized cross product" (det([xᵀ; J_b]) = −25.8 < 0), "KernelFrame: X' against central differences; no sign flips; X(0) of the reference" (1.42 off), "Controller<PandaArm> with the lift's beta: A is the Jacobian of ybar off the lift" (the X′ term at the self-motion start 8.0e-4, below its 1e-3 floor), and both self-motion runs (max |ξ| 1.34e-6 > 1.3e-6; the β deviation misses its 1.51035e-4 anchor by 2.0e-6, outside ± 1 %). Why: −X is still a unit kernel vector, so β = Xᵀ(q − q*) and dβ·X = +1 still hold. But β = 0.2 now starts the self-motion run on the other side of the lift; only the orientation tests and the tight closed-loop anchors see that.

1. The X′ term of eq:dbeta with the wrong sign. 9 test cases fail: "LiftRedundancy: dbeta against a central difference of beta off the lift" (0.565 > 1e-8), "Controller<PandaArm> with the lift's beta: A is the Jacobian of ybar off the lift" (0.625), the paper runs (max |β| 0.0193 instead of 1.52e-5), the self-motion runs (β deviation 1.30e-4 off), the dt-halving test (ratio 1.0), the first command (48.3 % instead of 49.4 %), and the dt = 0.3 s failure (2.7 s instead of 2.1 s). On the lift q = q*, the term vanishes, so "LiftRedundancy: beta = 0 and dbeta X = +1 on the lift" passes: that is why the tests check A at the paper start, 0.42 rad off the lift.

1. A prediction without η̇ Δt. 4 test cases fail: "Controller<RigidBody>: step returns qdd* with A qdd* + Adot qdot = mu" (prediction off by 4.3e-4) and the three rigid-body runs (`maxIterations` 2, not 1). The Panda runs pass. Why: one Newton update from a guess e₀ off leaves about C e₀², with C ≈ 0.007 on the Panda tube (Trace 3). So it reaches |φ| < 1e-10 only for e₀ below about 1e-4. The Panda moves 0.08 × 1e-3 = 8e-5 per period (one update suffices), the rigid body about 1e-3 per 2 ms period (two are needed).

1. Ȧq̇ with the wrong sign. 15 test cases fail: the three "A qdd* + Adot qdot = mu" tests (errMu 0.37 to 1.46), "Controller<RigidBody>: signs of the tangential and transverse laws" (0.063), "Controller<RigidBody>: the mu ramp multiplies mu, not Adot qdot" (0.47), and every closed-loop anchor (rigid pose run: max deviation 0.246; Panda: 1.4e-3 off). Why: q̈* = A⁻¹(μ − Ȧq̇) cancels the velocity-dependent part of ȳ̈ = A q̈ + Ȧ q̇. With the sign flipped, it doubles that part instead. At rest Ȧq̇ = 0, so the tests at rest and the T = 0 runs pass; the comparison of 1, 4 and 16 substeps passes too, because all three runs carry the same wrong Ȧq̇.

1. The ramp on Ȧq̇ as well. Fails only "Controller<RigidBody>: the mu ramp multiplies mu, not Adot qdot; r(0) = 0 and r(T) = 1" (0.235 > 1e-8). Why: Ȧq̇ is not a command but the cancellation of a term of the dynamics of ȳ. Ramping it would leave −(1 − r) Ȧq̇ uncancelled while the arm moves; the test catches it with a moving state at t = 0. The closed loops have no ramp (`rampTime = 0`, r = 1), so they cannot see it.

1. Ȧq̇ also at rest. No test fails: the mutation is equivalent. Why: at rest `retract(q, 0, ±h)` returns q itself, so both extra projections compute the same A, and (A₊ − A₋)·0 = 0 exactly. The shortcut only saves the two extra projections. The allocation test still passes too: the extra work allocates nothing.

1. `stepCount` without its `+ 1e-9`. No test fails. Why: every (T, dt) the tests use (20/1e-3, 20/0.002, 20/0.3, 1/1e-3, 0.05/1e-3, L/0.08/1e-3, ...) divides to at or above the intended integer. But 0.3/0.1 = 2.9999999999999996 and 0.7/0.1 = 6.9999999999999991 in floating point, so `stepCount(0.3, 0.1, ...)` would return 2 and a 0.3 s run would lose its last instant. A test with T = 0.3, dt = 0.1 would catch it: a good one to add.

1. q updated without ½Δt² q̈*. 6 test cases fail. Five fail through the log check `errQ < 1e-14` (1.49e-6 for the paper run): both paper runs (and their max ||ξ| − design| 2.99e-6 off, peak at 0.653 s instead of 0.409 s), both self-motion runs (max |ξ| 1.83e-5 > 1.3e-6 in the one-loop run), and the dt-halving test. The sixth is the dt = 0.3 s run, which no longer fails (`REQUIRE_FALSE(run.ok)` fails). Why: with q̈* held over the period, the exact update is q + Δt q̇ + ½Δt² q̈*. Dropping the last term is a first-order error, and the designed responses expose it.

1. Substeps of length Δt instead of Δt/4. 5 test cases fail: all rigid-body runs (max deviation 0.4056 instead of 9.69e-4) and "simulate: the substeps only refine the plant's integration: 1, 4 and 16 substeps agree" (η differs by 1.70 after 1 s). Why: each control period now integrates 4Δt of plant time while the controller assumes Δt, so the loop runs a different plant. The substep test exists for exactly this.
