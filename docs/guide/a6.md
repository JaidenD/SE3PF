## Check yourself

These questions test whether you can predict what the code does and why, without looking. Each answer below is short and uses the numbers measured for this guide.

1. `Metric::Exp` and the matrix exponential of ζ̂ give the same rotation. Where do they differ, and what do both give for ζ = (0, 0, π/2, 1, 0, 0)?
2. `ConingCircle::acceleration` loses the term `- w.cross(v)` on line 89. Which check fails, by how much, and what happens when a `Tube` is built on that path?
3. Why does `logSO3` need a separate branch for θ > π − 1e-4, and why does the symmetric-part formula not have the same problem?
4. Why is θ computed as `atan2(s.norm(), c)` and not `acos(c)`? What does acos return at θ = 1e-8?
5. For which rotation angles does `Metric::Log` return false? Derive the band from the trace test. What does `distance` return then, and why is that value convenient?
6. `vee(R - R.transpose())` does not compile, but `expSO3(w + h * d)` does. Why?
7. `Metric` refuses W = diag(1, 1, 2, 1, 1, 1), yet `constantSpeed` would accept both paths in it. Why does it accept them, and what would go wrong if `Metric` did too?
8. Why is the translation block of Γ(ζ) equal to exp(ω̂)ᵀ and not the identity?
9. Trace `eval(-1e-17, y)` on a spline with n = 100 and L = 0.77: the values of x, k and t, and the result.
10. In a Release build, what would `eval(NaN, y)` do if the `finite` guard were removed?
11. When n doubles, by what factors should the spline's value and derivative errors fall? Why does the test require only 14 and 7?
12. `rng()` in `test_helpers.hpp` is `inline`. What breaks if it is declared `static` instead?
13. The logSO3 test still passes if the near-π branch is deleted. Why, and which extra test angle would catch it?
14. Why does `Jr` lose accuracy just above θ = 1e-6 while `JrInv` does not, although `JrInv`'s K² coefficient cancels too?
15. Why does `Tube` store a copy of the `Metric` but only a reference to the `Path`?

### Answers

1. They differ in the translation. Exp_I puts v there; the matrix exponential (the screw motion) puts J_l(ω)v. For this ζ, Exp_I gives p = (1, 0, 0) and the matrix exponential gives (2/π)(1, 1, 0) = (0.6366, 0.6366, 0), a quarter arc. A one-parameter subgroup is a geodesic of the product metric only when ω × v = 0, since ad_ζᵀWζ = (0, −w_p ω × v).
2. The ζ_γ′ check of `checkArcLengthPath` fails with an error of 1.98 against a tolerance of 1e-6. A `Tube` on that path throws "Tube: the holonomy is not a rotation; the transport is too inaccurate". The transported frame leaves the normal space (|N₀ᵀWζ_γ| reaches 0.21), and H has |HᵀH − I| = 0.48 and det H = 0.74, far beyond the 1e-6 guard of `src/tube.cpp:182`.
3. s = sin θ · n carries rounding of about 1e-16, and near π, sin θ ≈ π − θ. The axis s/‖s‖ then has a relative error of about 1e-16/(π − θ): over the test's 20 axes the round trip without the branch is off by 3.0e-10 at π − 1e-6 and 3.2e-8 at π − 1e-8. The symmetric part divides by 1 − cos θ ≈ 2, and the column it normalizes has length at least 1/√3.
4. acos has an infinite slope at ±1, so rounding in c = 1 − θ²/2 is amplified. At θ = 1e-8, c rounds to exactly 1 and acos returns 0, a 100 % error. atan2 takes the sine part ‖s‖ ≈ θ directly and is accurate to one rounding of θ at every angle measured.
5. tr R = 1 + 2 cos θ, so tr R + 1 = 2(1 − cos(π − θ)) ≈ (π − θ)². The test tr R < −1 + 1e-12 refuses π − θ below 1e-6; at exactly 1e-6 the rounding of the trace decides (measured: 1.01e-6 passes on every axis, 0.99e-6 fails on every axis, 1e-6 passes on 592 of 1000). `distance` then returns NaN, and since `d < best` is false for NaN, `globalProject` never picks such a sample without a special case.
6. `vee` has a `Matrix3d` and a `Matrix4d` overload. The expression `R - R.transpose()` is neither, converts to both through Eigen's template constructor, and the two conversions rank equally, so the call is ambiguous. `expSO3` has one overload, so converting the expression to a temporary `Vector3d` is unambiguous.
7. On both curves ω̃_z is constant (cos α − 1 and 1) and so is ω̃_x² + ω̃_y², so weighting ω_z by 2 keeps ‖ζ̃‖_W constant. If `Metric` accepted it, `Exp`, `Log` and `Gamma` would still evaluate the product-type closed forms, which are not that metric's geodesics; every ξ, η and J_Ψ would be silently wrong.
8. Exp_I(ζ + tδ) has position v + tδ_v in space, so its spatial velocity is δ_v. Γ is a body-coordinate derivative, Exp_I⁻¹ · d/dt Exp_I, and the body velocity of a pose with attitude R is Rᵀδ_v = exp(ω̂)ᵀδ_v.
9. `fmod` gives −1e-17, and x = −1e-17 + L rounds to exactly L. Then x/h = 100 exactly, so k = 100 is clamped to 99 and t = 1. The weights are (0, 0, 1, 0), so y = y_[100], which `build` set to y_[0]: the right value for s ≡ 0.
10. `fmod(NaN, L)` is NaN, `x < 0.0` is false, and `static_cast<int>(NaN)` is undefined behaviour (INT_MIN on x86). The clamp `k >= n_` is false, and `y_[k]` reads far outside the vector: a crash or garbage. With the guard, k = 0 and t = NaN make every entry NaN.
11. Values have error O(h⁴), so they fall 16 times; derivatives have error O(h³), so they fall 8 times. The measured ratios are 16.00 and 7.99. The thresholds 14 and 7 leave 12.5 % for higher-order terms, which matter on coarser grids.
12. A `static` function has internal linkage, so every `.cpp` that includes the header gets its own `rng()` and its own generator. The listener in `rng_listener.cpp` would reseed only its own copy, the test files would keep drawing from unreseeded generators, and results would depend on test order again.
13. Without the branch, the worst round-trip error at π − 1e-6 is 3.0e-10, below the 1e-9 tolerance. At π − 1e-8 the error is 3.2e-8 and the test fails; that angle also catches θ from `acos` (1.7e-8).
14. In `Jr`, the cancelling coefficient (1 − cos θ)/θ² multiplies K, whose size is θ. Its error of about 1e-16/θ² becomes about 1e-16/θ in the matrix: about 5e-11 just above θ = 1e-6. In `JrInv` the K term is exactly ½K, and the cancelling coefficient multiplies K², of size θ², so the matrix error stays near 1e-16 (about 4e-16 measured).
15. A `Metric` is a 288-byte value that never changes, so a copy is cheap and cannot dangle. A `Path` is abstract: storing it by value would require its concrete type, so `Tube` keeps a `const Path&` and deletes the constructor that would bind it to a temporary.
