## Check yourself

These questions test whether you could have written this layer: each asks why a line is the way it is, or what breaks if it changes. Try each before reading the answer.

1. In `PandaArm::output`, why must `p += R * ti;` come before `R = R * Ri;`, and why is `R = R * Ri` safe without a temporary of your own?
2. What does passing `Jb = nullptr` to `PandaArm::output` save, and what does it not save?
3. A sensor glitch writes NaN into q[4]. What do `jointMargin` with the default `minCoeff()` and with `minCoeff<PropagateNaN>` return, and which one makes `margin >= 0.10` fail?
4. Why are the joint limits static functions returning a `Vec7`, while `tauRateMax` is a `static constexpr double`?
5. The projected Newton step takes 11 updates at s = 0 and 9 at a typical node. Why that many, when Newton is supposed to converge in a handful?
6. Why is the closure gap measured before `Q[n_] = Q[0]`, and what would the test "the branch closes" see if it were measured through `Lift::eval`?
7. Why does `minimumCheck` find q₊ and q₋ with `constrainedIK` instead of using q* ± δx, and what value would the shortcut give?
8. What is ‖n‖ in `kernelVector`, and what does the function return when J_b loses rank?
9. Why does `KernelFrame` need no sign alignment between neighbouring nodes, and no holonomy correction?
10. Show that dβ X = +1 on the lift. Why does the test check +1 and not |dβ X| = 1?
11. Where does `deta` come from, and why is it a parameter of `evaluate` rather than computed inside `LiftRedundancy`?
12. What happens at compile time, and what would happen at run time without the deleted overloads, for `LiftRedundancy beta(Lift(path), kernel);`?
13. In `simulate`, why is `q` updated before `qd`, and why is the update exact?
14. Why does the self-motion run start with q̇₀ = A(q₀)⁻¹(ν_d, 0, ..., 0) instead of at rest?
15. If someone moved the declaration of `paperStart_` above `lift_` in `PandaExample`, what would the compiler say, and what would happen when the program runs?

### Answers

1. The translation of (R, p)·T_i is p + R t_i with the old R; updating R first would rotate t_i by R R_i, which is not the DH product, and the origins from joint 3 on would be wrong. `R = R * Ri` is safe because Eigen assumes a matrix product may alias its destination and evaluates it into a temporary before assigning; only `.noalias()` would remove that protection.
2. It saves the inverse g⁻¹, the 6 × 6 adjoint `Ad(inverse(g))` and its product with the 6 × 7 J_s. It does not save the seven spatial columns (z_i, p_i × z_i), which the loop accumulates in every call because each costs one cross product.
3. With the default `PropagateFast`, Eigen leaves the result unspecified when a NaN is present; measured with this build, the NaN margin of joint 5 is skipped (it is not the first entry), and the function returns the smallest margin of the other joints, so the corrupted q passes. With `PropagateNaN` it returns NaN with `joint = 4`, and `margin >= 0.10` is false because every comparison with NaN is false. The code uses the second.
4. An Eigen `Vec7` cannot be `constexpr`, so a `static const Vec7` would be built by code that runs before `main`, in an order unspecified across `.cpp` files; another file's static could read it as zeros. A function builds the value when called. A `double` is a literal type, so it can be `static constexpr`, which the compiler fixes at compile time.
5. The step is Newton for the pose equation but only a fixed-point iteration for the Lagrange condition, because it ignores how ker J_b turns as q moves (the Dxᵀ(q − q_r) term of ∇h). The null-space residual shrinks by a constant factor per update, 0.025 to 0.18 depending on where on the path, instead of squaring. At a typical node the first update leaves a residual near 4e-5, and at a factor of 0.08 it takes 8 more updates to pass 1e-12; from q_r at s = 0, 0.99 rad away, it takes 11 in all.
6. After `Q[n_] = Q[0]`, and in the spline, s = L wraps to 0 and returns node 0 exactly, so the gap would always read 0 and a branch that did not close would pass. The test also checks `gap > 0.0` for that reason: measured 1.47e-13.
7. f(q) = ‖q − q_r‖² is quadratic, so its second difference along any straight line is 2δ² = 5e-3, whatever q* is. Only points on the curved self-motion test whether q* is a minimum. The projected points give 4.1028e-3 at worst, positive, so q* is a minimum.
8. By Cauchy–Binet, ‖n‖² = det(J_b J_bᵀ), so ‖n‖ is the product of the six singular values of J_b (0.0735 at q*(0)). If J_b loses rank, n = 0 and `n / n.norm()` is 0/0, so every entry is NaN, which any `allFinite` check catches.
9. The sign is part of the formula: det([xᵀ; J_b]) = ‖n‖ > 0, so x(q) is a smooth function of q with no choice to make, and X(s) = x(q*(s)) inherits the periodicity of q*. Holonomy arises when a frame is transported along the path, as N is in the tube; for r = 1, X is determined by q*(s) up to sign, and the sign is fixed, so nothing is transported.
10. On the lift q = q*(η), so the X′ term vanishes, and X spans ker J_b(q), so dη X = (row 0 of J_Ψ⁻¹J_b) X = 0. That leaves dβ X = XᵀX = 1. A sign error in the X term of eq:dbeta would give −1, which a test of |dβ X| = 1 would accept.
11. It is row 0 of J_Ψ⁻¹J_b, because J_b q̇ = J_Ψ(η̇, ξ̇). The controller already computes that whole 6 × 7 matrix with one LU factorization of J_Ψ for the first six rows of A, so passing row 0 avoids a second factorization and keeps `LiftRedundancy` free of tube code.
12. The temporary binds better to `const Lift&&` than to `const Lift&`, so overload resolution selects the deleted constructor and compilation fails. Without the deleted overloads, the code would compile, the temporary lift would be destroyed at the semicolon, and `beta` would read freed memory at every call, possibly still returning plausible numbers.
13. The new q needs the old q̇: q_(k+1) = q_k + Δt q̇_k + ½Δt² q̈*_k. The update is the exact solution of q̈ = constant over one period, so the simulation adds no integration error, and the only error left is the sample-and-hold of q̈*, which is O(Δt).
14. The run is meant to check the β channel while the arm moves along the path at ν_d from the first instant. Because ȳ̇ = A q̇, the solution of A(q₀)q̇₀ = (ν_d, 0, ..., 0) gives exactly η̇ = ν_d (no speed error) with ξ̇ = β̇ = 0. A moving start with a self-motion component would give β̇(0) ≠ 0, which the designed response β₀(1 + 4t)e^(−4t) does not assume. Starting at rest would also keep β̇(0) = 0, but the arm would first accelerate along the path (k_t = 5, time constant 0.2 s), so the fastest part of the β transient would happen before the motion the run is meant to test.
15. With the initializer list unchanged, its order would no longer match the declaration order, so GCC would warn (`-Wreorder`, an error under the CI's `-Werror`). If the list were reordered too, nothing would warn: the compiler does not check what `start` reads. At run time `start` would call `lift_.eval` on a lift whose constructor has not run, which is undefined behaviour (garbage or a crash). Members are built in declaration order, so the declaration order must be the dependency order.
