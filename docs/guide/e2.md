## The apps and the plot scripts

Both plain apps have the same shape: build the example offline, call `simulate` twice, print every number beside its expected value, write one CSV per run, and return 0, 1 or 2. The plot scripts are their mirror image: they read those CSV files by column name and draw the paper's figures.

### The skeleton of an app

Here is `main` of `rigid_body_sim`; `panda_sim` and `panda_mujoco` differ only in what they run and print.

```cpp
// apps/rigid_body_sim.cpp:58-68, 75-87
int main(int argc, char** argv)
{
    const std::filesystem::path dir = argc > 1 ? argv[1] : "out/";
    try {
        std::filesystem::create_directories(dir);

        const RigidBodyExample example;  // builds the tube (offline)
        std::printf("Rigid-body example: tumbling circle, r = 1 m, W = I, L = %.8f\n", example.tube().length());

        const RigidBodyRun pose = simulate(example, RigidBodyExample::Reference::Position);
        const RigidBodyRun velocity = simulate(example, RigidBodyExample::Reference::Velocity);
// ...
        const std::filesystem::path poseFile = dir / "rigid_body_pose.csv";
        const std::filesystem::path velocityFile = dir / "rigid_body_velocity.csv";
        if (!writeCsv(poseFile, pose) || !writeCsv(velocityFile, velocity)) {
            std::cerr << "error: cannot write the logs to " << dir << "\n";
            return 1;
        }
        std::printf("wrote %s and %s\n", poseFile.string().c_str(), velocityFile.string().c_str());
        return pose.ok && velocity.ok ? 0 : 2;
    } catch (const std::exception& e) {
        std::cerr << "error: " << e.what() << "\n";
        return 1;
    }
}
```

The C++ in these lines, one mechanism at a time:

- `int main(int argc, char** argv)`. The operating system passes the command-line words as C strings: `argv[0]` is the program name, `argv[1]` the first argument, and `argc` counts them. So `argc > 1` means "an argument was given".
- `std::filesystem::path` (C++17, header `<filesystem>`) is a type for file names. `dir / "rigid_body_pose.csv"` joins two parts with the right separator; you never glue strings with `"/"` by hand. The conditional `argc > 1 ? argv[1] : "out/"` has a C string on both sides, and the result is converted to a `path`.
- A relative path such as `out/` is relative to the directory you run the program from, not to the binary. `./build-rel/rigid_body_sim` started in the project root writes `out/`; `tools/ci.sh` passes `build-ci-release/out` so that `out/` is not touched.
- `std::filesystem::create_directories(dir)` creates every missing level and does nothing if the directory exists. It throws `std::filesystem::filesystem_error` if it cannot.
- `try { ... } catch (const std::exception& e)`. Every standard exception (`std::invalid_argument` from `stepCount`, `std::runtime_error` from a failed lift, `filesystem_error`) derives from `std::exception`, so one handler catches them all. Catching by `const&` avoids copying and keeps the real type's `what()` message. Without the `try`, an uncaught exception calls `std::terminate`, which aborts the process after a terse "terminate called after throwing ..." line; the shell then reports exit code 134 (SIGABRT) instead of 1.
- `const RigidBodyExample example;` builds the tube offline. `const` means nothing after this line may change it, which is also what `simulate` promises by taking it as `const RigidBodyExample&`.
- `RigidBodyExample::Reference::Position` names a value of an `enum class`. A scoped enum's values must be written with the enum's name, and they do not convert to `int` silently.
- `std::cerr` is the error stream. Error messages go there and summaries to standard output, so `app > log` still shows errors on the terminal.

The CSV writer shows how every log in this project is written:

```cpp
// apps/rigid_body_sim.cpp:20-37
    bool writeCsv(const std::filesystem::path& file, const RigidBodyRun& run)
    {
        std::ofstream f(file);
        if (!f)
            return false;
        f << "t,eta,eta_dot,ref,e_tan,xi1,xi2,xi3,xi4,xi5,xi_norm,xi_design,u1,u2,u3,u4,u5,u6\n";
        f.precision(10);
        for (const RigidBodyLogRow& r : run.log) {
            f << r.t << ',' << r.eta << ',' << r.etaDot << ',' << r.ref << ',' << r.eTan;
            for (int i = 0; i < 5; ++i)
                f << ',' << r.xi[i];
            f << ',' << r.xiNorm << ',' << r.xiDesign;
            for (int i = 0; i < 6; ++i)
                f << ',' << r.u[i];
            f << '\n';
        }
        return static_cast<bool>(f);
    }
```

- `std::ofstream f(file)` opens the file for writing and empties it. `if (!f)` is true when the open failed (no permission, missing directory); the function then returns `false` and `main` exits with 1.
- `f.precision(10)` sets 10 significant digits (not 10 decimals) for every later `double`. Ten digits are enough for the plots and for the 1e-8 cross-check in `plot_panda.py`.
- `const RigidBodyLogRow& r : run.log` loops over the log by reference. Without the `&`, each row, with its Eigen vectors ξ and u, would be copied once per iteration.
- `static_cast<bool>(f)` asks whether any write failed. One subtlety: the stream is flushed when `f` is destroyed after the `return`, and an error during that last flush is not seen. `panda_mujoco` writes with C stdio and checks the result of `std::fclose`, which covers that last flush too (see the MuJoCo section).

Columns: `t, eta, eta_dot, ref, e_tan, xi1..xi5, xi_norm, xi_design, u1..u6`. Here `ref` is η_d for the pose reference and ν_d for the velocity reference, `e_tan` is e_η or e_v, and `u = (τ, f)` is the body wrench held over the period. `xi_design` is |ξ₀|(1 + 4t)e^{−4t}.

`printSummary` (`apps/rigid_body_sim.cpp:40-54`) is plain `std::printf`: `%.3e` prints scientific notation with 3 decimals, `%zu` is the format for a `std::size_t` such as `run.log.size()`, and `run.ok ? "" : "  FAILED"` appends a flag only when the run failed. The exit code is `pose.ok && velocity.ok ? 0 : 2` (`apps/rigid_body_sim.cpp:82`): the app does not judge the numbers, the tests do (`tests/test_rigid_body_example.cpp`).

The CSV writer adds two loops worth knowing:

```cpp
// apps/panda_sim.cpp:27-49
    bool writeCsv(const std::filesystem::path& file, const PandaRun& run)
    {
        std::ofstream f(file);
        if (!f)
            return false;
        f << "t,eta,eta_dot,ref,e_tan,xi1,xi2,xi3,xi4,xi5,xi_norm,xi_design,beta,beta_design";
        for (const char* name : {"q", "qd", "qdd"})
            for (int i = 1; i <= 7; ++i)
                f << ',' << name << i;
        f << ",sigma_min,joint_margin,newton\n";
        f.precision(10);
        for (const PandaLogRow& r : run.log) {
            f << r.t << ',' << r.eta << ',' << r.etaDot << ',' << r.ref << ',' << r.eTan;
            for (int i = 0; i < 5; ++i)
                f << ',' << r.xi[i];
            f << ',' << r.xiNorm << ',' << r.xiDesign << ',' << r.beta << ',' << r.betaDesign;
            for (const Vec7* v : {&r.q, &r.qd, &r.qdd})
                for (int i = 0; i < 7; ++i)
                    f << ',' << (*v)[i];
            f << ',' << r.sigmaMin << ',' << r.jointMargin << ',' << r.iterations << '\n';
        }
        return static_cast<bool>(f);
    }
```

- `for (const char* name : {"q", "qd", "qdd"})`. A braced list in a range-for is a `std::initializer_list<const char*>`. Combined with the inner loop it writes the 21 column names `q1..q7, qd1..qd7, qdd1..qdd7`, numbered from 1 as on the robot, while the code indexes from 0.
- `for (const Vec7* v : {&r.q, &r.qd, &r.qdd})`. This list holds pointers, so no `Vec7` is copied; `(*v)[i]` first follows the pointer, then indexes. A list `{r.q, r.qd, r.qdd}` would copy three vectors per row, 20001 times.

Columns: `t, eta, eta_dot, ref, e_tan, xi1..xi5, xi_norm, xi_design, beta, beta_design, q1..q7, qd1..qd7, qdd1..qdd7, sigma_min, joint_margin, newton`. Here `ref` is ν_d, `e_tan` is e_v = η̇ − ν_d, and `newton` is the number of Newton updates of the projection at q.

The summary helpers use one C++ idiom worth copying, an aggregate with default member initializers:

```cpp
// apps/panda_sim.cpp:76-81
    struct ArmExpected {
        const char* margin = "";
        const char* sigma = "";
        const char* velocity = "";
        const char* acceleration = "";
    };
```

`printArm(paper, {"[0.3592 rad, joint 4]", "[0.0474]", "[26 %]", "[49 % ...]"})` fills the four fields in declaration order. `printArm(self, {})` leaves all four at `""`. `endLine` (`apps/panda_sim.cpp:68-73`) prints the expected string only when `expected[0] != '\0'`, that is, when it is not empty; the brackets are part of the string. The self-motion run has no design-doc values for these lines, so they end without one (only the Newton line always ends with "[1]").

`printHeader` (`apps/panda_sim.cpp:58-65`) prints the run's row count and last t, and the failure time if a step failed. `valid` (`apps/panda_sim.cpp:53-56`) is `run.ok && run.minJointMargin >= 0.0`. The joint-acceleration plant has no joint limits, so a run could leave the joint range and still be `ok`; the exit code 2 catches that.

### apps/panda_limits.hpp

`panda_limits.hpp` writes the joint limits of `PandaArm` as `panda_limits.csv`, one row per joint numbered from 1, so that the plot scripts need no copy of them:

```cpp
// apps/panda_limits.hpp:13-26
    inline bool writePandaLimits(const std::filesystem::path& file)
    {
        std::ofstream f(file);
        if (!f)
            return false;
        const Vec7 qMin = PandaArm::qMin(), qMax = PandaArm::qMax();
        const Vec7 dqMax = PandaArm::dqMax(), ddqMax = PandaArm::ddqMax(), tauMax = PandaArm::tauMax();
        f << "joint,q_min,q_max,qd_max,qdd_max,tau_max\n";
        f.precision(10);  // as the logs; the limits have at most 5 significant digits, so they are read back exactly
        for (int i = 0; i < 7; ++i)
            f << i + 1 << ',' << qMin[i] << ',' << qMax[i] << ',' << dqMax[i] << ',' << ddqMax[i] << ',' << tauMax[i]
              << '\n';
        return static_cast<bool>(f);
    }
```

- `inline` on a function defined in a header. Every `.cpp` that includes the header gets its own copy of the definition. Without `inline`, two such `.cpp` files in one program would give the linker two definitions and it would stop with "multiple definition". `inline` tells it they are the same function (the one-definition rule). Each app here has one `.cpp`, so it is a safety habit, not a fix.
- `#pragma once` at the top keeps a header from being included twice in one `.cpp`.
- `PandaArm::qMin()` and friends are functions, not `static Vec7` members (`include/se3pf/panda.hpp:37-44`). A static Eigen object is built at program start in an unspecified order across files, so another file's static could read it before it is set.
- `f.precision(10)` with limits of at most 5 significant digits (−2.8973, 2.175, 87) means the scripts read back exactly the values the C++ code used.

### The plot scripts: what they share

All three plot scripts follow one pattern:

1. `matplotlib.use("Agg")` comes before `import matplotlib.pyplot`. Agg draws into image files and never opens a window, so a script behaves the same on a desktop, over SSH and in CI. The backend is chosen before `pyplot` is imported; the `# noqa: E402` tells the linter that the late import is deliberate.
2. `ROOT` is the project root computed from the script's own path, so the default directory is `<root>/out` wherever you start the script.
3. The data is loaded and its columns are checked by name.
4. A 3 × 1 or 3 × 2 grid of panels is drawn with one fixed palette: five colorblind-checked series colors, near-black ink (`INK`) for the measured output of a single run, and gray dashes for designed responses and references. `plot_mujoco.py` gives each run its own series color instead.
5. Both a PNG (for the screen) and a PDF (for the paper) are written next to the logs.

Two loaders exist. `plot_rigid_body.py` and `plot_panda.py` use numpy's structured arrays:

```bash
# tools/plot_panda.py:57-62
def load(path):
    data = np.genfromtxt(path, delimiter=",", names=True)
    missing = [c for c in COLUMNS if c not in data.dtype.names]
    if missing:
        sys.exit(f"{path}: missing columns {missing}; rerun panda_sim")
    return data
```

`names=True` takes the header line as field names, so `data["xi_norm"]` is the column called `xi_norm`. `COLUMNS` (`tools/plot_panda.py:51-54`) repeats the header that `panda_sim` writes; a log from an older build stops the script with a clear message instead of a wrong figure.

`plot_mujoco.py` (and `render_mujoco.py`, `view_mujoco.py`) read the header line themselves and build a dictionary:

```bash
# tools/plot_mujoco.py:66-73
def load(directory, run):
    path = os.path.join(directory, f"mujoco_{run}.csv")
    if not os.path.exists(path):
        sys.exit(f"{path} not found; run  ./build-rel/panda_mujoco {directory}  first")
    with open(path) as f:
        names = f.readline().strip().split(",")
    data = np.loadtxt(path, delimiter=",", skiprows=1, ndmin=2)
    return {name: data[:, i] for i, name in enumerate(names)}
```

`np.loadtxt(..., skiprows=1)` reads the numbers below the header, `ndmin=2` keeps a 2-D array even for a one-row file, and the dictionary maps each name to its column. The result is used exactly like the structured array: `r["tau_rate_cmd"]`.

The limits file is checked too. `load_limits` (`tools/plot_panda.py:65-70`) and `load_tau_max` (`tools/plot_mujoco.py:54-63`) stop unless it has exactly the rows of joints 1 to 7. `plot_panda.py` also checks that the limits file belongs to the logs:

```bash
# tools/plot_panda.py:97-106
def joint_margins(data, q_min, q_max, name):
    """Distance of each joint to its nearer limit, shape (rows, 7). Its row minimum must be the log's joint_margin
    column (PandaArm::jointMargin): if the limits file and the log came from different builds, stop."""
    q = joints(data, "q")
    margins = np.minimum(q - q_min, q_max - q)
    err = np.max(np.abs(np.min(margins, axis=1) - data["joint_margin"]))
    if err > 1e-8:  # the logs have 10 significant digits
        sys.exit(f"{name}: panda_limits.csv does not reproduce the joint_margin column (off by {err:.1e} rad); "
                 "rerun panda_sim")
    return margins
```

It recomputes each joint's distance to its nearer limit from `q1..q7` and the limits file, takes the row minimum, and compares it with the `joint_margin` column that `PandaArm::jointMargin` wrote. The tolerance 1e-8 sits above the 10-significant-digit rounding of the logs. A limits file from another build stops the script.
