## Controller<System>, line by line

This section walks through `include/se3pf/controller.hpp` from top to bottom: the five free-standing helpers first (`Gains`, `TangentialReference`, `quinticRamp`, `wrapSymmetric`, `stepCount`), then the class, then `outputs` (eq:A) and `step` (Algorithm 1) in the order they execute.

### Gains

`Gains` is a plain struct of seven numbers with the paper's defaults written into the declaration:

```cpp
// include/se3pf/controller.hpp:13-31
    // Gains of the controller (Section V, Feedback linearization). The defaults are the paper's: transverse and
    // redundancy poles at -lambda with lambda = 4 rad/s (K_p = lambda^2 I = 16 I, K_d = 2 lambda I = 8 I), k_t = 5
    // for a velocity reference, and k_p = 9, k_d = 6 for a pose reference (tangential poles at -3).
    struct Gains {
        double Kp = 16.0, Kd = 8.0;          // transverse, eq:transverse: K_p = Kp I, K_d = Kd I
        double kt = 5.0;                     // tangential velocity, eq:tan-vel
        double kpEta = 9.0, kdEta = 6.0;     // tangential position, eq:tan-pos
        double KpBeta = 16.0, KdBeta = 8.0;  // redundancy (n = 7 only), eq:beta-law

        // Transverse and redundancy poles at -lambda (critically damped): Kp = KpBeta = lambda^2, Kd = KdBeta =
        // 2 lambda. The tangential gains keep their defaults.
        static Gains fromLambda(double lambda)
        {
            Gains g;
            g.Kp = g.KpBeta = lambda * lambda;
            g.Kd = g.KdBeta = 2.0 * lambda;
            return g;
        }
    };
```

| Field | Paper | Law | Default | Closed-loop poles |
| --- | --- | --- | --- | --- |
| `Kp`, `Kd` | K_p = Kp I, K_d = Kd I | eq:transverse, ξ̈ = −K_pξ − K_dξ̇ | 16, 8 | s² + 8s + 16 = (s + 4)²: double pole at −4 |
| `kt` | k_t | eq:tan-vel, ė_v = −k_t e_v | 5 | −5 |
| `kpEta`, `kdEta` | k_p, k_d | eq:tan-pos, ë_η + k_d ė_η + k_p e_η = 0 | 9, 6 | (s + 3)²: double pole at −3 |
| `KpBeta`, `KdBeta` | K_p,β, K_d,β | eq:beta-law, β̈ = −K_p,β β − K_d,β β̇ | 16, 8 | (s + 4)² |

- `double Kp = 16.0, Kd = 8.0;` are default member initializers (C++11): every `Gains g;` starts with the paper's values, with no constructor to write.
- `fromLambda` is a `static` member function: you call it on the type, `Gains::fromLambda(4.0)`, without an object. It sets s² + K_d s + K_p = (s + λ)², the critically damped choice: K_p = λ², K_d = 2λ. Critical damping gives the fastest decay without oscillation, and the closed form |ξ(t)| = |ξ₀|(1 + λt)e^{−λt} from rest that the simulations compare against.
- `fromLambda` sets the transverse and redundancy gains together and leaves the tangential ones at their defaults; the Panda example then sets `KpBeta`, `KdBeta` and `kt` again explicitly (`src/panda_example.cpp:56-63`).
- The controller uses only the gains of the selected tangential mode: `kt` for a velocity reference, `kpEta` and `kdEta` for a position reference. `KpBeta` and `KdBeta` are read only when n = 7.
- Nothing validates gains: `fromLambda(-1.0)` returns K_d = −2, an unstable law, and the controller's constructor accepts it. Gains are trusted configuration, chosen offline.

### TangentialReference

`TangentialReference` says what η should do: follow a speed ν_d(t, η) (eq:tan-vel) or a position η_d(t) (eq:tan-pos). It stores the reference as a function, because the controller must evaluate it at the current t and η in every step:

```cpp
// include/se3pf/controller.hpp:33-48
    // What the tangential output eta should do (Section V): follow a velocity nu_d(t, eta) along the path
    // (eq:tan-vel), or a position eta_d(t) on it (eq:tan-pos). eta_d is real-valued (it may run past L); the
    // controller wraps the error eta - eta_d into (-L/2, L/2]. Only the function of the selected mode is used.
    // Calling a std::function does not allocate, so the 1 kHz step may call it; building one may allocate, so do
    // it before the run.
    struct TangentialReference {
        enum class Mode { Velocity, Position };

        // nu = nu_d(t, eta) and its partial derivatives d nu_d / dt and d nu_d / d eta
        using VelocityFn = std::function<void(double t, double eta, double& nu, double& dnuDt, double& dnuDeta)>;
        // etaD = eta_d(t) and its first two time derivatives
        using PositionFn = std::function<void(double t, double& etaD, double& detaD, double& ddetaD)>;

        Mode mode = Mode::Velocity;
        VelocityFn velocity;
        PositionFn position;
```

- `enum class Mode { Velocity, Position };` is a scoped enumeration: you must write `TangentialReference::Mode::Velocity`, and it does not convert silently to `int`. A plain `enum` would leak `Velocity` into the enclosing scope and compare equal to integers.
- `std::function<void(double t, double eta, double& nu, ...)>` is a type that can hold any callable with that signature: a lambda, a function pointer, a functor. The `using` lines give these long types short names.
- The function returns its three numbers through `double&` parameters: ν_d and both partial derivatives (velocity), or η_d, η̇_d and η̈_d (position). The controller needs all of them in eq:tan-vel and eq:tan-pos, and out-parameters cost nothing.
- Both members always exist; only the one of the selected `mode` is used.

The factories build a valid reference in one call:

```cpp
// include/se3pf/controller.hpp:50-64
        static TangentialReference fromVelocity(VelocityFn f)
        {
            TangentialReference r;
            r.mode = Mode::Velocity;
            r.velocity = std::move(f);
            return r;
        }

        static TangentialReference fromPosition(PositionFn f)
        {
            TangentialReference r;
            r.mode = Mode::Position;
            r.position = std::move(f);
            return r;
        }
```

- `r.velocity = std::move(f);` moves the callable instead of copying it. A `std::function` that holds a large capture owns heap memory, and a move hands that memory over without a new allocation.
- Taking `VelocityFn f` by value and then moving is the usual C++ idiom for "sink" parameters: the argument is built (or moved) into `f` once, the member is moved from `f`, and no second copy is made.

```cpp
// include/se3pf/controller.hpp:66-81
        // nu_d = nu, a constant speed along the path
        static TangentialReference constantVelocity(double nu)
        {
            return fromVelocity([nu](double, double, double& v, double& dvDt, double& dvDeta) {
                v = nu;
                dvDt = 0.0;
                dvDeta = 0.0;
            });
        }

        // True if the function of the selected mode is set.
        bool valid() const
        {
            return mode == Mode::Velocity ? static_cast<bool>(velocity) : static_cast<bool>(position);
        }
    };
```

- `[nu](double, double, double& v, ...)` is a lambda that captures `nu` by value: the lambda object stores its own copy of the double, so it stays valid after `constantVelocity` returns. Unnamed parameters (`double, double`) are the ignored t and η.
- `static_cast<bool>(velocity)` asks whether the `std::function` holds a callable. Its conversion to `bool` is `explicit`, so a plain `return velocity;` from a `bool` function would not compile; inside an `if` it converts automatically (as in `include/se3pf/controller.hpp:275`).
- Calling an empty `std::function` throws `std::bad_function_call`. `valid()` lets the constructor reject such a reference offline, so the online step never calls an empty one.

Allocation, measured with a counting `operator new` in a scratch program (GCC 11.4, libstdc++): `constantVelocity(0.5)` allocates nothing, because a capture of one `double` fits in `std::function`'s internal 16-byte buffer (two doubles still fit). A lambda capturing three doubles (24 bytes) allocates once, and copying that reference allocates again; moving it allocates nothing. Two thousand calls of either allocate nothing. Hence the header's rule (`include/se3pf/controller.hpp:36-37`): build references before the run, call them freely inside it.

### quinticRamp

The quintic smoothstep scales μ at the start of a hardware run, so the first command at rest is exactly zero:

```cpp
// include/se3pf/controller.hpp:83-93
    // Quintic smoothstep r(x) = 10 x^3 - 15 x^4 + 6 x^5 for x in [0, 1], clamped to 0 below and 1 above. r and its
    // first two derivatives vanish at x = 0, and r' and r'' vanish at x = 1, so a command multiplied by r(t / T)
    // starts at exactly zero and reaches its full value smoothly (Rules for the 1 kHz loop: hardware only).
    inline double quinticRamp(double x)
    {
        if (!(x > 0.0))  // also NaN: no command rather than a NaN command
            return 0.0;
        if (x >= 1.0)
            return 1.0;
        return x * x * x * (10.0 + x * (-15.0 + 6.0 * x));
    }
```

```latex
r(x) = 10x^3 - 15x^4 + 6x^5, \qquad
r'(x) = 30x^2(1-x)^2, \qquad
r''(x) = 60x(1-x)(1-2x).
```

- r, r′ and r″ vanish at x = 0, and r′, r″ vanish at x = 1. So the commanded acceleration, and with it the torque, starts from zero and joins the full law without a jump in its first two derivatives.
- `x * x * x * (10.0 + x * (-15.0 + 6.0 * x))` is Horner's form of the same polynomial: fewer multiplications, and less rounding than summing three powers.
- `if (!(x > 0.0)) return 0.0;` handles x ≤ 0 and NaN in one test (NaN makes every comparison false). A NaN time therefore gives "no command", never a NaN command.
- Values: r(0.1) = 0.00856, r(0.25) = 0.1035, r(0.5) = 0.5, r(0.75) = 0.8965. The symmetry r(x) + r(1 − x) = 1 is checked in the test at `tests/test_controller.cpp:368-369`.
- Why it exists: without the ramp, the paper's Panda start asks for 49 % of a joint's acceleration limit in the first command (49.4 % in `panda_sim`'s output), above the 30 % hardware margin. With a 1 s ramp the peak is 11.5 % (`docs/DESIGN.md:415`; `TICKETS.md:199` and `TICKETS.md:211`). The paper's own closed loop has no ramp (T = 0, the default).

### wrapSymmetric

`wrapSymmetric(x, L)` returns the representative of x mod L in (−L/2, L/2]: the shortest signed arc between two points of the circle R/LZ. The controller uses it for e_η = η − η_d:

```cpp
// include/se3pf/controller.hpp:95-104
    // x mod L as the representative in (-L/2, L/2]: the error e_eta of eq:tan-pos between two points of R/LZ.
    inline double wrapSymmetric(double x, double L)
    {
        double d = std::fmod(x, L);  // in (-L, L)
        if (d > 0.5 * L)
            d -= L;
        if (d <= -0.5 * L)
            d += L;
        return d;
    }
```

- `std::fmod(x, L)` keeps the sign of x: `fmod(-5.9, 2.0)` is −1.9, `fmod(6.3, 2.0)` is 0.3 (up to rounding). So `d` lies in (−L, L), and the two `if`s move it into (−L/2, L/2].
- The interval excludes −L/2 and includes L/2: `wrapSymmetric(1.0, 2.0)` is 1.0, and `wrapSymmetric(-1.0, 2.0)` is also 1.0. So every x has exactly one representative.
- Why wrap at all: η lives in [0, L) but η_d is real-valued and may run past L (the test reference is past L at t = 40: η_d(40) = 13.15 > L = 10.88). Without wrapping, a reference one loop ahead would produce e_η ≈ −L and drive the body a full loop forward instead of not at all.
- Compare `Tube::wrap` (`src/tube.cpp:213-221`), which maps into [0, L) for η itself and needs an extra check because −1e-17 + L rounds to L.
- No failure path: NaN in gives NaN out, and L is the tube length, which is positive.

### stepCount

`stepCount` is a shared helper of the three simulators (rigid body, Panda, MuJoCo): how many control periods fit in a run of length T.

```cpp
// include/se3pf/controller.hpp:106-119
    // Number of control periods of a simulated run of length T with period dt: the instants t_k = k dt <= T are
    // k = 0, ..., stepCount(T, dt, maxSteps), so a run has stepCount + 1 rows (20001 for T = 20 s, dt = 1 ms). The
    // 1e-9 allows for rounding, so that t = T is included when T is a multiple of dt. Shared by the simulators
    // (rigid body, Panda, MuJoCo). Offline: throws std::invalid_argument unless T and dt are finite, T >= 0, dt > 0
    // and T / dt <= maxSteps (which also keeps the result in range of long, and turns a mistyped T or dt into an
    // error instead of a huge allocation).
    inline long stepCount(double T, double dt, long maxSteps)
    {
        if (!std::isfinite(T) || !std::isfinite(dt) || !(T >= 0.0) || !(dt > 0.0))
            throw std::invalid_argument("stepCount: need finite T >= 0 and dt > 0");
        if (!(T / dt <= static_cast<double>(maxSteps)))  // also T / dt = inf for a tiny dt
            throw std::invalid_argument("stepCount: T / dt exceeds the step limit of the run");
        return static_cast<long>(std::floor(T / dt + 1e-9));
    }
```

- The instants are t_k = k Δt for k = 0, ..., `stepCount`, so a run has `stepCount + 1` log rows: 10001 for the rigid body (T = 20 s, Δt = 2 ms).
- The `1e-9` handles rounding in T/Δt. `0.3 / 0.1` is 2.9999999999999996 in double precision, so `floor` alone would give 2 and drop the last instant t = 0.3. With Δt = 1e-3, the first k for which `floor(k*dt / dt)` falls below k is k = 2001 (k·Δt/Δt = 2000.9999999999998). Adding 1e-9 fixes these cases and is far too small to add a step when T is not a multiple of Δt (the test at `tests/test_controller.cpp:405` gets 66 for T = 20, Δt = 0.3).
- `!(T / dt <= static_cast<double>(maxSteps))` rejects a run that is too long, and also T/Δt = inf (with Δt = 1e-320 the quotient overflows to infinity). It runs before any allocation: a mistyped T of 1e15 s at Δt = 2 ms would otherwise ask to reserve 5e17 log rows.
- `static_cast<long>(...)` converts the floored double to an integer. Casting inf or a value beyond the range of `long` would be undefined behaviour, which the checks above rule out.
- Failure: throws `std::invalid_argument`. This is offline code, called once before a run.

### The class: compile-time sizes and nested structs

```cpp
// include/se3pf/controller.hpp:136-143
    template <class System>
    class Controller {
        public:
            static constexpr int n = System::kDof;
            static_assert(n == 6 || n == 7, "Controller: n = 6 (r = 0) or n = 7 (r = 1) generalized velocities");
            using Config = typename System::Config;
            using VecN = Vec<n>;
            using MatN = Mat<n, n>;
```

- `template <class System> class Controller` defines a family of classes; `Controller<RigidBody>` and `Controller<PandaArm>` are two separate classes generated by the compiler.
- `static constexpr int n = System::kDof;` copies n into the class as a compile-time constant. Every size below depends on it.
- `static_assert(n == 6 || n == 7, ...)` stops compilation with that message for any other n. The controller supports r = 0 (n = 6) and r = 1 (n = 7) redundant directions; a general r would need a β with r components.
- `using Config = typename System::Config;` needs `typename`: inside a template, the compiler cannot know whether `System::Config` names a type or a static value until `System` is known, and assumes "value" unless told otherwise.
- `VecN` and `MatN` are the fixed-size `Vec<n>` and `Mat<n, n>`.

```cpp
// include/se3pf/controller.hpp:145-166
            // Outputs at one configuration (eq:A)
            struct OutputState {
                double eta = 0.0;          // tangential output, in [0, L)
                Vec5 xi = Vec5::Zero();    // transverse output
                double beta = 0.0;         // redundancy output (n = 7 only)
                MatN A = MatN::Zero();     // ybar_dot = A qdot; rows (eta, xi_1..xi_5[, beta])
                int iterations = 0;        // Newton updates of the projection
            };

            // What one step saw and did, for logs and tests
            struct Status {
                double t = 0.0;
                double eta = 0.0, etaDot = 0.0;
                double ref = 0.0;          // nu_d(t, eta) (velocity reference) or eta_d(t) (position reference)
                double eTan = 0.0;         // e_v = eta_dot - nu_d, or e_eta = eta - eta_d wrapped into (-L/2, L/2]
                Vec5 xi = Vec5::Zero(), xiDot = Vec5::Zero();
                double beta = 0.0, betaDot = 0.0;  // n = 7 only
                double ramp = 1.0;         // the factor r(t / T) on mu (1 when the ramp is off)
                double sigmaMin = 0.0;     // smallest singular value of A (Proposition 2: positive near the path)
                int iterations = 0;        // Newton updates of the projection at q
                bool ok = false;
            };
```

- Nested structs: `Controller<RigidBody>::OutputState` and `Controller<PandaArm>::OutputState` are different types, with a 6 × 6 or a 7 × 7 `A`. Their sizes follow from `System` automatically.
- Every member has a default initializer (`= 0.0`, `= Vec5::Zero()`, `= MatN::Zero()`). Eigen does not zero its matrices, so without these an `OutputState o;` would hold garbage until `outputs` writes it.
- `A` holds the rows in the order of ȳ: row 0 is dη, rows 1 to 5 are dξ, row 6 (n = 7) is dβ.
- `Status` is what one step reports, for logs and tests. `ok` starts `false` and `ramp` starts at 1.0, so a default `Status` reads "failed, no ramp".
- `iterations` counts Newton updates of the projection at q (1 to 20, `src/tube.cpp:267`). In the rigid-body and Panda closed loops it is 1 in every cycle.

### Constructor and accessors

```cpp
// include/se3pf/controller.hpp:168-183
            // Throws std::invalid_argument if the reference has no function for its mode, or if the redundancy
            // output is null for n = 7 (an arm with a redundant joint needs beta) or set for n = 6 (no redundancy).
            Controller(const Tube& tube, const Gains& gains, TangentialReference reference,
                       const RedundancyOutput* redundancy = nullptr)
                : tube_(tube), gains_(gains), reference_(std::move(reference)), redundancy_(redundancy)
            {
                if (!reference_.valid())
                    throw std::invalid_argument("Controller: the tangential reference has no function for its mode");
                if (n == 7 && redundancy_ == nullptr)
                    throw std::invalid_argument("Controller: a redundant system (n = 7) needs a redundancy output");
                if (n == 6 && redundancy_ != nullptr)
                    throw std::invalid_argument("Controller: a system with n = 6 has no redundancy output");
            }
            // no temporary tube: the controller keeps a reference to it
            Controller(const Tube&& tube, const Gains& gains, TangentialReference reference,
                       const RedundancyOutput* redundancy = nullptr) = delete;
```

- The initializer list stores a reference to the tube, a copy of the gains, the moved reference and the redundancy pointer.
- `TangentialReference reference` is taken by value and moved into `reference_`, the same sink idiom as in the factories.
- The null-redundancy rules: n = 7 requires a `RedundancyOutput` (A would have no seventh row), and n = 6 forbids one (there is no β to put it in). Both are checked at construction, so the 1 kHz `step` never has to check them.
- `if (n == 7 && ...)` is a plain `if` with a compile-time-constant condition. That is fine here because the body compiles for both n; `if constexpr` is needed only when a branch would not compile for one of them.
- The second constructor takes `const Tube&&` and is `= delete`. An rvalue argument (a temporary `Tube`) binds better to `&&` than to `const&`, so overload resolution picks the deleted one and compilation fails. Without it, `Controller<RigidBody> c(Tube(path, W), ...)` would compile and leave `tube_` referring to a destroyed object. The test at `tests/test_controller.cpp:460-463` checks this with `STATIC_REQUIRE_FALSE(std::is_constructible_v<...>)`.
- Failure: throws `std::invalid_argument`, offline.

```cpp
// include/se3pf/controller.hpp:185-190
            const Tube& tube() const { return tube_; }
            const Gains& gains() const { return gains_; }
            const TangentialReference& reference() const { return reference_; }
            const RedundancyOutput* redundancy() const { return redundancy_; }
            double prediction() const { return etaHat_; }  // eta-hat, the start of the next projection
            double rampTime() const { return rampTime_; }
```

The accessors return `const` references or values; `prediction()` exposes η̂, the start of the next projection, which the tests check after each step.

```cpp
// include/se3pf/controller.hpp:330-337
        private:
            const Tube& tube_;
            Gains gains_;
            TangentialReference reference_;
            const RedundancyOutput* redundancy_;
            double etaHat_ = 0.0;     // prediction eta-hat (Algorithm 1)
            double rampTime_ = 0.0;   // T of the mu ramp; 0 = off
    };
```

The private members are exactly the controller's state: a reference to the tube (`const Tube&`), the gains, the reference, the redundancy pointer, η̂ and the ramp time. A reference member makes the class copy-constructible but not assignable (a reference cannot be re-seated), which is fine: nothing assigns controllers. `etaHat_ = 0.0` means the prediction is never uninitialized, even if you forget `reset`.

### setReference, setRampTime, reset

```cpp
// include/se3pf/controller.hpp:192-212
            // Offline: throws std::invalid_argument if the reference has no function for its mode.
            void setReference(TangentialReference reference)
            {
                if (!reference.valid())
                    throw std::invalid_argument("Controller: the tangential reference has no function for its mode");
                reference_ = std::move(reference);
            }

            // mu ramp for hardware-like runs: mu is multiplied by quinticRamp(t / T), so the first command at rest
            // is exactly zero. T = 0 turns it off (the default, and the paper's closed loop). Offline: throws
            // std::invalid_argument unless T is finite and T >= 0.
            void setRampTime(double T)
            {
                if (!(T >= 0.0) || !std::isfinite(T))
                    throw std::invalid_argument("Controller: the ramp time must be finite and >= 0");
                rampTime_ = T;
            }

            // Sets the prediction eta-hat = eta0 wrapped into [0, L). Call it before the first step of every run,
            // with eta0 near the closest point (Tube::globalProject, or s0 for a start pose Psi(s0, xi)).
            void reset(double eta0) { etaHat_ = tube_.wrap(eta0); }
```

- `setReference` switches the tangential law between runs, with the same validity check as the constructor.
- `setRampTime(T)`: `!(T >= 0.0)` rejects negative T and NaN in one test, and `!std::isfinite(T)` rejects infinity. T = 0 turns the ramp off.
- `reset(eta0)` sets η̂ to `tube_.wrap(eta0)`, in [0, L). Call it before every run. Newton's method converges to a root of φ_g near its start, and Proposition 1 makes that root the closest point only when the start is close. A stale η̂ from a previous run could make the first projection converge to the wrong point or fail.
- How close is close: from the rigid body's start pose, a guess of 0.1 (the true η) takes 1 Newton update, a guess of 0 takes 2, and a guess of 3.0 takes 7 (scratch run). A guess of 5.0 converges in 3 updates to η = 5.614, a root of φ_g that is not the closest point. For a start pose Ψ(s₀, ξ), η = s₀ exactly, which is why the examples call `reset(0.1)`.
- `reset` has no failure path. A NaN `eta0` makes η̂ NaN, and the next `step` returns false, because `Tube::projectionCondition` refuses a non-finite s (`src/tube.cpp:243-244`).

### outputs: ȳ and A at one configuration (eq:A)

`outputs(q, guess, out)` computes everything that depends only on q: η, ξ, β and the matrix A of eq:A,

```latex
A(q) = \begin{bmatrix} J_\Psi(\eta,\xi)^{-1} J_b(q) \\ d\beta(q) \end{bmatrix},
\qquad \dot{\bar y} = A(q)\,\dot q,
\qquad \bar y = (\eta, \xi, \beta).
```

For n = 6 the last block row is absent.

```cpp
// include/se3pf/controller.hpp:214-229
            // ybar and A at q (eq:A), with the projection started at guess. False if the pose has left the tube or
            // a value is not finite.
            bool outputs(const Config& q, double guess, OutputState& out) const
            {
                Mat<6, n> Jb = Mat<6, n>::Zero();
                const Pose g = System::output(q, &Jb);
                if (!tube_.outputs(g, guess, out.eta, out.xi, &out.iterations))
                    return false;

                // J_Psi^-1 J_b by one LU factorization of J_Psi; the inverse is never formed. Its rows are
                // d eta (row 0) and d xi (rows 1..5).
                const Mat6 JPsi = tube_.JPsi(out.eta, out.xi);
                const Mat<6, n> top = JPsi.partialPivLu().solve(Jb);
                if (!top.allFinite())
                    return false;
                out.A.template topRows<6>() = top;
```

1. `System::output(q, &Jb)` gives g = Π(q) and J_b. `Jb` is zeroed first so that a System that forgets to write it gives zeros, not garbage.
1. `tube_.outputs(g, guess, out.eta, out.xi, &out.iterations)` runs Newton's method on the projection condition φ_g(s) = ⟨e_g(s), ζ_γ(s)⟩_W from `guess`, stopping when |φ_g| < 1e-10, then sets ξ = N(η)ᵀ W e_g(η) (Proposition 1). It returns false if the pose has left the tube: Log_I fails (an attitude error of π), a value is not finite, |φ′| < 1e-12, or there is no convergence in 20 updates (`src/tube.cpp:241-297`).
1. `tube_.JPsi(out.eta, out.xi)` is the 6 × 6 body Jacobian of Ψ, columns (η, ξ₁, ..., ξ₅).
1. `JPsi.partialPivLu().solve(Jb)` computes J_Ψ⁻¹J_b without forming J_Ψ⁻¹. `partialPivLu()` factors J_Ψ = P⁻¹LU once (LU with row pivoting); `solve` then runs triangular solves for all n columns of J_b at once. That costs less than forming the inverse and multiplying, and rounds less. Partial pivoting is enough because J_Ψ is invertible inside the tube; it does not detect a singular matrix, which is why the result is checked.
1. `if (!top.allFinite()) return false;` catches inf or NaN from a singular J_Ψ or a NaN input.
1. `out.A.template topRows<6>() = top;` writes the first six rows of A. For n = 6 that is all of A; for the rigid body J_b = I, so A = J_Ψ⁻¹ (checked to 1e-12 at `tests/test_controller.cpp:498-500`). The keyword `template` is required because `out.A`'s type depends on n.

Why row 0 is dη: ȳ̇ = A q̇ and η̇ is its first component, so row 0 of J_Ψ⁻¹J_b is the gradient of η(q). The redundancy output needs it for eq:dbeta.

```cpp
// include/se3pf/controller.hpp:231-241
                // eq:A, last row: d beta, which needs d eta = row 0 of J_Psi^-1 J_b (eq:dbeta)
                if constexpr (n == 7) {
                    const Vec7 deta = top.row(0).transpose();
                    Vec7 dbeta = Vec7::Zero();
                    redundancy_->evaluate(q, out.eta, deta, out.beta, dbeta);
                    out.A.row(6) = dbeta.transpose();
                    if (!std::isfinite(out.beta) || !dbeta.allFinite())
                        return false;
                }
                return true;
            }
```

- `if constexpr (n == 7)` compiles this block only for the Panda. For n = 6 the block would not compile: line 233 makes a `Vec7` from a 6-entry row, line 235 passes the 4 × 4 pose `q` as a `Vec7`, and line 236 assigns a 7-entry row into a 6 × 6 A. With a plain `if`, Eigen stops the build at all three lines with `static assertion failed: YOU_MIXED_MATRICES_OF_DIFFERENT_SIZES` (reproduced with GCC 11.4). With `if constexpr` the discarded branch is never instantiated.
- `redundancy_->evaluate(q, out.eta, deta, out.beta, dbeta)` is the virtual call. It receives the projected η (not the guess) and dη, so β of Lemma 3 is evaluated at the right point of the lift. The test with `WavyCouplingOutput` exists to catch exactly a β evaluated at the guess or a wrong row passed as dη (`tests/test_controller.cpp:962-988`).
- `Vec7 dbeta = Vec7::Zero();` again protects against an implementation that leaves its output unwritten.
- `out.A.row(6) = dbeta.transpose();` stores the covector dβ as row 6.
- Failure: false if β or dβ is not finite. Writing row 6 before the check is harmless, because a caller must not use `out` after a false return.

What `outputs` returns on failure, summarized: false, with `out` partly written. It is `const`: it does not change η̂ or anything else in the controller, which is why `step` can call it three times with different configurations and guesses.

### step, part 1: outputs at q and ȳ̇

`step(q, dq, t, dt, qdd, st)` is one control cycle (Algorithm 1). It is not `const`: it updates η̂.

```cpp
// include/se3pf/controller.hpp:243-257
            // One control cycle (Algorithm 1) at time t with period dt: qdd receives qdd* = A^-1 (mu - Adot qdot).
            // False (and qdd unchanged) if the projection fails, A is nearly singular (sigma_min(A) < 1e-9) or a
            // result is not finite; a simulation then stops, the robot driver damps the arm to rest.
            bool step(const Config& q, const VecN& dq, double t, double dt, VecN& qdd, Status& st)
            {
                st = Status();
                st.t = t;

                // Steps 1-6 and the first part of step 7, all in outputs: g = Pi(q), eta by Newton's method from the
                // prediction, xi, J_Psi, beta (n = 7) and A. Then ybar_dot = A qdot = (eta_dot, xi_dot[, beta_dot]).
                OutputState out;
                if (!outputs(q, etaHat_, out))
                    return false;
                const VecN yDot = out.A * dq;
                const Vec5 xiDot = yDot.template segment<5>(1);
```

- `st = Status();` resets the status first. If any later check fails, the caller sees `st.ok == false` and the time `st.t`, never stale values from the previous cycle.
- `outputs(q, etaHat_, out)` starts Newton's method at the prediction η̂.
- `const VecN yDot = out.A * dq;` is ȳ̇ = A q̇: η̇ in `yDot[0]`, ξ̇ in entries 1 to 5, β̇ in entry 6 (n = 7). The type is written out instead of `auto`: with `auto`, Eigen would store an unevaluated product expression, not a vector (design doc, Eigen pitfalls).
- `yDot.template segment<5>(1)` is the 5-entry block starting at index 1, ξ̇.

### step, part 2: Ȧq̇ by a central difference

```cpp
// include/se3pf/controller.hpp:259-270
                // Step 7 (continued): Adot qdot = d/dh A(c(h)) qdot at h = 0 along the curve c(h) = retract(q, qdot,
                // h), by a central difference. Both projections start from the eta just found. At rest
                // Adot qdot = 0, and the two projections are skipped.
                VecN Adq = VecN::Zero();
                if (!(dq.array() == 0.0).all()) {
                    constexpr double h = 1e-5;
                    OutputState plus, minus;
                    if (!outputs(System::retract(q, dq, h), out.eta, plus)
                        || !outputs(System::retract(q, dq, -h), out.eta, minus))
                        return false;
                    Adq = ((plus.A - minus.A) * dq) / (2.0 * h);
                }
```

- `retract(q, dq, ±h)` gives two configurations on a curve with velocity q̇ (section "The System interface and RigidBody" shows why any such curve gives the same limit), and Ȧq̇ = (A(c(h)) − A(c(−h))) q̇ / 2h + O(h²).
- Why a finite difference at all: an analytic Ȧ would need the derivative of J_Ψ (second derivatives of Exp_I, and N″ of the frame spline) and of J_b (the Hessian of the forward kinematics). The difference needs only two more calls of `outputs`.
- Why central: a forward difference (A(c(h)) − A(q)) q̇ / h would reuse A(q) and save one projection, but its error is O(h). A scratch study at the rigid-body start pose g₀ with a body twist of norm 0.7 (‖Ȧq̇‖∞ = 0.23), against a sixth-order central difference with h = 2e-4 (itself accurate to about 7e-11), gives:

| h | central error | forward error |
| --- | --- | --- |
| 1e-3 | 4.4e-8 | 1.1e-4 |
| 1e-4 | 4.6e-10 | 1.1e-5 |
| 1e-5 | 2.1e-10 | 1.1e-6 |
| 1e-6 | 2.3e-9 | 1.1e-7 |
| 1e-7 | 3.7e-8 | 4.9e-8 |
| 1e-8 | 2.3e-7 | 6.7e-7 |

The central error falls as h² (a factor 100 from h = 1e-3 to 1e-4) until rounding takes over. Each computed A carries errors of about 1e-14 (A at g₀ changes by 8e-15 to 1.4e-14 when the projection starts from a different guess), and the difference divides them by 2h, so below about 1e-5 the error grows again as 1/h. The best forward result (about 5e-8, at h = 1e-7) is some 200 times worse than the central one at h = 1e-5. For the Panda at its paper start with q̇ drawn from N(0, 0.2²) per joint (‖Ȧq̇‖ = 0.015), the central error is 8.6e-12 at h = 1e-4, 1.0e-11 at 1e-5 and 3.4e-10 at 1e-6, and the best forward result is 2.3e-9: h = 1e-5 sits at or next to the bottom of both curves.
- `constexpr double h = 1e-5;` makes h a compile-time constant local to the function.
- "Both projections start from the eta just found": the curve moves η by only about h·η̇ (4e-6 in the study above), so `out.eta` is an excellent guess and one Newton update suffices. There is a second, subtler benefit. Newton's error after one update is quadratic in the start error, and the start errors for +h and −h are equal and opposite, so the two leftover errors are nearly equal: in the study above the residuals are |φ| = 2.1434e-13 and 2.1430e-13. A shared bias in η cancels in the difference A(c(h)) − A(c(−h)), which is divided by 2h = 2e-5 and would otherwise amplify it.
- `if (!(dq.array() == 0.0).all())`: `.array()` switches Eigen to coefficient-wise operations, `== 0.0` gives a boolean array, `.all()` is true when every entry is exactly zero. At rest Ȧq̇ = 0 exactly, and the two projections are skipped: the step at rest takes about 5.9 µs instead of 9.3 µs (rigid body; Panda 7.5 µs instead of 12.2 µs, scratch timing). Any nonzero entry, even 1e-300, runs the difference. A NaN entry is not equal to zero either, so the projections run and fail, and `step` returns false.
- `VecN Adq = VecN::Zero();` must be initialized: in the rest case nothing else writes it.
- A known limit: the frame spline N(s) is only C¹ (cubic Hermite), so N″ jumps at its 2000 grid nodes, and the derivative of A along the motion jumps with it. When the ±h stencil straddles a node, the difference returns a mix of the two one-sided values, an error up to about 1e-6 (comment at `tests/test_controller.cpp:183-185`). The closed loops absorb this; the tests that compare Ȧq̇ to 1e-7 put η in the middle of a grid interval.
- Failure: false if either projection fails, for example when c(±h) has left the tube.

### step, part 3: μ∥, the tangential law

```cpp
// include/se3pf/controller.hpp:272-290
                // Step 8: mu = (mu_par, mu_transverse[, mu_beta])
                double muPar = 0.0;
                if (reference_.mode == TangentialReference::Mode::Velocity) {
                    if (!reference_.velocity)
                        return false;
                    double nu = 0.0, dnuDt = 0.0, dnuDeta = 0.0;
                    reference_.velocity(t, out.eta, nu, dnuDt, dnuDeta);
                    st.ref = nu;
                    st.eTan = yDot[0] - nu;  // e_v
                    muPar = dnuDt + dnuDeta * yDot[0] - gains_.kt * st.eTan;  // eq:tan-vel
                } else {
                    if (!reference_.position)
                        return false;
                    double etaD = 0.0, detaD = 0.0, ddetaD = 0.0;
                    reference_.position(t, etaD, detaD, ddetaD);
                    st.ref = etaD;
                    st.eTan = wrapSymmetric(out.eta - etaD, tube_.length());  // e_eta in (-L/2, L/2]
                    muPar = ddetaD - gains_.kdEta * (yDot[0] - detaD) - gains_.kpEta * st.eTan;  // eq:tan-pos
                }
```

Velocity reference (eq:tan-vel). Define e_v = η̇ − ν_d(t, η) and ask for ė_v = −k_t e_v. Differentiating ν_d along the motion gives:

```latex
\dot e_v = \ddot\eta - \partial_t\nu_d - \partial_\eta\nu_d\,\dot\eta = -k_t\,e_v
\quad\Longrightarrow\quad
\mu_\parallel = \partial_t\nu_d(t,\eta) + \partial_\eta\nu_d(t,\eta)\,\dot\eta - k_t\,(\dot\eta - \nu_d(t,\eta)).
```

Position reference (eq:tan-pos). Define e_η = η − η_d(t) wrapped into (−L/2, L/2] and ask for ë_η + k_d ė_η + k_p e_η = 0:

```latex
\mu_\parallel = \ddot\eta_d(t) - k_d\,(\dot\eta - \dot\eta_d(t)) - k_p\,e_\eta, \qquad
e_\eta = \operatorname{wrap}_{(-L/2,\,L/2]}\bigl(\eta - \eta_d(t)\bigr).
```

- The reference is evaluated at the projected `out.eta`, not at the prediction.
- `if (!reference_.velocity) return false;` is a guard against calling an empty `std::function`, which would throw `std::bad_function_call`. The constructor and `setReference` already rule this out, so the check never fires in practice; it keeps "no exceptions in step" true by construction.
- `st.ref` and `st.eTan` are written here, but `st.ok` stays false until the end, so a failure later in the step still reports failure.
- Only the wrapped error is used; the derivative terms use η̇ − η̇_d, which needs no wrapping because rates live on the tangent line, not the circle.
- Sign check from the tests (`tests/test_controller.cpp:651-658`): at rest on the path 0.5 behind a constant η_d, e_η = −0.5 and μ∥ = −9(−0.5) = +4.5, so η accelerates forward. With η_d one loop behind (s + 0.5 − L) the wrap gives the same +4.5.

### step, part 4: μ⋔, μ_β and the ramp

```cpp
// include/se3pf/controller.hpp:292-300
                VecN mu = VecN::Zero();
                mu[0] = muPar;
                mu.template segment<5>(1) = -gains_.Kp * out.xi - gains_.Kd * xiDot;  // eq:transverse
                if constexpr (n == 7)
                    mu[6] = -gains_.KpBeta * out.beta - gains_.KdBeta * yDot[6];  // eq:beta-law

                // Optional ramp on mu only: at rest at t = 0, Adot qdot = 0 too, so the first command is zero.
                const double r = rampTime_ > 0.0 ? quinticRamp(t / rampTime_) : 1.0;
                mu *= r;
```

```latex
\mu_\pitchfork = -K_p\,\xi - K_d\,\dot\xi \quad\text{(eq:transverse)}, \qquad
\mu_\beta = -K_{p,\beta}\,\beta - K_{d,\beta}\,\dot\beta \quad\text{(eq:beta-law)}.
```

- `mu.template segment<5>(1) = ...` writes entries 1 to 5 at once. `-gains_.Kp * out.xi` multiplies the vector ξ by the scalar K_p: the paper's K_p I.
- `if constexpr (n == 7)` again, but here a plain `if` would also compile and do no harm: `mu[6]` and `yDot[6]` are run-time indexes, and the false condition means they never run for n = 6 (if they did, they would index past a 6-vector: an assert in Debug, undefined behaviour in Release). `if constexpr` removes the line from `Controller<RigidBody>` altogether and states the intent.
- The ramp multiplies μ only, not Ȧq̇. With q̈* = A⁻¹(rμ − Ȧq̇), the outputs get ȳ̈ = rμ exactly: the linearization stays exact and only the requested acceleration is scaled. Ramping Ȧq̇ too, q̈* = A⁻¹r(μ − Ȧq̇), would give ȳ̈ = rμ + (1 − r)Ȧq̇: an uncommanded acceleration during the ramp. At rest Ȧq̇ = 0, so at t = 0 the command is exactly zero (test at `tests/test_controller.cpp:714-717`).
- `rampTime_ > 0.0 ? quinticRamp(t / rampTime_) : 1.0` avoids dividing by T = 0 when the ramp is off.

### step, part 5: σ_min(A) and the solve

```cpp
// include/se3pf/controller.hpp:302-310
                // Step 9 (the controller's part of eq:fb): qdd* = A^-1 (mu - Adot qdot). The LU factorization does
                // not see rank loss (a nearly singular A gives huge but finite values), so check sigma_min first.
                const double sigmaMin = Eigen::JacobiSVD<MatN>(out.A).singularValues().minCoeff();
                if (!(sigmaMin >= 1e-9))  // also NaN
                    return false;
                const VecN result = out.A.partialPivLu().solve(mu - Adq);
                if (!result.allFinite())
                    return false;
                qdd = result;
```

- `Eigen::JacobiSVD<MatN>(out.A)` computes the singular value decomposition of the fixed-size A by Jacobi rotations; with no options, only the singular values (no U, V). `.singularValues().minCoeff()` is σ_min(A).
- Why σ_min and not the determinant: σ_min is the distance from A to the nearest singular matrix (in the 2-norm), which is exactly what "nearly singular" means and what Proposition 2 bounds. A determinant depends on scale: 0.1 I₇ has determinant 1e-7 yet is perfectly conditioned.
- Why check at all, when the LU solve follows: partial-pivot LU does not report rank loss. A nearly singular A gives huge but finite q̈*, which `allFinite` would accept. The test system `StuckBody` (`tests/test_controller.cpp:328-338`) has σ_min = 9.6e-13, its LU solve returns finite numbers, and the step must refuse it.
- Why 1e-9: it is an absolute "singular to working precision" threshold, seven to nine orders of magnitude below the values in practice. σ_min(A) stays in [0.876, 1.0] along the rigid-body runs, is 0.0474 at the Panda's paper start, and about 0.054 at its smallest along the Panda's lift (comment at `tests/test_controller.cpp:1079`). It guards the arithmetic, not the robot: the hardware margin is σ_min ≥ 1e-3 (`HardwareBounds::sigmaMin`, `include/se3pf/panda.hpp:62`), checked by the MuJoCo runs (`apps/panda_mujoco.cpp:219`).
- `!(sigmaMin >= 1e-9)` is true for NaN too.
- Cost: the SVD is the single most expensive operation in the step. Scratch timings on this machine: 4.0 µs for the 6 × 6 A in a 9.3 µs rigid-body step, 4.9 µs for the 7 × 7 A in a 12.2 µs Panda step; the LU solve takes 0.13 to 0.2 µs. The 1 kHz budget is 1000 µs.
- `out.A.partialPivLu().solve(mu - Adq)` is q̈* = A⁻¹(μ − Ȧq̇), again without forming A⁻¹.
- `qdd = result;` is the only write to `qdd`, after every check, so a false return leaves the caller's `qdd` untouched (test at `tests/test_controller.cpp:742-772`).

### step, part 6: the prediction and the status

```cpp
// include/se3pf/controller.hpp:312-328
                // Step 9 (end): the prediction for the next cycle, eta-hat = (eta + eta_dot dt) mod L
                etaHat_ = tube_.wrap(out.eta + yDot[0] * dt);

                st.eta = out.eta;
                st.etaDot = yDot[0];
                st.xi = out.xi;
                st.xiDot = xiDot;
                if constexpr (n == 7) {
                    st.beta = out.beta;
                    st.betaDot = yDot[6];
                }
                st.ramp = r;
                st.sigmaMin = sigmaMin;
                st.iterations = out.iterations;
                st.ok = true;
                return true;
            }
```

- η̂ ← (η + η̇Δt) mod L is a first-order prediction of where the closest point will be at the next sample. Along the 20 s rigid-body velocity run it is never more than 5.2e-6 from the next projected η, while the previous η is up to 1.4e-3 away. Restarting Newton from the previous η instead (scratch run) gives the same maximum deviation to seven digits but needs 2 updates in some cycles instead of 1.
- η̂ is updated only on success; after a failure the next step starts from the same prediction.
- The status is filled from values already computed; `st.ok = true` is the last write before `return true`.

### What step returns, case by case

| Situation | Return | `qdd` | `st` | η̂ |
| --- | --- | --- | --- | --- |
| Success | true | q̈* | all fields, `ok = true` | (η + η̇Δt) mod L |
| Projection at q fails (pose left the tube, NaN in q, NaN η̂) | false | unchanged | default, `t` set | unchanged |
| A projection for Ȧq̇ fails (c(±h) outside the tube, inf or NaN in q̇) | false | unchanged | default, `t` set | unchanged |
| J_Ψ⁻¹J_b, β or dβ not finite | false | unchanged | default, `t` set | unchanged |
| Reference function empty | false | unchanged | default, `t` set | unchanged |
| σ_min(A) < 1e-9 or NaN | false | unchanged | `t`, `ref`, `eTan` set, `ok = false` | unchanged |
| q̈* not finite (for example a reference that returns NaN) | false | unchanged | `t`, `ref`, `eTan` set, `ok = false` | unchanged |

A simulation stops at the first false (`src/rigid_body_example.cpp:96-100`); the robot driver will damp the arm to rest.
