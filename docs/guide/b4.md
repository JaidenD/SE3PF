## The tube-radius estimate

`estimateTubeRadius` finds the largest ε for which no sampled path point is closer than ε to any probe pose Ψ(s, εd), by doubling ε until the test fails and then bisecting. The result estimates the tube radius ε₀ of Theorem 1; the paper's starts must lie inside it.

### What the test checks

The test is Proposition 1(c) turned into a numerical check. The probe g = Ψ(s, εd), with d a unit vector of R⁵, sits at distance exactly ε from γ(s) along a normal geodesic. The reason: ‖N(s)εd‖_W = ε, and Log_I(Exp_I(e)) = e below rotation angle π.

If some other path point is closer to g than ε, then γ(s) is not the closest point of g. The tubular coordinates then break down at that ε.

So ε passes when, for every foot point s and direction d tried, no path sample is closer to Ψ(s, εd) than ε. The test passes for small ε and fails for large ε, and the estimate is the boundary.

### RadiusOptions

The options are a plain struct whose defaults are the paper's test. A caller changes only the fields it needs.

```cpp
// include/se3pf/tube.hpp:101-115
    // Options of the tube-radius estimate (Implementation, Tube radius). The defaults are the paper's test.
    struct RadiusOptions {
        int footPoints = 32;          // values of s, at the midpoints of 32 equal pieces of [0, L)
        int randomDirections = 6;     // unit directions d in R^5, in addition to +-e_1, ..., +-e_5
        unsigned seed = 1;            // of the random directions, so the estimate is reproducible
        int checkPoints = 1000;       // uniform samples of the path searched for a point closer than epsilon
        double relTol = 1e-7;         // "closer" means dist < epsilon (1 - relTol)
        double startFraction = 0.01;  // the doubling starts at epsilon = startFraction * L
        int bisections = 14;
    };

    // Estimate of the tube radius epsilon_0 of Theorem 1: epsilon passes if no sampled point of the path is closer
    // than epsilon to any pose Psi(s, epsilon d) (the test of Proposition 1(c)). Doubles epsilon until it fails,
    // then bisects; returns the largest passing epsilon. Offline, under a second in Release.
    double estimateTubeRadius(const Tube& tube, const RadiusOptions& options = {});
```

| Field | Default | Meaning | Why this value |
| --- | --- | --- | --- |
| `footPoints` | 32 | foot points s = L(i + 0.5)/32, the midpoints of 32 pieces | midpoints keep the feet off the sample grid: sample index 1000(2i + 1)/64 = 15.625(2i + 1) is never an integer |
| `randomDirections` | 6 | random unit d, in addition to the 10 directions ±e₁, …, ±e₅ | 16 directions in all, as the design doc specifies (`docs/DESIGN.md:230`) |
| `seed` | 1 | seed of `std::mt19937` for the random directions | the estimate is reproducible run to run |
| `checkPoints` | 1000 | uniform path samples searched for a closer point | spacing L/1000; computed once, outside the loop over ε |
| `relTol` | 1e-7 | "closer" means dist < ε(1 − 1e-7) | rounding in a distance (about 1e-15 relative) can never fail ε; only a real intrusion can |
| `startFraction` | 0.01 | the doubling starts at ε = 0.01 L | small enough to pass on any path tried |
| `bisections` | 14 | bisection steps after the doubling | brackets ε to 1/16384 of the last doubling interval |

The paper itself does not yet state these numbers; PAPER-1 asks it to state the directions and samples.

One portability note on `seed`. `std::mt19937` gives the same integers on every platform, but `std::normal_distribution` is implementation-defined: libstdc++ and libc++ turn those integers into different normal numbers. The coarse test therefore uses `randomDirections = 0`, so its reference values hold with any standard library.

### Setting up: directions, samples and λ_min

```cpp
// src/tube.cpp:387-406
    double estimateTubeRadius(const Tube& tube, const RadiusOptions& opt)
    {
        if (opt.footPoints < 1 || opt.checkPoints < 1 || opt.randomDirections < 0 || opt.bisections < 0
            || !(opt.startFraction > 0.0))
            throw std::invalid_argument("estimateTubeRadius: invalid options");

        // Directions: +-e_1, ..., +-e_5, then random unit vectors (normal entries, normalized; fixed seed).
        std::vector<Vec5> dirs;
        for (int i = 0; i < 5; ++i) {
            dirs.push_back(Vec5::Unit(i));
            dirs.push_back(-Vec5::Unit(i));
        }
        std::mt19937 rng(opt.seed);
        std::normal_distribution<double> normal(0.0, 1.0);
        for (int k = 0; k < opt.randomDirections; ++k) {
            Vec5 d = Vec5::Zero();
            for (int i = 0; i < 5; ++i)
                d[i] = normal(rng);
            dirs.push_back(d.normalized());
        }
```

```cpp
// src/tube.cpp:408-414
        // The path samples do not depend on epsilon: compute them once.
        std::vector<Pose> samples(opt.checkPoints);
        for (int k = 0; k < opt.checkPoints; ++k)
            samples[k] = tube.path().pose(tube.length() * k / opt.checkPoints);

        const SelfAdjointEigenSolver<Mat6> eigW(tube.metric().matrix(), EigenvaluesOnly);
        const double sqrtLambdaMin = std::sqrt(eigW.eigenvalues().minCoeff());
```

The options are validated first; `!(opt.startFraction > 0.0)` also rejects NaN. The directions are ±e₁, …, ±e₅ (indices 0 to 9 of `dirs`, in the order +e₁, −e₁, +e₂, …), then six normalized vectors of standard normal entries. A normalized Gaussian vector is uniformly distributed on the unit sphere S⁴, which is why normal entries are used rather than uniform ones.

The path samples do not depend on ε, so they are computed once and reused by all 20 calls of `radiusPasses`. `SelfAdjointEigenSolver<Mat6> eigW(W, EigenvaluesOnly)` computes the eigenvalues of W without eigenvectors; the smallest gives √λ_min = 0.1 for the Panda with ℓ = 0.1 m and 1 for W = I.

### The test for one ε: radiusPasses

```cpp
// src/tube.cpp:349-369
        // The test for one epsilon: false as soon as a sampled path point is closer than epsilon to some pose
        // Psi(s, epsilon d). That happens beyond a focal point of the normal geodesics (first seen right beside
        // the foot point s, hence the extra samples there), beyond the cut locus, or where distant parts of the
        // path come close.
        bool radiusPasses(const Tube& tube, double eps, const RadiusOptions& opt, const std::vector<Vec5>& dirs,
                          const std::vector<Pose>& samples, double sqrtLambdaMin)
        {
            const double L = tube.length();
            const double h = L / opt.checkPoints;  // spacing of the path samples
            const double limit = eps * (1.0 - opt.relTol);
            const Metric& W = tube.metric();

            // Most path points are far from g, and a lower bound rules them out: W >= lambda_min(W) I, so
            // dist_W >= sqrt(lambda_min) dist_I. Without it, a far point at a relative rotation angle of pi, where
            // Log_I fails and Metric::distance returns NaN, would count as closer. For the points the bound cannot
            // rule out, the distance itself decides, and a failed logarithm there counts as closer.
            auto closer = [&](const Pose& gp, const Pose& g) {
                if (sqrtLambdaMin * identityDistance(gp, g) >= limit)
                    return false;
                return !(W.distance(gp, g) >= limit);
            };
```

```cpp
// src/tube.cpp:371-384
            for (int i = 0; i < opt.footPoints; ++i) {
                const double s = L * (i + 0.5) / opt.footPoints;
                for (const Vec5& d : dirs) {
                    const Pose g = tube.Psi(s, eps * d);
                    for (const Pose& gp : samples)
                        if (closer(gp, g))
                            return false;
                    for (double off : {0.5, 0.25, 0.125})  // beside the foot point
                        if (closer(tube.path().pose(s + off * h), g) || closer(tube.path().pose(s - off * h), g))
                            return false;
                }
            }
            return true;
        }
```

The loops visit 32 foot points × 16 directions = 512 probes. Each probe is compared with the 1000 samples and with six extra points at s ± h/2, s ± h/4 and s ± h/8, where h = L/1000 is the sample spacing. The function returns `false` at the first point found closer, so a failing ε usually costs much less than the full 512 × 1006 = 515 072 comparisons.

`for (double off : {0.5, 0.25, 0.125})` is a range-for over a braced list: the compiler turns `{0.5, 0.25, 0.125}` into a `std::initializer_list<double>`, a small read-only array with no heap use.

The extra points beside the foot catch focal points. Beyond a focal point of the normal geodesics, the first path point to come closer than ε is right next to the foot, between two samples. The points at h/2, h/4 and h/8 resolve that.

For the three example paths they change nothing: with them removed, all three estimates are identical (measured). The radius of these paths is set by distant parts of the path coming close, not by curvature.

Where the test fails just above each estimate (at 1.001 times the estimate, against 20 000 samples):

| --- | --- | --- | --- |
| Rigid body | 1 | random direction 13, d = (−0.678, 0.132, 0.146, −0.402, 0.583), foot s = 9.012 | 0.488 L away |

### The lower-bound prefilter

The lambda `closer` first tries to rule a point out with a lower bound of the distance, and computes `Metric::distance` only for the points the bound cannot rule out. The bound is there for correctness, not speed: it costs about as much as the distance itself.

```cpp
// src/tube.cpp:338-347
    namespace {
        // dist_I(g1, g2) = |(log R, p)| with (R, p) = g1^-1 g2: the distance of the metric W = I (Example 1). It is
        // defined everywhere, also at a rotation angle of pi, where the geodesic is not unique but its length is.
        double identityDistance(const Pose& g1, const Pose& g2)
        {
            const Pose g = inverse(g1) * g2;
            const Vector3d w = logSO3(Matrix3d(g.block<3,3>(0,0)));
            const Vector3d p = g.block<3,1>(0,3);
            return std::sqrt(w.squaredNorm() + p.squaredNorm());
        }
```

The bound comes from W ≥ λ_min I, which means ‖x‖_W ≥ √λ_min ‖x‖ for every twist x.

For the product type, Log_I(g) = (log R, p) whatever w_R and w_p are, so dist_W and dist_I are norms of the same vector (log R, p) and dist_W ≥ √λ_min dist_I. `Metric` accepts only the product type (`src/metric.cpp:12-20`); for a general W the inequality would still hold, because every curve is at least √λ_min times as long in W as in I.

```latex
\mathrm{dist}_W(g_1, g_2) \;\ge\; \sqrt{\lambda_{\min}(W)}\;\mathrm{dist}_I(g_1, g_2),\qquad
\mathrm{dist}_I(g_1, g_2) = \bigl\|\bigl(\log R,\ p\bigr)\bigr\|,\quad (R, p) = g_1^{-1} g_2
```

`identityDistance` is defined everywhere, also at relative rotation angle π. `logSO3` has a branch for angles within 1e-4 of π that reads the axis from the symmetric part of R (`src/se3.cpp:56-65`); the geodesic is not unique there, but its length π is.

The bound is needed because `Metric::distance` returns NaN when the relative rotation angle is π: `Metric::Log` refuses tr R < −1 + 1e-12 (`src/metric.cpp:57`, `src/metric.cpp:83-89`).

The lambda counts a NaN as closer: `!(W.distance(gp, g) >= limit)` is `true` for NaN, since `NaN >= limit` is `false`. That is the conservative choice for a point that may really be close.

Without the bound, that rule wrecks the rigid-body estimate. Some far path samples sit within 1e-6 rad of a relative angle π from a probe, by coincidence:

| ε | NaN distances among 512 000 checks | Example |
| --- | --- | --- |
| 0.108828 (the start, 0.01 L) | 0 | none |
| 0.217656 (first doubling) | 4 | foot s = 3.2308, direction −e₂, sample s = 9.3919, tr R + 1 = 1.1e-16 |
| 0.148569 | 0 | none |
| 0.148600 | 2 | foot s = 1.1903, direction −e₃, sample s = 6.2250, angle π − 3.5e-7 |

So ε = 0.217656 fails on a NaN, and the bisection between 0.108828 and 0.217656 settles at 0.148569 instead of 1.926489. The estimate collapses by a factor of 13 because of four points out of half a million. Bisection assumes that passing is monotone in ε, and sporadic NaN failures break exactly that assumption.

With the bound, those far samples never reach `Metric::distance`. A relative angle of π gives dist_I ≥ π, so the bound rules them out whenever √λ_min π ≥ ε(1 − relTol). In all three tubes λ_min = w_R, so this covers every ε below the injectivity radius π√w_R (0.314 for the Panda with ℓ = 0.1 m, π for the others; `docs/DESIGN.md:134`).

Above it, an ε may fail on a NaN, which is right: the tube radius cannot exceed the injectivity radius.

Treating NaN as not closer would also give 1.926489 here (measured, with or without the bound), but it would accept an ε whenever the distance to a truly close point is undefined. The code keeps the conservative rule and removes the spurious cases with the bound.

### Doubling, then bisection

```cpp
// src/tube.cpp:416-431
        // Double epsilon from startFraction * L until the test fails, then bisect.
        double lo = 0.0, hi = opt.startFraction * tube.length();
        while (radiusPasses(tube, hi, opt, dirs, samples, sqrtLambdaMin)) {
            lo = hi;
            hi *= 2.0;
            if (hi > 1e3 * tube.length())  // never fails: not a closed path the test can resolve
                throw std::runtime_error("estimateTubeRadius: the test passes for every epsilon");
        }
        for (int k = 0; k < opt.bisections; ++k) {
            const double mid = 0.5 * (lo + hi);
            if (radiusPasses(tube, mid, opt, dirs, samples, sqrtLambdaMin))
                lo = mid;
            else
                hi = mid;
        }
        return lo;
```

The loop doubles `hi` while the test passes, keeping the last passing value in `lo`. Once `hi` fails, the 14 bisection steps keep `lo` passing and `hi` failing, so the answer is bracketed. The function returns `lo`, the largest ε known to pass, which is the safe end of the bracket.

For all three tubes the run makes 20 calls of `radiusPasses`: 5 passing doublings, 1 failing, 14 bisections. The doubling intervals and the final resolution:

| Tube | Start 0.01 L | Last pass, first fail | Resolution after 14 bisections |
| --- | --- | --- | --- |
| Rigid body | 0.1088 | 1.741, 3.482 | 1.06e-4 |
| Panda, ℓ = 0.1 m | 0.0077 | 0.1232, 0.2464 | 7.5e-6 |
| Panda, ℓ = 1 m | 0.0174 | 0.278, 0.556 | 1.7e-5 |

The throw at `hi > 1e3 * tube.length()` guarantees termination. From 0.01 L it fires after at most 17 doublings (0.01 × 2¹⁷ > 1000), if the test never fails, for example on a path the sampling cannot resolve.

How to read this table:

- More probes can only find more intrusions, so the estimate is optimistic. As long as passing is monotone in ε, it can only go down as directions and foot points are added. The rigid body drops from 1.926 to 1.865 and the ℓ = 1 m Panda from 0.307 to 0.283 with 1000 directions.
- The rigid-body value 1.926 is set by one random direction (number 13 above). The ±eᵢ alone give 2.043, and so do seeds 2, 3 and 4, whose random directions miss that bad region.
- The Panda with ℓ = 0.1 m is limited by the coordinate direction −e₄, which every option set contains, so its estimate never moves.
- The coarse options give a higher rigid-body value (2.122: fewer probes) and a lower Panda value (0.124658: with 8 bisections the bracket is 4.8e-4 wide, and `lo` is its lower end).

The paper reports 1.89, 0.125 and 0.279. The test does not compare with these: it accepts ±10 % around its own anchors 1.93, 0.125 and 0.307 (`tests/test_tube.cpp:692-693`, `tests/test_tube.cpp:698`). Against the paper, the ℓ = 1 m value is 9.9 % high with the default directions and 1.6 % high with 1000.

Both example starts lie inside: 0.6245 < 1.93 and 0.0312 < 0.125. PAPER-1 asks the paper to state how many directions it samples.
