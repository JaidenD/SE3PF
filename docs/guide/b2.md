## The normal frame, step by step

The constructor builds N(s) of Lemma 1 in five steps at the 2001 nodes s_k = k h, h = L/n, and stores values and exact derivatives in a cubic Hermite spline. It runs once, takes about 5 ms in Release, and throws if anything is wrong.

```cpp
// src/tube.cpp:154-163
    Tube::Tube(const Path& path, const Metric& metric, int gridIntervals)
        : path_(path), metric_(metric), L_(path.length()), n_(gridIntervals)
    {
        if (n_ < 4)
            throw std::invalid_argument("Tube: need at least 4 grid intervals");
        const double h = L_ / n_;

        // Step 1: initial frame N0(0) by Gram-Schmidt.
        std::vector<Mat65> N0(n_ + 1, Mat65::Zero());
        N0[0] = initialFrame(path_.velocity(0.0), metric_);
```

The member initializer list (`: path_(path), metric_(metric), ...`) sets the members before the body runs. Members are always initialized in the order they are declared in the class (`include/se3pf/tube.hpp:93-98`), not the order written in the list; here the two orders agree.

The order would matter only if one initializer read another member. None does: `L_(path.length())` reads the parameter `path`, not the member `path_`. The body runs after every member is set, so `h = L_ / n_` on line 159 is safe in any case.

The node spacing depends on the path:

| Tube | L | h = L/2000 |
| --- | --- | --- |
| Panda, ℓ = 0.1 m (W = diag(0.01 I, I)) | 0.7700876453 | 3.85e-4 |
| Panda, ℓ = 1 m (W = I) | 1.7386966410 | 8.69e-4 |
| Rigid body (W = I) | 10.8827961854 | 5.44e-3 |

The guard `n_ < 4` only rejects nonsense; the real accuracy check comes in step 3. `N0` is a `std::vector` of n + 1 zero matrices; the constructor (offline) may allocate, so a heap vector is fine here.

### Step 1: the initial frame by Gram-Schmidt

Step 1 orthonormalizes ζ_γ(0), e₁, …, e₆ in ⟨·,·⟩_W, in that order, skips any vector whose residual is below 1e-8, and keeps the five vectors after ζ_γ(0) as N₀(0).

```cpp
// src/tube.cpp:31-55
        // Step 1 of Lemma 1: Gram-Schmidt in <.,.>_W on zeta_gamma(0), e_1, ..., e_6, in that order, skipping
        // every vector whose residual has W-norm below 1e-8. The five vectors after zeta_gamma are N0(0). The
        // order fixes the frame, and with it the meaning of xi (the start poses Psi(0.1, xi0) assume this order).
        Mat65 initialFrame(const Vec6& z0, const Metric& W)
        {
            std::vector<Vec6> basis;
            auto add = [&](Vec6 x) {
                for (const Vec6& b : basis)
                    x -= W.inner(b, x) * b;
                const double nx = W.norm(x);
                if (nx > 1e-8)
                    basis.push_back(x / nx);
            };
            add(z0);
            for (int i = 0; i < 6; ++i)
                add(Vec6::Unit(i));
            // seven vectors in R^6: exactly one e_i drops out (e_5 on the rigid-body path, e_6 on the Panda path)
            if (basis.size() != 6)
                throw std::runtime_error("Tube: Gram-Schmidt did not give six W-orthonormal vectors");

            Mat65 N0 = Mat65::Zero();
            for (int j = 0; j < 5; ++j)
                N0.col(j) = basis[j + 1];
            return N0;
        }
```

C++ first: `auto add = [&](Vec6 x) { ... };` defines a lambda, an unnamed function object written inline.

The capture `[&]` lets its body use `basis` and `W` from the enclosing function by reference, so `basis.push_back` changes the real vector. The parameter `Vec6 x` is taken by value, so the lambda edits its own copy and the caller's vector is untouched.

The loop `x -= W.inner(b, x) * b` is modified Gram-Schmidt. Each projection uses the already-reduced `x`, not the original vector, which loses less orthogonality to rounding than the classical form. `W.inner(b, x)` is bᵀWx, so orthogonality is in the metric, as Lemma 1 requires.

Seven vectors in R⁶ are always dependent, so exactly one eᵢ leaves a residual of rounding size. The measured W-norms of the residuals show how clean the split is:

| Vector | Panda, ℓ = 0.1 m | Rigid body |
| --- | --- | --- |
| ζ_γ(0) | 1 | 1 |
| e₁ | 0.1 | 0.816 |
| e₂ | 0.0979 | 1 |
| e₃ | 0.09997 | 0.707 |
| e₄ | 0.707 | 1 |
| e₅ | 0.247 | 6.6e-16 (dropped) |
| e₆ | 2.4e-16 (dropped) | 1 |

The threshold 1e-8 sits about seven orders of magnitude above the dropped residuals and seven below the smallest kept one (0.0979). Note that the W-norm decides: e₁ has W-norm √0.01 = 0.1 for the Panda metric, so it is kept and normalized to 10 e₁.

The rigid body's tangent is ζ_γ(0) = (e₁ + e₃ + e₅)/√3, so once ζ_γ, e₁ and e₃ are in the basis, e₅ is in their span.

The Panda's tangent is ζ_γ(0) = (0, 2.0186, −0.2536, −0.6923, −0.6708, 0.1713); its last entry is nonzero, so ζ_γ, e₁, …, e₅ already span R⁶ and e₆ drops. Its first entry is zero, so e₁ is already W-orthogonal to ζ_γ and the first column of N(0) is exactly 10 e₁ (a test checks this).

The `throw` is a safety net that the example paths never reach, and it does not catch a degenerate tangent. If ζ_γ(0) is zero or NaN, `nx > 1e-8` is false for it (every comparison with NaN is false), so it is skipped. Then e₁ to e₆ are all kept and the basis has six vectors again.

Measured with a test path whose velocity is NaN: the constructor gets past step 1 and step 3, and `rotationPlanes` finally throws `std::invalid_argument` on the NaN holonomy. With a velocity that is zero everywhere it builds a constant frame without any error. A real `Path` cannot do either: both curves divide their body velocity by the constant speed σ, so ‖ζ_γ‖_W = 1 everywhere (`src/path.cpp:73-78`, `src/path.cpp:122-127`).

The order matters because Lemma 1 fixes N only up to a constant orthogonal Q: N(s)Q satisfies everything too.

But ξ is a coordinate vector in this frame, so the start poses Ψ(0.1, ξ₀) of both examples depend on the order. With the columns of N reversed (N P, P the reversal), the same ξ₀ gives these starts:

| Start pose Ψ(0.1, ξ₀) | This order | Columns reversed |
| --- | --- | --- |
| Rigid body, ξ₀ = (0.4, −0.3, 0.2, −0.1, 0.3) | 25.45°, 0.4389 m | 15.50°, 0.5629 m |
| Panda, ξ₀ = (0.02, −0.015, 0.01, −0.005, 0.015) | 15.07°, 16.82 mm | 11.02°, 24.6 mm |

The paper reports 25.5°, 0.44 m and 15.1°, 16.8 mm, which only this order reproduces. The holonomy angles do not depend on the order, because H becomes QᵀHQ. The ticket PAPER-1 asks to state the order in the paper.

### Step 2: transport by RK4 (eq:transport)

Step 2 integrates the transport equation from N₀(0) over [0, L] with one classical RK4 step per grid interval. The ODE moves N₀ only along ζ_γ, just enough to stay W-orthogonal to it:

```latex
N_0'(s) = -\,\zeta_\gamma(s)\,\zeta_\gamma'(s)^\top W\,N_0(s),\qquad N_0(0)\ \text{from step 1}
```

```cpp
// src/tube.cpp:20-29
        // Right-hand side of eq:transport, N0' = -zeta_gamma zeta_gamma'^T W N0. N0 moves only along zeta_gamma,
        // just enough to stay W-orthogonal to it: with |zeta_gamma|_W = 1, (N0^T W zeta_gamma)' = 0 and
        // (N0^T W N0)' = 0, so N0 stays a W-orthonormal frame of the normal space.
        Mat65 transportRate(const Path& path, const Metric& W, double s, const Mat65& N)
        {
            const Vec6 z = path.velocity(s);
            const Vec6 dz = path.acceleration(s);
            const RowVec5 row = W.flat(dz).transpose() * N;  // zeta_gamma'^T W N
            return -z * row;
        }
```

`row` is the 1 × 5 row ζ_γ′ᵀ W N₀. Then `-z * row` is a 6 × 1 column times a 1 × 5 row: an outer product, a 6 × 5 matrix.

The order of the products is chosen for cost. `W.flat(dz)` is a full 6 × 6 matrix times a vector (Eigen does not know W is diagonal), so the code costs 36 + 30 + 30 = 96 multiplications. Forming the 6 × 6 matrix ζ_γ ζ_γ′ᵀ W first and then multiplying by N₀ would cost 36 + 36 + 180 = 252.

Why the ODE keeps the frame W-orthonormal and normal. With ‖ζ_γ‖_W = 1 (the path has unit speed in W):

```latex
\bigl(\zeta_\gamma^\top W N_0\bigr)' = \zeta_\gamma'^\top W N_0 - \bigl(\zeta_\gamma^\top W \zeta_\gamma\bigr)\,\zeta_\gamma'^\top W N_0 = 0,
\qquad
\bigl(N_0^\top W N_0\bigr)' = -\bigl(N_0^\top W \zeta_\gamma'\bigr)\bigl(\zeta_\gamma^\top W N_0\bigr) - \bigl(N_0^\top W \zeta_\gamma\bigr)\bigl(\zeta_\gamma'^\top W N_0\bigr) = 0
```

The second identity uses the first: ζ_γᵀ W N₀ = 0 for all s. So N₀ stays a W-orthonormal frame of the normal space, exactly in the ODE and up to the RK4 error in the code.

```cpp
// src/tube.cpp:165-174
        // Step 2: transport (eq:transport) by RK4, one step per grid interval.
        for (int k = 0; k < n_; ++k) {
            const double s = k * h;
            const Mat65& N = N0[k];
            const Mat65 k1 = transportRate(path_, metric_, s, N);
            const Mat65 k2 = transportRate(path_, metric_, s + 0.5 * h, N + (0.5 * h) * k1);
            const Mat65 k3 = transportRate(path_, metric_, s + 0.5 * h, N + (0.5 * h) * k2);
            const Mat65 k4 = transportRate(path_, metric_, s + h, N + h * k3);
            N0[k + 1] = N + (h / 6.0) * (k1 + 2.0 * k2 + 2.0 * k3 + k4);
        }
```

The four stages evaluate the right-hand side at s, s + h/2 (twice) and s + h. The path gives ζ_γ and ζ_γ′ in closed form at any s (`src/path.cpp:73-91`, `src/path.cpp:122-140`), so the half-step points need no interpolation. Every interval costs four calls of `transportRate`, so the whole transport makes 8000 velocity and 8000 acceleration evaluations.

C++ detail: `const Mat65& N = N0[k];` is a reference into the vector, not a copy. It is safe because the vector is never resized inside the loop. A `push_back` could move the vector's storage and leave `N` pointing at freed memory, which is why the vector is created at its final size `n_ + 1` on line 162.

Why one RK4 step per interval. The integrator's nodes are then exactly the spline's nodes, so nothing has to be interpolated between them. RK4's global error is O(h⁴), the same order as the cubic Hermite spline that stores the result, so neither part wastes accuracy.

The measured closure gap (step 5) shows the fourth order. Each halving of h divides it by 16:

| n | Panda ℓ = 0.1 m | Panda ℓ = 1 m | Rigid body |
| --- | --- | --- | --- |
| 500 | 9.4e-9 | 2.8e-9 | 1.2e-9 |
| 1000 | 5.9e-10 | 1.75e-10 | 7.4e-11 |
| 2000 (default) | 3.7e-11 | 1.1e-11 | 4.6e-12 |
| 4000 | 8.8e-11 | 6.8e-13 | 2.9e-13 |

The closure test, which requires a gap below 1e-9, explains the default of 2000 intervals. With n = 1000 the gap passes with a factor of only 1.7 to spare; with n = 2000, by a factor of 27.

Going to 4000 does not help the Panda (8.8e-11): its gap has reached the floor set by the eigenvectors of its tiny second plane (step 4). At n = 4000 its `logError` rises to 8.8e-12 (from 8.1e-14 at n = 2000), and the gap is that times max |N| = 10. The cost of 2000 is small: 5 ms and about 1 MB.

Why plain RK4 and not a Lie-group integrator that keeps N₀ᵀWN₀ = I exactly. RK4 does not preserve quadratic invariants, so N₀ᵀWN₀ drifts, but only by about 3.5e-11 at n = 2000 (the `orthogonalityError` of H). Step 4 removes that drift from H by an SVD, so the extra machinery would buy nothing measurable.

### Step 3: the holonomy H

Step 3 compares the transported frame at s = L with the frame at s = 0. Since ζ_γ(L) = ζ_γ(0), both frames span the same normal space, so N₀(L) = N₀(0) H for a 5 × 5 matrix H, a rotation of the normal space:

```latex
H = N_0(0)^\top W\, N_0(L),\qquad N_0(L) = N_0(0)\,H
```

```cpp
// src/tube.cpp:176-183
        // Step 3: holonomy H = N0(0)^T W N0(L), so that N0(L) = N0(0) H. It is a rotation of the normal space.
        const Mat5 H = N0[0].transpose() * metric_.matrix() * N0[n_];
        diag_.detH = H.determinant();
        diag_.orthogonalityError = (H.transpose() * H - Mat5::Identity()).cwiseAbs().maxCoeff();
        // A loose guard (the default grid gives about 1e-11, which the tests check to 1e-10): only a grossly
        // inaccurate transport, e.g. far too few grid intervals, stops the construction here.
        if (std::abs(diag_.detH - 1.0) > 1e-6 || diag_.orthogonalityError > 1e-6)
            throw std::runtime_error("Tube: the holonomy is not a rotation; the transport is too inaccurate");
```

The formula follows from N₀(0)ᵀ W N₀(0) = I: multiply N₀(L) = N₀(0)H on the left by N₀(0)ᵀW. The transported frame does not close by itself: the measured max |N₀(L) − N₀(0)| is 1.56 (Panda), 0.58 (ℓ = 1 m) and 1.27 (rigid body). That is the reason for steps 4 and 5.

The guard is deliberately loose. The default grid gives |HᵀH − I| of 3.5e-11 and the tests check 1e-10, but the constructor only stops at 1e-6.

Only grossly inaccurate transport trips it. Measured by trying every n from 4 to 300: the Panda tube throws for n ≤ 154 and builds from n = 155. The ℓ = 1 m tube builds from n = 137, the rigid-body tube from n = 94.

The guard is not NaN-safe: for a NaN H, both comparisons are false and the construction goes on. `rotationPlanes` then catches it with its own NaN-safe determinant check (step 4).

### Step 4: nearest rotation, then Φ = log H

Step 4 replaces H by the nearest rotation H_r and then takes Φ = log H_r from the invariant planes of H_r.

```cpp
// src/tube.cpp:185-197
        // Step 4: Phi = log H. RK4 leaves H orthogonal only to about 1e-11, so first replace it by the nearest
        // rotation H_r = U V^T (from the SVD H = U Sigma V^T), then take the logarithm from its invariant planes.
        const JacobiSVD<Mat5> svd(H, ComputeFullU | ComputeFullV);
        const Mat5 Hr = svd.matrixU() * svd.matrixV().transpose();
        const RotationPlanes planes = rotationPlanes(Hr);
        const Mat5 Phi = planes.log();

        diag_.planes = planes.count;
        for (int i = 0; i < planes.count; ++i)
            diag_.angles[i] = planes.theta[i];
        std::sort(diag_.angles.begin(), diag_.angles.end(), std::greater<double>());
        diag_.logError = (planes.exp(1.0) - Hr).cwiseAbs().maxCoeff();
        diag_.skewError = (Phi + Phi.transpose()).cwiseAbs().maxCoeff();
```

With the SVD H = UΣVᵀ, the matrix H_r = UVᵀ is the orthogonal matrix closest to H in the Frobenius norm. It is the orthogonal Procrustes solution, the orthogonal factor of the polar decomposition.

The singular values of the Panda's H differ from 1 by at most 1.9e-11; H_r sets them all to exactly 1. Since det H > 0 was checked, det H_r = +1: det(UVᵀ) has the sign of det H, because det Σ > 0.

`JacobiSVD` is Eigen's two-sided Jacobi SVD, the most accurate choice for small matrices. For a fixed-size matrix Eigen allows only the full U and V (`ComputeFullU | ComputeFullV`).

Asking for thin ones trips the assertion "thin U and V are only available when your matrix has a dynamic number of columns" (`Eigen/src/SVD/JacobiSVD.h:640` in Eigen 3.4.0). For a square 5 × 5 matrix, full and thin are the same anyway.

The projection comes before the logarithm because `rotationPlanes` assumes an exact rotation: the eigenvalues of (H + Hᵀ)/2 come in equal pairs, and Hu − cu lies in the plane of u. A raw H is not in SO(5), so no Φ can satisfy exp(Φ) = H exactly.

Measured on the Panda: without the SVD, exp(Φ) misses H by 1.75e-11 (the RK4 drift); with it, exp(Φ) matches H_r to 8.1e-14. The closure gap barely moves (3.8e-11 without, 3.7e-11 with), so the projection is about a clean input and a meaningful `logError`, not about the size of the gap.

### rotationPlanes: the invariant planes

`rotationPlanes(H)` finds the planes from the symmetric part S = (H + Hᵀ)/2. On plane i, S equals cos θ_i on both u_i and v_i; on a fixed direction it equals 1:

```latex
S = \tfrac12\bigl(H + H^\top\bigr) = \sum_i \cos\theta_i\,\bigl(u_i u_i^\top + v_i v_i^\top\bigr) + P_{\mathrm{fixed}}
```

```cpp
// src/tube.cpp:80-99
    RotationPlanes rotationPlanes(const Mat5& H)
    {
        if (!(H.determinant() > 0.0))
            throw std::invalid_argument("rotationPlanes: H is not a rotation (det H <= 0)");

        // (H + H^T)/2 = sum_i cos(theta_i) (u_i u_i^T + v_i v_i^T) + (projection onto the fixed directions)
        const Mat5 S = 0.5 * (H + H.transpose());
        const SelfAdjointEigenSolver<Mat5> eig(S);  // eigenvalues in increasing order: largest angles first
        const Vec5& lambda = eig.eigenvalues();
        const Mat5& V = eig.eigenvectors();

        RotationPlanes P;
        std::array<Vec5, 4> used = {Vec5::Zero(), Vec5::Zero(), Vec5::Zero(), Vec5::Zero()};
        int nUsed = 0;
        // x minus its components along the plane vectors found so far
        auto orthogonalize = [&](Vec5 x) {
            for (int j = 0; j < nUsed; ++j)
                x -= used[j].dot(x) * used[j];
            return x;
        };
```

`!(H.determinant() > 0.0)` is the NaN-safe form of `det <= 0`: every comparison with NaN is false, so a NaN determinant also throws. `SelfAdjointEigenSolver` is Eigen's eigensolver for symmetric matrices; it returns real eigenvalues in increasing order. The smallest cos θ comes first, so the largest angle is found first.

The references `const Vec5& lambda = eig.eigenvalues();` and `const Mat5& V = ...` point into the named object `eig`, which lives until the function returns, so they are safe. `orthogonalize` is a lambda that removes the components along the plane vectors found so far (stored in `used`, at most four vectors).

The measured eigenvalues of S, as 1 − λ, show the structure:

| Tube | 1 − λ₁, 1 − λ₂ (plane 1) | 1 − λ₃, 1 − λ₄ (plane 2) | 1 − λ₅ (fixed) |
| --- | --- | --- | --- |
| Panda, ℓ = 0.1 m | 1.296e-2, 1.296e-2 | 3.206e-9, 3.206e-9 | −6.7e-16 |
| Rigid body | 1.561, 1.561 | 0.1186, 0.1186 | −1.6e-15 |


The fixed-direction rule is `1.0 - lambda(k) < 1e-12`. A truly fixed direction has 1 − λ of rounding size, about 1e-15.

The Panda's second plane has θ = 8.0e-5, so 1 − cos θ = θ²/2 = 3.2e-9. The threshold 1e-12 sits about three orders of magnitude from both, and in angle it means θ < √(2e-12) = 1.4e-6.

What goes wrong with another threshold. At 1e-8 the Panda's second plane would count as fixed, and the frame would stay open by 7.8e-4 (measured with that plane dropped).

At 0, a fixed direction whose eigenvalue rounds to just below 1 would enter the plane branch with sin θ near 1e-16 < 1e-9. It would go to the rotation-by-π branch, find no partner and throw. The three tubes happen to have 1 − λ₅ < 0 and would still build, but the two `rotationPlanes` tests then fail with "no partner for a rotation by pi" (measured).

The test `u.norm() < 0.5` skips the second eigenvector of a plane already found. A double eigenvalue gives two eigenvectors spanning the plane {u, v}; after orthogonalizing against u and v the second one is about zero. A new direction keeps a norm near 1, so 0.5 separates the two cases with a wide margin.

Then the plane itself. With c = uᵀHu = cos θ and r = Hu − cu = sin θ v, the partner is v = r/‖r‖ and sin θ = ‖r‖ ≥ 0. The angle is `std::atan2(s, c)`, which is accurate at every angle; `acos(c)` would lose half the digits near 0 and π, where its derivative is infinite.

The rotation-by-π branch runs when sin θ < 1e-9. Then Hu = −u and r is pure rounding, so it has no direction. Any unit vector of the (−1)-eigenspace orthogonal to u completes the plane.

The loop takes the first eigenvector with λ ≤ −1 + 1e-6 that survives orthogonalization. Any such choice gives a valid logarithm, and step 5 closes the frame for every Φ with exp(Φ) = H.

The bound −1 + 1e-6 accepts eigenvalues of angles within about 1.4e-3 of π. That is far wider than the 1e-9 that sent the code into this branch, so the true partner is never missed.

A rotation of R⁵ has at most two planes, so finding a third means H is not orthogonal. The angle is stored with `atan2(s, c)`, the vectors are appended to `used`, and `count` advances.

The Panda's small plane is accurate, but not to rounding. Its eigenvalue is separated from the fixed one by only 3.2e-9, so an eigenvector is accurate to about ε_mach/gap ≈ 1.1e-16 / 3.2e-9 = 3.5e-8.

That tilt, times the angle θ = 8e-5, gives an error in exp(Φ) of about 2ε_mach/θ ≈ 3e-12. The measured `logError` is 8.1e-14, well inside that bound.

Why not `Hr.log()` from Eigen's `unsupported/Eigen/MatrixFunctions`. For a rotation by π it loses the rotation (measured with Eigen 3.4.0). For H = diag(R(π), 1, 1, 1) it returns the zero matrix, so |exp(log H) − H| = 2.0; for a randomly rotated copy of that H the miss is 1.12.

The planes give an exact logarithm on the same matrix (error 1.2e-16), and exp(−(s/L)Φ) costs one sine and cosine per plane instead of a Padé matrix exponential at each node.

After the logarithm, the diagnostics are filled (`src/tube.cpp:192-197`). `std::sort(..., std::greater<double>())` orders the angles largest first; `std::greater` comes from `<functional>` (`src/tube.cpp:6`). The planes already come largest first, so the sort only guarantees the order of `diag_.angles` independently of that detail.

### Step 5: the closed frame and its derivative

Step 5 undoes the holonomy gradually along the path. Multiplying on the right by a rotation that goes from I at s = 0 to H_r⁻¹ at s = L closes the frame:

```latex
N(s) = N_0(s)\,\exp\!\bigl(-\tfrac{s}{L}\,\Phi\bigr),\qquad N(L) = N_0(0)\,H\,H_r^{-1} \approx N_0(0) = N(0)
```

Because exp(−(s/L)Φ) is orthogonal and acts on the right, N still satisfies NᵀWN = I and NᵀWζ_γ = 0. Differentiating, and using that exp(−(s/L)Φ) commutes with Φ, gives eq:frame-ode:

```latex
N'(s) = N_0'(s)\,e^{-\frac{s}{L}\Phi} - \tfrac{1}{L}\,N_0(s)\,e^{-\frac{s}{L}\Phi}\,\Phi
      = -\,\zeta_\gamma(s)\,\zeta_\gamma'(s)^\top W\,N(s) \;-\; \tfrac{1}{L}\,N(s)\,\Phi
```

```cpp
// src/tube.cpp:199-210
        // Step 5: the closed frame N(s) = N0(s) exp(-(s/L) Phi) (eq:holonomy), and its exact derivative from
        // eq:frame-ode, N' = -zeta_gamma zeta_gamma'^T W N - (1/L) N Phi, at the nodes.
        std::vector<Mat65> Y(n_ + 1, Mat65::Zero()), D(n_ + 1, Mat65::Zero());
        for (int k = 0; k <= n_; ++k) {
            const double s = k * h;
            Y[k] = N0[k] * planes.exp(-s / L_);
            D[k] = transportRate(path_, metric_, s, Y[k]) - (1.0 / L_) * (Y[k] * Phi);
        }
        // N(L) must equal N(0). Measured here, on the node values: the spline replaces node n by node 0.
        diag_.closureGap = (Y[n_] - Y[0]).cwiseAbs().maxCoeff();

        N_.build(L_, std::move(Y), std::move(D));
```

`Y[k]` is N(s_k), computed with the closed-form `planes.exp(-s / L_)`. `D[k]` is N′(s_k) from the formula above: `transportRate` applied to the closed frame `Y[k]` gives the first term, and `(1.0 / L_) * (Y[k] * Phi)` the second.

The second term is large: up to 2.0 in an entry for the Panda and 0.14 for the rigid body. Leaving it out fails the N′ test by far (error 2.0 at the nodes, measured).

Note that `Y` uses `planes.exp` while `D` uses `Phi` from `planes.log()`. The two must describe the same rotation, or the spline's node derivatives no longer match its node values.

The closure gap and two mutations it catches (measured):

| Tube | `closureGap` | with exp(+(s/L)Φ) (wrong sign) | with the second plane dropped |
| --- | --- | --- | --- |
| Panda, ℓ = 0.1 m | 3.7e-11 | 3.09 | 7.8e-4 |
| Panda, ℓ = 1 m | 1.1e-11 | 0.89 | 1.9e-4 |
| Rigid body | 4.6e-12 | 1.17 | 0.25 |

The Panda's dropped-plane gap, 7.8e-4, is about θ × max |N| = 8e-5 × 10. The entries of N are as large as 10 because a unit W-norm vector along e₁ is 10 e₁ when w_R = 0.01.

Why the gap is measured on `Y` before the spline. `PeriodicHermite::build` overwrites node n with node 0 so the spline closes exactly:

```cpp
// include/se3pf/spline.hpp:19-31
            // n + 1 samples; sample n must repeat sample 0 (it is overwritten with it, so the spline closes exactly).
            void build(double L, std::vector<T> y, std::vector<T> dy)
            {
                if (!(L > 0.0) || y.size() < 2 || dy.size() != y.size())
                    throw std::invalid_argument("PeriodicHermite: need L > 0 and n + 1 >= 2 values and derivatives");
                n_ = static_cast<int>(y.size()) - 1;
                L_ = L;
                h_ = L / n_;
                y_ = std::move(y);
                dy_ = std::move(dy);
                y_[n_] = y_[0];
                dy_[n_] = dy_[0];
            }
```

After `build`, `frame(L)` wraps L to 0 and returns node 0 bit for bit, so a gap measured through `frame` is always zero. The node values before `build` are therefore the direct check.

The frame-property tests (NᵀWN = I, NᵀWζ_γ = 0) pass for an open frame whose node derivatives match its values. With the second plane dropped, Y and D both come from the one-plane Φ, and they still pass. The N′ test notices that open frame only at node 0, where its differences straddle the seam: error 1.19 there, against 5.6e-8 for the closed frame (measured).

A one-line sign flip `planes.exp(s / L_)` on line 204 is different: `D` still uses −Φ, so the node derivatives disagree with the values. The N′ test then fails at every node (4.0, and 4.7e3 at node 0), and even the frame-property tests fail (errors up to 9e-7 between the nodes, measured).

Why exact node derivatives. A cubic Hermite spline needs a value and a derivative at each node; with exact derivatives its error is O(h⁴), matching RK4. Measured on the Panda, NᵀWN = I holds to 3.5e-11 at the nodes and 3.6e-11 at the midpoints, and N at the midpoints agrees with a 4000-interval tube to 8.7e-11.

`std::move(Y)` hands the vector's heap buffer to `build` instead of copying 480 KB. `build` takes its vectors by value (a "sink" parameter), so the moved-in buffers become the spline's `y_` and `dy_` with no copy at all. After the move, `Y` and `D` are empty (a moved-from vector is guaranteed empty after move construction), and the constructor does not touch them again.
