## The rigid-body example

`RigidBodyExample` packages the paper's first simulation, a free body following the tumbling circle in the metric W = I, and `simulate` runs it as a sampled closed loop. It reproduces the paper's numbers: a maximum deviation from the designed transverse response of 9.69e-4 (pose reference) and 9.51e-4 (velocity reference), inside the paper's "within 1e-3".

### The class: everything the loop needs, in dependency order

```cpp
// include/se3pf/rigid_body_example.hpp:13-33
    // The paper's rigid-body example (design doc, Rigid-body simulation and Appendix: Rigid body): the free body
    // J = diag(1.0, 1.2, 0.8) kg m^2, m = 2 kg follows the tumbling circle (r = 1 m) in the metric W = I. It starts
    // at rest at Psi(0.1, xi0), xi0 = (0.4, -0.3, 0.2, -0.1, 0.3), with transverse poles at -lambda = -4, under
    // a pose reference (k_p = 9, k_d = 6) or a velocity reference (k_t = 5).
    //
    // The object owns everything the closed loop needs, in dependency order: the metric, the path, the tube (which
    // keeps a reference to the path) and the body. It cannot be copied or moved, since a copy's tube would still
    // refer to the original's path. Construction builds the tube (offline, a few milliseconds in Release).
    class RigidBodyExample {
        public:
            // The tangential law: a position eta_d(t) (eq:tan-pos) or a velocity nu_d(t) (eq:tan-vel), as in
            // TangentialReference::Mode
            enum class Reference { Position, Velocity };

            static constexpr double kS0 = 0.1;       // start point on the path
            static constexpr double kLambda = 4.0;   // transverse poles at -lambda, rad/s
            static constexpr long kMaxSteps = 10'000'000;  // the longest run simulate accepts, in control periods

            RigidBodyExample();
            RigidBodyExample(const RigidBodyExample&) = delete;
            RigidBodyExample& operator=(const RigidBodyExample&) = delete;
```

- `enum class Reference { Position, Velocity };` names the two tangential laws of the example. It mirrors `TangentialReference::Mode`, but belongs to the example's interface.
- `static constexpr double kS0 = 0.1;` and `kLambda = 4.0` are compile-time constants of the class. `10'000'000` uses the C++14 digit separator `'`, which the compiler ignores; it only makes the number readable.
- The copy constructor and copy assignment are `= delete`. The tube keeps a reference to the path (`include/se3pf/tube.hpp:93`). A copied example would contain a copied tube whose reference still points at the original's `path_`: destroy the original and the copy's tube dangles.
- Declaring the copy constructor (even as deleted) also stops the compiler from generating a move constructor, so the example cannot be moved either. A move would have the same dangling problem. The test checks all three with `STATIC_REQUIRE_FALSE` (`tests/test_rigid_body_example.cpp:123-125`).

```cpp
// include/se3pf/rigid_body_example.hpp:35-45
            // Not on a temporary example (deleted &&-overloads): a controller keeps a reference to the tube.
            const Metric& metric() const& { return metric_; }
            const Path& path() const& { return path_; }
            const Tube& tube() const& { return tube_; }
            const RigidBody& body() const { return body_; }
            const Metric& metric() const&& = delete;
            const Path& path() const&& = delete;
            const Tube& tube() const&& = delete;

            static Vec5 xi0();                // start offset (0.4, -0.3, 0.2, -0.1, 0.3), |xi0| = 0.6245
            Pose startPose() const;           // g0 = Psi(0.1, xi0); since a pose Psi(s0, xi) has eta = s0, reset(0.1)
```

- `const Tube& tube() const& { return tube_; }` is a ref-qualified member function: the trailing `&` means it can be called only on an lvalue (a named object). The overload `const Tube& tube() const&& = delete;` matches rvalues (temporaries) and is deleted. So `RigidBodyExample().tube()`, which would return a reference into an object destroyed at the end of the statement, does not compile. The test detects this at compile time with `HasTube` (`tests/test_rigid_body_example.cpp:30-34` and `tests/test_rigid_body_example.cpp:126-127`).
- `body()` has no such guard, so `const RigidBody& b = RigidBodyExample().body();` would compile and dangle. No code in the repository does this; the controller never keeps a reference to the body.
- `xi0()` is ξ₀ = (0.4, −0.3, 0.2, −0.1, 0.3), with |ξ₀| = 0.6245.

```cpp
// include/se3pf/rigid_body_example.hpp:47-63
            // lambda = 4 for the transverse gains; k_t = 5, k_p = 9, k_d = 6 for the tangential laws
            static Gains gains();

            // eta_d(t) = L/4 + (L/5) (1 - cos(pi t / 10)) for Reference::Position,
            // nu_d(t) = 0.5 + 0.2 sin(0.5 t) for Reference::Velocity
            TangentialReference reference(Reference which) const;

            // The designed response of the transverse output from rest: |xi(t)| = |xi0| (1 + lambda t) e^{-lambda t}
            // (eq:transverse-cl with K_p = lambda^2 I, K_d = 2 lambda I and xi_dot(0) = 0).
            static double designedXiNorm(double t);

        private:
            Metric metric_;
            TumblingCircle path_;
            Tube tube_;
            RigidBody body_;
    };
```

The private members are listed in the order they must be built: `metric_` (W = I), `path_` (needs the metric for arc length), `tube_` (needs both), `body_`.

### Construction order

```cpp
// src/rigid_body_example.cpp:10-14
    // Members in declaration order: the path needs the metric, the tube needs both.
    RigidBodyExample::RigidBodyExample()
        : metric_(Metric::product(1.0, 1.0)), path_(1.0, metric_), tube_(path_, metric_), body_(RigidBody::example())
    {
    }
```

- C++ initializes members in their declaration order, not in the order of the initializer list. Here the two agree, which is what the comment insists on. If `tube_` were declared before `path_`, the tube would be built from a path not yet constructed, however the list was written.
- `Metric::product(1.0, 1.0)` is W = diag(w_R I, w_p I) with w_R = w_p = 1, so ℓ = √(w_R/w_p) = 1 m: one radian weighs as much as one metre.
- `path_(1.0, metric_)` is the tumbling circle of radius 1 m, with length L = 2√3π = 10.88279619 in this metric.
- `tube_(path_, metric_)` builds the normal frame N(s) of Lemma 1 on the default 2000 grid intervals. This is the only expensive part, about 3 ms in Release; the whole `rigid_body_sim` run, construction, both 20 s loops and the CSV files included, takes 0.34 s on this machine.

### Start pose, gains and the two references

```cpp
// src/rigid_body_example.cpp:16-35
    Vec5 RigidBodyExample::xi0()
    {
        Vec5 xi;
        xi << 0.4, -0.3, 0.2, -0.1, 0.3;
        return xi;
    }

    Pose RigidBodyExample::startPose() const
    {
        return tube_.Psi(kS0, xi0());
    }

    Gains RigidBodyExample::gains()
    {
        Gains g = Gains::fromLambda(kLambda);
        g.kt = 5.0;
        g.kpEta = 9.0;
        g.kdEta = 6.0;
        return g;
    }
```

- `Vec5 xi; xi << 0.4, ...;` fills a fixed-size vector with Eigen's comma initializer.
- `startPose()` is g₀ = Ψ(0.1, ξ₀). Proposition 1 says a pose Ψ(s₀, ξ) inside the tube has η = s₀ and outputs ξ, so the controller's `reset(0.1)` is exact and the first projection needs one Newton update.
- g₀ is 25.45° and 0.4389 m from γ(0.1) (the paper: 25.5°, 0.44 m). |ξ₀| = 0.6245 is well inside the estimated tube radius 1.93 (paper 1.89; `docs/DESIGN.md:442`).
- At g₀, A = J_Ψ⁻¹ has σ_min = 0.876 and σ_max = 1.328 (scratch run): far from singular, and not orthogonal because the body is off the path (on the path, with W = I, A is orthogonal and σ_min = 1).
- `gains()`: λ = 4 gives K_p = 16, K_d = 8; k_t = 5, k_p = 9, k_d = 6. The last three equal the struct's defaults; writing them again documents the example's choice next to the code that uses it.

```cpp
// src/rigid_body_example.cpp:37-55
    TangentialReference RigidBodyExample::reference(Reference which) const
    {
        const double L = path_.length();
        if (which == Reference::Position) {
            // eta_d(t) = L/4 + (L/5) (1 - cos(w t)), w = pi / 10: from L/4 to L/4 + 2L/5 and back in 20 s
            return TangentialReference::fromPosition([L](double t, double& etaD, double& detaD, double& ddetaD) {
                const double w = EIGEN_PI / 10.0;
                etaD = L / 4.0 + (L / 5.0) * (1.0 - std::cos(w * t));
                detaD = (L / 5.0) * w * std::sin(w * t);
                ddetaD = (L / 5.0) * w * w * std::cos(w * t);
            });
        }
        // nu_d(t) = 0.5 + 0.2 sin(0.5 t), independent of eta
        return TangentialReference::fromVelocity([](double t, double, double& nu, double& dnuDt, double& dnuDeta) {
            nu = 0.5 + 0.2 * std::sin(0.5 * t);
            dnuDt = 0.1 * std::cos(0.5 * t);
            dnuDeta = 0.0;
        });
    }
```

```latex
\eta_d(t) = \frac{L}{4} + \frac{L}{5}\Bigl(1 - \cos\frac{\pi t}{10}\Bigr), \qquad
\nu_d(t) = 0.5 + 0.2\,\sin(0.5\,t).
```

- The position reference starts at L/4 at rest (η̇_d(0) = 0), goes to L/4 + 2L/5 at t = 10 s and back at t = 20 s. Its derivatives are written by hand; the test compares them with central differences (`tests/test_rigid_body_example.cpp:144-152`).
- `[L](...)` captures the local `L` by value. The lambda is returned inside the `TangentialReference` and called long after `reference()` has returned; capturing by reference (`[&]`) would leave it reading a dead local variable.
- The velocity lambda captures nothing (`[]`); ∂ν_d/∂η = 0 because this ν_d depends on time only.
- `EIGEN_PI` is Eigen's π constant. `M_PI` is not part of standard C++, so portable code avoids it.
- The start is far from both references: at t = 0, e_η = 0.1 − L/4 = −2.6207 for the pose run, and e_v = −0.5 for the velocity run.

### The designed response

```cpp
// src/rigid_body_example.cpp:57-60
    double RigidBodyExample::designedXiNorm(double t)
    {
        return xi0().norm() * (1.0 + kLambda * t) * std::exp(-kLambda * t);
    }
```

With K_p = λ²I and K_d = 2λI, each component of ξ obeys the same critically damped equation, and the body starts at rest:

```latex
\ddot\xi + 2\lambda\dot\xi + \lambda^2\xi = 0,\quad \xi(0) = \xi_0,\ \dot\xi(0) = 0
\quad\Longrightarrow\quad
\xi(t) = \xi_0\,(1 + \lambda t)\,e^{-\lambda t}, \qquad
|\xi(t)| = |\xi_0|\,(1 + \lambda t)\,e^{-\lambda t}.
```

All five components scale by the same factor, so the norm follows the same curve; this is the "designed response" every log row compares against. It does not depend on the tangential law, which is why the pose and velocity runs share it.

### The log row and the run summary

```cpp
// include/se3pf/rigid_body_example.hpp:65-75
    // One row of the closed-loop log, at a control instant t_k = k dt (before the plant moves on).
    struct RigidBodyLogRow {
        double t = 0.0;
        double eta = 0.0, etaDot = 0.0;
        double ref = 0.0;            // eta_d (pose reference) or nu_d (velocity reference)
        double eTan = 0.0;           // e_eta or e_v
        Vec5 xi = Vec5::Zero();
        double xiNorm = 0.0;
        double xiDesign = 0.0;       // |xi0| (1 + 4t) e^{-4t}
        Vec6 u = Vec6::Zero();       // body wrench (tau, f), held over [t, t + dt)
    };
```

```cpp
// include/se3pf/rigid_body_example.hpp:77-95
    // The log and the summary numbers of one closed-loop run (the Closed loops table of the design doc).
    struct RigidBodyRun {
        RigidBodyExample::Reference reference = RigidBodyExample::Reference::Position;
        double dt = 0.0;
        int substeps = 0;
        std::vector<RigidBodyLogRow> log;

        double startAttitudeDeg = 0.0;   // angle between the attitudes of g0 and gamma(0.1), degrees
        double startPosition = 0.0;      // distance between their positions, m
        double maxDeviation = 0.0;       // max over the log of ||xi| - |xi0| (1 + 4t) e^{-4t}|
        double maxDeviationTime = 0.0;
        double finalXiNorm = 0.0;        // |xi| at the last row
        double finalTanError = 0.0;      // e_eta or e_v at the last row
        double maxInput = 0.0;           // max over the log of |u|_inf
        double maxInputTime = 0.0;
        int maxIterations = 0;           // most Newton updates in one projection
        bool ok = false;                 // false if a step failed (the pose left the tube)
        double failureTime = -1.0;       // time of that step, or -1
    };
```

- One `RigidBodyLogRow` per control instant t_k, recorded before the plant moves on; `u` is the wrench held over [t_k, t_k + Δt).
- `RigidBodyRun` holds the log (a `std::vector`, sized at run time: 10001 rows for the paper's run) and the summary numbers that the design doc's Closed loops table lists. `failureTime = -1.0` is a sentinel: a real time is never negative.

### simulate: the sample-and-hold closed loop

```cpp
// include/se3pf/rigid_body_example.hpp:97-103
    // The paper's closed loop with sample-and-hold: start at rest at g0 = Psi(0.1, xi0) and reset(0.1); at every
    // t_k = k dt, k = 0, ..., stepCount(T, dt) (the instants k dt <= T): step gives qdd*, u = M qdd* + C zeta (eq:fb
    // with G = 0) is held for the period while RigidBody::integrate takes `substeps` equal steps. Stops at the first
    // failed step. Offline: the log is reserved before the loop; throws std::invalid_argument unless T >= 0 and
    // dt > 0 are finite, T / dt <= RigidBodyExample::kMaxSteps and substeps >= 1.
    RigidBodyRun simulate(const RigidBodyExample& example, RigidBodyExample::Reference which, double T = 20.0,
                          double dt = 0.002, int substeps = 4);
```

The parameters `T`, `dt` and `substeps` have default arguments (20 s, 2 ms, 4): `simulate(ex, which)` runs the paper's setup, and the tests pass other values (1 s runs, Δt = 1 ms, 1 or 16 substeps).

```cpp
// src/rigid_body_example.cpp:62-82
    RigidBodyRun simulate(const RigidBodyExample& example, RigidBodyExample::Reference which, double T, double dt,
                          int substeps)
    {
        if (substeps < 1)
            throw std::invalid_argument("simulate: need substeps >= 1");
        // Checks T and dt (finite, T >= 0, dt > 0, T / dt <= kMaxSteps) before anything is built or allocated.
        const long steps = stepCount(T, dt, RigidBodyExample::kMaxSteps);  // the instants k dt <= T

        RigidBodyRun run;
        run.reference = which;
        run.dt = dt;
        run.substeps = substeps;

        Controller<RigidBody> controller(example.tube(), RigidBodyExample::gains(), example.reference(which));
        const RigidBody& body = example.body();
        const Mat6 M = body.mass();

        // Start at rest at g0 = Psi(0.1, xi0), whose closest point is gamma(0.1).
        Pose g = example.startPose();
        Vec6 zeta = Vec6::Zero();
        controller.reset(RigidBodyExample::kS0);
```

1. `substeps < 1` is rejected first, then `stepCount` validates T and Δt. Both throw `std::invalid_argument` before anything is built or allocated.
1. The controller is a local object, built for this run with the example's tube, gains and reference. It lives on the stack and is destroyed when `simulate` returns; the tube it refers to lives in `example`, which outlives it.
1. `const Mat6 M = body.mass();` is computed once: the mass matrix is constant in body coordinates.
1. The body starts at rest at g₀ (`zeta = Vec6::Zero()`), and `controller.reset(kS0)` puts η̂ at 0.1.

```cpp
// src/rigid_body_example.cpp:84-91
        const Pose gamma0 = example.path().pose(RigidBodyExample::kS0);
        const Matrix3d Rerr = gamma0.block<3,3>(0,0).transpose() * g.block<3,3>(0,0);
        run.startAttitudeDeg = logSO3(Rerr).norm() * 180.0 / EIGEN_PI;
        run.startPosition = (g.block<3,1>(0,3) - gamma0.block<3,1>(0,3)).norm();

        run.log.reserve(static_cast<std::size_t>(steps) + 1);
        const double h = dt / substeps;
        run.ok = true;
```

1. The start errors are computed from R_γᵀR_g: `logSO3(Rerr).norm()` is the rotation angle in radians, converted to degrees.
1. `run.log.reserve(steps + 1)` allocates the whole log once. Inside the loop `push_back` then never reallocates, so the loop itself allocates nothing (the Panda version of this property is tested at `tests/test_controller.cpp:1157-1178`). `static_cast<std::size_t>` converts the `long` step count to the unsigned size type that `reserve` takes.
1. `const double h = dt / substeps;` is the plant's step: 0.5 ms for the paper's 2 ms period and 4 substeps.

```cpp
// src/rigid_body_example.cpp:92-115
        for (long k = 0; k <= steps; ++k) {
            const double t = k * dt;
            Vec6 qdd = Vec6::Zero();
            Controller<RigidBody>::Status st;
            if (!controller.step(g, zeta, t, dt, qdd, st)) {
                run.ok = false;
                run.failureTime = t;
                break;
            }

            // eq:fb with G = 0, held over [t, t + dt) (zero-order hold)
            const Vec6 u = M * qdd + body.coriolis(zeta);

            RigidBodyLogRow row;
            row.t = t;
            row.eta = st.eta;
            row.etaDot = st.etaDot;
            row.ref = st.ref;
            row.eTan = st.eTan;
            row.xi = st.xi;
            row.xiNorm = st.xi.norm();
            row.xiDesign = RigidBodyExample::designedXiNorm(t);
            row.u = u;
            run.log.push_back(row);
```

- `const double t = k * dt;` computes each instant by multiplication, never by `t += dt`. Repeated addition accumulates rounding: adding 0.002 ten thousand times gives 19.999999999999794, not 20, and differs from k·0.002 at 9983 of the 10000 instants. The test relies on the multiplication, checking `r.t == k * run.dt` exactly (`tests/test_rigid_body_example.cpp:71`).
- `controller.step(g, zeta, t, dt, qdd, st)`: for the rigid body `q` is the pose g and `dq` is the body twist ζ.
- On failure the run records the time and stops; the log keeps the rows before it.
- `u = M * qdd + body.coriolis(zeta)` is eq:fb with G = 0, evaluated once at t_k with the sampled ζ. This is the zero-order hold.
- Each row copies what the `Status` reports, plus |ξ| and the designed value at t.

```cpp
// src/rigid_body_example.cpp:117-137
            const double deviation = std::abs(row.xiNorm - row.xiDesign);
            if (deviation > run.maxDeviation) {
                run.maxDeviation = deviation;
                run.maxDeviationTime = t;
            }
            const double uMax = u.cwiseAbs().maxCoeff();
            if (uMax > run.maxInput) {
                run.maxInput = uMax;
                run.maxInputTime = t;
            }
            run.maxIterations = std::max(run.maxIterations, st.iterations);

            for (int i = 0; i < substeps; ++i)
                body.integrate(g, zeta, u, h);
        }

        if (!run.log.empty()) {
            run.finalXiNorm = run.log.back().xiNorm;
            run.finalTanError = run.log.back().eTan;
        }
        return run;
```

- The summary numbers are maxima over the log, with the time at which each occurs. `u.cwiseAbs().maxCoeff()` is the infinity norm ‖u‖∞.
- `body.integrate(g, zeta, u, h)` runs `substeps` times with the same u: the plant moves in continuous time (RK4) while the input is held. That is the difference from the paper's ideal continuous-time loop, and it is the whole source of the deviation.
- `if (!run.log.empty())` guards the final values; with `T = 0` the log has one row, and only a failure at t = 0 leaves it empty.

### The numbers, and what they mean

Output of `./build-ci-release/rigid_body_sim <dir>` on this machine, with the design doc's expected values and the paper's:

| Quantity | This run | Design doc | Paper |
| --- | --- | --- | --- |
| L | 10.88279619 | 2√3π | |
| start: ‖ξ₀‖; angle and distance from γ(0.1) | 0.6245; 25.45°; 0.4389 m | same | 25.5°, 0.44 m |
| pose reference: largest deviation of ‖ξ‖ from the design | 9.685e-4 at t = 0.430 s | 9.69e-4 | within 1e-3 |
| pose reference: final ‖ξ‖; final e_η | 1.78e-6; −1.69e-6 | 1.8e-6; −1.7e-6 | |
| pose reference: max ‖u‖∞ | 29.11 at t = 0 | 29.1 at t = 0 | |
| velocity reference: largest deviation of ‖ξ‖ from the design | 9.509e-4 at t = 0.408 s | 9.51e-4 | within 1e-3 |
| velocity reference: final ‖ξ‖; final e_v | 2.81e-6; −3.25e-6 | 2.8e-6; −3.2e-6 | |
| velocity reference: max ‖u‖∞ | 14.48 at t = 0 | 14.5 at t = 0 | |
| Newton updates per projection | at most 1 | | |

The largest input is the first one, at rest. For the pose reference, q̈*(0) = (12.40, 8.80, 7.91, 1.56, 9.38, −14.56) and u(0) = M q̈* = (12.40, 10.57, 6.33, 3.12, 18.75, −29.11): the −29.11 N is the force along the body z axis. It is large because e_η(0) = −2.62 asks for μ∥ = η̈_d(0) − 9e_η ≈ 0.21 + 23.59 = 23.8, on top of the transverse command −16ξ₀. The velocity reference starts with the gentler μ∥ = 0.1 + 5 · 0.5 = 2.6, hence 14.48.

The deviation from the designed response is a sample-and-hold effect of order Δt. The controller makes ȳ̈ = μ hold exactly at the sample instants; within a period the held u no longer matches the changing state. Halving Δt halves the deviation (scratch runs; the 1 ms value is also checked by the test at `tests/test_rigid_body_example.cpp:288-301`):

| Δt | velocity reference | pose reference |
| --- | --- | --- |
| 4 ms | 1.905e-3 | 1.939e-3 |
| 2 ms (the paper's) | 9.509e-4 | 9.685e-4 |
| 1 ms | 4.751e-4 | 4.841e-4 |
| 0.5 ms | 2.375e-4 | 2.420e-4 |

Each halving divides the deviation by a factor between 2.000 and 2.003. If a change to the code breaks this ratio, the extra error is a bug, not sampling.

What each ingredient is worth, from scratch runs of the same 20 s loop at Δt = 2 ms with one ingredient removed (not code in the repository):

| Variant | largest deviation of ‖ξ‖ from the design |
| --- | --- |
| The code as it is | 9.51e-4 (velocity), 9.69e-4 (pose) |
| Ȧq̇ dropped (a System whose `retract` ignores h, so A(c(h)) = A(q)) | 1.91e-2 (velocity), 1.18e-1 (pose) |
| Cζ dropped from u (u = M q̈*) | 1.22e-2 (velocity), 5.24e-2 (pose) |
| `retract` replaced by the screw motion g exp(hζ̂) | 9.51e-4 and 9.69e-4, identical to all seven printed digits |
| Newton restarted from the previous η instead of η̂ | 9.51e-4 and 9.69e-4, but 2 updates in some cycles |

Ȧq̇ is not a small correction: without it the pose run misses the designed response by 0.12, more than a hundred times the sampling effect.

            std::cerr << "error: cannot write the logs to " << dir << "\n";
            return 1;
        }
        std::printf("wrote %s and %s\n", poseFile.string().c_str(), velocityFile.string().c_str());
        return pose.ok && velocity.ok ? 0 : 2;
    } catch (const std::exception& e) {
        std::cerr << "error: " << e.what() << "\n";
        return 1;
    }
}

- `argc > 1 ? argv[1] : "out/"` picks the output directory: the first command-line argument, or `out/` relative to the current directory. `std::filesystem::create_directories` creates it (and its parents) if needed.
- `using namespace se3pf;` at file scope (line 15) is acceptable in a program's `.cpp`; in a header it would leak the names into every file that includes it.
- The `try`/`catch (const std::exception& e)` around everything turns any offline exception (a bad argument, a failed tube construction, a filesystem error) into a message and exit code 1.
- Exit codes: 0 if both runs succeeded, 2 if a step failed in either, 1 on an exception or a write error. `tools/ci.sh:58` runs the app and checks only this exit code; the expected values in brackets are printed for a human to compare, and the tests check the numbers.

            for (int i = 0; i < 5; ++i)
                f << ',' << r.xi[i];
            f << ',' << r.xiNorm << ',' << r.xiDesign;
            for (int i = 0; i < 6; ++i)
                f << ',' << r.u[i];
            f << '\n';
        }
        return static_cast<bool>(f);
    }

- The helpers sit in an anonymous namespace, so they are private to this file.
- `std::ofstream f(file); if (!f) return false;` checks that the file opened. `f.precision(10)` prints 10 significant digits. `return static_cast<bool>(f);` reports whether every write so far succeeded (a full disk sets the stream's fail bit).
