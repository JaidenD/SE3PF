## C++ techniques index

Every C++ technique the project uses is listed below with where to see it, why it is used there, and what breaks without it. The table is grouped: Eigen first, then functions and classes, templates, the standard library, error handling, and the tests.

### The table

### Three techniques in context

The template header of the controller shows `static constexpr`, `static_assert`, `typename` and the alias templates together:

```cpp
// include/se3pf/controller.hpp:136-143
    template <class System>
    class Controller {
        public:
            static constexpr int n = System::kDof;
            static_assert(n == 6 || n == 7, "Controller: n = 6 (r = 0) or n = 7 (r = 1) generalized velocities");
            using Config = typename System::Config;
            using VecN = Vec<n>;
            using MatN = Mat<n, n>;
```

`jointMargin` shows a NaN that must fail closed, and an optional output through a pointer:

```cpp
// src/panda.cpp:81-92
    double PandaArm::jointMargin(const Vec7 &q, int *joint)
    {
        // Distance of each joint to its nearer limit; positive inside the range, negative outside.
        const Vec7 margins = (q - qMin()).cwiseMin(qMax() - q);
        // Fail closed: the default minCoeff (PropagateFast) skips a NaN unless it is the first entry, which would
        // let a corrupted q pass a margin check. PropagateNaN returns NaN with the index of the NaN joint.
        int i = 0;
        const double margin = margins.minCoeff<PropagateNaN>(&i);
        if (joint)
            *joint = i;
        return margin;
    }
```

The test program replaces the global `operator new`, so it can count every allocation made inside a window of 1000 control steps:

```cpp
// tests/test_controller.cpp:46-58
namespace {
    // Atomic: a test may allocate on a thread of its own (started with std::async, say), and unsynchronized
    // increments of a plain long from two threads would be a data race. Relaxed order is enough for a counter.
    std::atomic<long> gNewCalls{0};
}

void* operator new(std::size_t size)
{
    gNewCalls.fetch_add(1, std::memory_order_relaxed);
    if (void* p = std::malloc(size == 0 ? 1 : size))
        return p;
    throw std::bad_alloc();
}
```

The counter misses Eigen's internal allocations, which use `malloc` directly. That is why the window also calls `Eigen::internal::set_is_malloc_allowed(false)`, available because `CMakeLists.txt:39` defines `EIGEN_RUNTIME_NO_MALLOC` for every target that links `se3pf`. Its check is an assert, so it fires only in Debug builds; in Release only the `operator new` counter is active.
