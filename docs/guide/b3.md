## Online: Ψ, projection, Newton, J_Ψ

The online functions compute Ψ, the outputs (η, ξ) and J_Ψ in a few microseconds, with no heap allocation and no exceptions. Each reports failure as `false` or as NaN entries. This section goes through them in the order the controller depends on them.

### wrap: s mod L in [0, L)

`wrap` maps any arc length onto the circle R/LZ, represented by [0, L). The controller's prediction η̂ (`include/se3pf/controller.hpp:313`) and every Newton update pass through it.

```cpp
// src/tube.cpp:213-221
    double Tube::wrap(double s) const
    {
        double x = std::fmod(s, L_);  // in (-L, L)
        if (x < 0.0)
            x += L_;
        if (x >= L_)  // -1e-17 + L rounds to L
            x -= L_;
        return x;
    }
```

`std::fmod(s, L)` returns a value with the sign of s, in (−L, L). Adding L moves negative values into (0, L]. The last check handles rounding: for s = −1e-17, the sum −1e-17 + L rounds to exactly L, which is outside [0, L), so it becomes 0.

The test checks `wrap(0.0) == 0.0`, `wrap(L) == 0.0` and `wrap(-1e-17) == 0.0` exactly, `wrap(-0.1) = L − 0.1` to 1e-15, `wrap(3L + 0.2) = 0.2` to 1e-14, and 100 random values in [−10, 10].

A non-finite s passes through as NaN: `fmod` of NaN or ±∞ is NaN, and every comparison with NaN is false, so neither correction fires. `projectionCondition` then rejects it.

### frame: N(s) and N′(s)

`frame` evaluates the spline built in step 5. It is a one-line wrapper, so all the work is in `PeriodicHermite::eval`.

```cpp
// src/tube.cpp:223-228
    void Tube::frame(double s, Mat65& N, Mat65* dN) const
    {
        // A non-finite s gives NaN entries (PeriodicHermite::eval), which Psi, JPsi and the controller's allFinite
        // checks pass on: online failure is a value.
        N_.eval(s, N, dN);
    }
```

```cpp
// include/se3pf/spline.hpp:36-54
            void eval(double s, T &y, T *dy = nullptr) const
            {
                assert(n_ > 0 && "PeriodicHermite::eval before build");
                const bool finite = std::isfinite(s);
                double x = finite ? std::fmod(s, L_) : 0.0;  // in (-L, L)
                if (x < 0.0)
                    x += L_;
                int k = static_cast<int>(x / h_);
                if (k >= n_)  // rounding can land exactly on L
                    k = n_ - 1;
                const double t = finite ? x / h_ - k : std::numeric_limits<double>::quiet_NaN();
                const double t2 = t * t, t3 = t2 * t;

                y = (2 * t3 - 3 * t2 + 1) * y_[k] + ((t3 - 2 * t2 + t) * h_) * dy_[k]
                  + (-2 * t3 + 3 * t2) * y_[k + 1] + ((t3 - t2) * h_) * dy_[k + 1];
                if (dy != nullptr)
                    *dy = ((6 * t2 - 6 * t) / h_) * y_[k] + (3 * t2 - 4 * t + 1) * dy_[k]
                        + ((-6 * t2 + 6 * t) / h_) * y_[k + 1] + (3 * t2 - 2 * t) * dy_[k + 1];
            }
```

On interval k, with t = (s − s_k)/h in [0, 1), the interpolant and its derivative are the cubic Hermite formulas below. Note the 1/h in the derivative: t changes by 1 over one interval of length h.

```latex
N(s) = (2t^3 - 3t^2 + 1)\,Y_k + (t^3 - 2t^2 + t)\,h\,D_k + (-2t^3 + 3t^2)\,Y_{k+1} + (t^3 - t^2)\,h\,D_{k+1}
```

```latex
N'(s) = \tfrac{1}{h}\bigl[(6t^2 - 6t)\,Y_k + (-6t^2 + 6t)\,Y_{k+1}\bigr] + (3t^2 - 4t + 1)\,D_k + (3t^2 - 2t)\,D_{k+1}
```

At a node (t = 0) the terms with 1/h vanish and N′ = D_k exactly. So a missing 1/h shows only between the nodes, which is why the N′ test checks both (measured: such a mutation fails only the between-node part and the J_Ψ test).

The NaN handling is careful. For a non-finite s, `x` is set to 0, so the node index `k` is 0 and in range. Only the weight `t` is NaN, so every entry of N and N′ becomes NaN.

Without this, `static_cast<int>(x / h_)` with x = NaN would be undefined behaviour in C++, a float-to-int conversion out of range. Then `y_[k]` would read outside the vector; measured with the check removed, the non-finite test crashes with a segmentation fault.

The clamp `if (k >= n_) k = n_ - 1;` handles an x so close to L that x/h rounds to n. With k = n − 1 and t = 1 the formula returns node n, which `build` made equal to node 0. `dN` is a pointer so the caller can skip the derivative: `frame(s, N)` passes `nullptr` and the `if (dy != nullptr)` branch is not taken.

### Psi: the tubular map (eq:Psi)

`Psi` builds the pose at arc length s and transverse offset ξ. It goes from γ(s) along the geodesic of W with initial body velocity N(s)ξ for unit time:

```latex
\Psi(s, \xi) = \gamma(s)\,\mathrm{Exp}_I\bigl(N(s)\,\xi\bigr)
```

```cpp
// src/tube.cpp:233-239
    Pose Tube::Psi(double s, const Vec5& xi) const
    {
        Mat65 N;
        frame(s, N);
        const Vec6 e = N * xi;
        return path_.pose(s) * metric_.Exp(e);
    }
```

`N * xi` is a 6 × 5 matrix times a 5-vector, a twist in (ω, v) order. For the product metric, Exp_I(ω, v) = (exp(ω̂), v) (`src/metric.cpp:46-51`); its translation is v itself, not the screw motion's J_l(ω)v. The order of the product matters: Exp_I(Nξ)γ(s) instead of γ(s)Exp_I(Nξ) differs by 0.13 in an entry at the Panda's start pose.

`Psi(s, 0)` returns γ(s) exactly (measured error 0). N·0 is exactly zero, Exp_I(0) is exactly I (the small-angle branch of `expSO3` gives I + 0 + 0), and a product with I adds only exact zeros. The test checks it to 1e-15.

The controller never calls `Psi`. It is used offline to build start poses (`src/rigid_body_example.cpp:25`, `src/lift.cpp:313`) and by the tests and the radius estimate.

### projectionCondition: e_g, φ_g and φ_g′

`projectionCondition` evaluates the scalar function whose root is η, and its derivative for Newton's method:

```latex
g_{\mathrm{err}}(s) = \gamma(s)^{-1} g,\qquad
e_g(s) = \mathrm{Log}_I\bigl(g_{\mathrm{err}}(s)\bigr)^\vee,\qquad
\varphi_g(s) = \bigl\langle e_g(s),\, \zeta_\gamma(s)\bigr\rangle_W
```

```cpp
// src/tube.cpp:241-257
    bool Tube::projectionCondition(const Pose& g, double s, double& phi, double& dphi, Vec6& e) const
    {
        if (!std::isfinite(s))  // e.g. a NaN guess for Newton's method
            return false;
        const Pose gErr = inverse(path_.pose(s)) * g;  // g_err(s) = gamma(s)^-1 g
        if (!metric_.Log(gErr, e))
            return false;
        const Vec6 z = path_.velocity(s);
        const Vec6 dz = path_.acceleration(s);

        // e_g'(s) = -Gamma(e_g)^-1 Ad_{g_err^-1} zeta_gamma (Online stage), so
        // phi_g' = <e_g', zeta_gamma>_W + <e_g, zeta_gamma'>_W
        const Vec6 de = -(metric_.GammaInv(e) * (Ad(inverse(gErr)) * z));
        phi = metric_.inner(e, z);
        dphi = metric_.inner(de, z) + metric_.inner(e, dz);
        return std::isfinite(phi) && std::isfinite(dphi);
    }
```

The derivative φ_g′ needs e_g′. Differentiate g_err = γ⁻¹g: since γ′ = γ ζ̂_γ, we get g_err′ = −ζ̂_γ g_err.

In body coordinates of g_err that is the twist −Ad_{g_err⁻¹} ζ_γ. On the other side, g_err = Exp_I(e_g), and eq:Gamma says the body velocity of Exp_I(e(s)) is Γ(e)e′:

```latex
\Gamma(e_g)\,e_g' = -\,\mathrm{Ad}_{g_{\mathrm{err}}^{-1}}\,\zeta_\gamma
\quad\Longrightarrow\quad
e_g' = -\,\Gamma(e_g)^{-1}\,\mathrm{Ad}_{g_{\mathrm{err}}^{-1}}\,\zeta_\gamma
```

```latex
\varphi_g'(s) = \bigl\langle e_g'(s),\, \zeta_\gamma(s)\bigr\rangle_W + \bigl\langle e_g(s),\, \zeta_\gamma'(s)\bigr\rangle_W
```

Line 253 is the first formula: `metric_.GammaInv(e)` is Γ(e)⁻¹ in closed form (`src/metric.cpp:74-81`), and `Ad(inverse(gErr))` is Ad_{g_err⁻¹}. Lines 254-255 are φ and the product rule for φ′. `GammaInv` is used instead of solving with `Gamma`, because the product type has a closed form for the inverse.

On the path the formula gives the anchor the tests use. For g = γ(s): e = 0, Γ(0) = I and Ad_I = I, so e′ = −ζ_γ and φ′ = −‖ζ_γ‖²_W = −1. Measured in the test: |φ| ≤ 8.1e-18 and |φ′ + 1| ≤ 3.1e-15.

By the first variation of arc length, φ_g(s) = −(d/ds) ½ dist(γ(s), g)². A finite difference confirms it to nine digits for the Panda start pose Ψ(0.1, ξ₀): at s = 0.05 both sides give +0.048278082, at s = 0.15 both give −0.048292021.

The sign makes sense: for s below the closest point, moving s forward brings γ(s) closer to g, so the distance falls and φ_g > 0. So the roots of φ_g are the critical points of the distance along the path: φ_g′ < 0 at a local minimum and φ_g′ > 0 at a local maximum.

Failure cases, all returning `false`:

- s is not finite (line 243). This is an early exit: without it, the NaN would flow through `path_.pose(s)` into φ, and line 256 would still return `false` (measured: removing line 243 changes no test result).
- `metric_.Log` fails: the relative rotation angle is within about 1e-6 rad of π, detected as tr R < −1 + 1e-12 (`src/metric.cpp:57`). There the minimizing geodesic is not unique, so e_g does not exist.
- φ or φ′ is not finite (line 256), for example because g itself has NaN entries.

On `false`, `phi` and `dphi` may hold partial values (and `e` too, if `Log` succeeded); callers must ignore them.

The test checks φ′ against a central difference with step 1e-6 to 1e-6, on the Panda and rigid-body tubes. Measured errors are 7.1e-11 (Panda) and 1.3e-9 (rigid body). Dropping the term ⟨e_g, ζ_γ′⟩_W would change φ′ by 1.35e-2 at the Panda's start pose (and by up to 0.14 at the test's points), so the test catches it.

### newton: the private root finder

`newton` runs Newton's method on φ_g from `guess`, wrapping every iterate into [0, L):

```latex
s_{k+1} = \operatorname{wrap}\!\Bigl(s_k - \frac{\varphi_g(s_k)}{\varphi_g'(s_k)}\Bigr),\qquad \text{stop when } |\varphi_g(s_{k+1})| < 10^{-10}
```

```cpp
// src/tube.cpp:259-281
    bool Tube::newton(const Pose& g, double guess, double& eta, Vec6& e, int* iterations) const
    {
        double s = wrap(guess);
        double phi = 0.0, dphi = 0.0;
        if (!projectionCondition(g, s, phi, dphi, e))
            return false;
        // Always at least one update (Online stage), so the count is the number of updates; started from the
        // prediction of the previous control cycle, one update suffices.
        for (int k = 1; k <= 20; ++k) {
            if (std::abs(dphi) < 1e-12)
                return false;
            s = wrap(s - phi / dphi);
            if (!projectionCondition(g, s, phi, dphi, e))
                return false;
            if (std::abs(phi) < 1e-10) {
                eta = s;
                if (iterations != nullptr)
                    *iterations = k;
                return true;
            }
        }
        return false;
    }
```

The counting rule follows from the loop: the convergence test comes after each update, so Newton always makes at least one update, even at the root. `*iterations` is the number of updates, 1 to 20. Started from the controller's prediction η̂, one update is the normal case, and the controller reports it (`include/se3pf/controller.hpp:220`).

The tolerance is |φ| < 1e-10. Near the path |φ′| is about 1 (0.993 at the Panda start, 0.866 at the rigid-body start), so the error in η is about |φ|/|φ′| ≤ 1.2e-10.

The round-trip test measures 1.4e-10 in η, just at that bound (the value TICKETS.md reports). The returned `e` belongs to the returned η, because φ was evaluated at the final s.

A convergence history shows the quadratic rate (Panda start pose Ψ(0.1, ξ₀), started at 0.12):

| Update k | s_k | φ_g(s_k) | φ_g′(s_k) |
| --- | --- | --- | --- |
| 0 (start) | 0.120000000000 | −1.98e-2 | −0.9799 |
| 1 | 0.099821799454 | 1.77e-4 | −0.9930 |
| 2 | 0.100000000221 | −2.2e-10 | −0.9930 |
| 3 | 0.100000000000 | −6.6e-17 | −0.9930 |

The number of correct digits roughly doubles per update, so three updates are needed from 0.02 away. Over 2000 random poses with |ξ| < 0.06 in the Panda tube, at most 3 updates were needed from an offset of +0.02 and at most 2 from +1e-4. The rigid-body start needs 2 updates from 0.12.

Why at most 20 updates. Twenty is far more than a converging run needs, so hitting the limit means the iteration wanders. The limit bounds the worst-case time at about 20 × 0.7 µs = 14 µs (one `projectionCondition` takes 0.7 µs) and guarantees termination.

The guard |φ′| < 1e-12 stops at a stationary point of φ_g, where the Newton step φ/φ′ is meaningless. The test finds one by bisection for the Panda start pose: t* = 0.2924980917, where φ = −0.1217 and φ′ = −6.7e-16. The step there would be 1.8e14, which `wrap` would reduce to an arbitrary point of [0, L).

Why wrap inside the update. Without it, a Newton step across the seam s = 0 = L would return η outside [0, L), for example s + L. In the seam test, s = 0.01 and the guess s − 0.05 wraps to L − 0.04. Newton starts near L, and its updates must cross the seam back to 0.01.

`newton` writes `eta` and `*iterations` only on success, and only after the convergence test. On every failure path the caller's variables keep their old values.

### outputs: (η, ξ) = Ψ⁻¹(g) (Proposition 1)

`outputs` is the online entry point: Newton for η, then the transverse coordinates in the frame N(η):

```latex
\xi = N(\eta)^\top W\, e_g(\eta)
```

```cpp
// src/tube.cpp:283-297
    bool Tube::outputs(const Pose& g, double guess, double& eta, Vec5& xi, int* iterations) const
    {
        Vec6 e = Vec6::Zero();
        double s = 0.0;
        if (!newton(g, guess, s, e, iterations))
            return false;
        Mat65 N;
        frame(s, N);
        const Vec5 x = N.transpose() * metric_.flat(e);  // xi = N(eta)^T W e_g(eta) (Proposition 1(a))
        if (!x.allFinite())
            return false;
        eta = s;
        xi = x;
        return true;
    }
```

At the root, φ_g(η) = ⟨e_g, ζ_γ⟩_W = 0, so e_g(η) lies in the normal space spanned by the columns of N(η): e_g(η) = N(η)ξ. Multiplying by N(η)ᵀW and using NᵀWN = I gives ξ.

The W matters: ξ = Nᵀe without W is off by 1.89 at the Panda start. On the rigid body, where W = I, the two are bit for bit the same, because `flat` multiplies by an exact identity. Only the Panda tests can catch a missing W.

`outputs` works in the locals `s` and `x` and copies them into `eta` and `xi` only after every check passed. So on `false` the caller's `eta` and `xi` are untouched; the tests check that `eta` keeps its sentinel −1. The pointer `iterations` is passed straight to `newton`, so it is already written if Newton converged and only the `allFinite` check failed.

The check `x.allFinite()` catches a NaN that slipped through (for example from a NaN frame).

The round-trip test on the Panda tube uses 20 random poses with 0.005 ≤ |ξ| ≤ 0.06 and the guess s + 0.02. It measures η to 1.4e-10 and ξ to 4.0e-12, with 2 or 3 updates. Proposition 1(c) holds as well: |ξ| equals the minimum distance over 20 000 path samples to 3.6e-9.

### globalProject: the closest point for a start

`globalProject` finds η for a pose with no prediction available, at the start of a run. It evaluates the distance to `samples` uniform points of the path and starts Newton from the closest one.

```cpp
// src/tube.cpp:299-316
    bool Tube::globalProject(const Pose& g, double& eta, int samples) const
    {
        // Newton's method alone may converge to another root of phi_g, which is not the closest point
        // (Proposition 1(b) needs dist(g, gamma(s)) < epsilon). So start it from the closest sample.
        double best = std::numeric_limits<double>::infinity(), sBest = 0.0;
        for (int k = 0; k < samples; ++k) {
            const double s = L_ * k / samples;
            const double d = metric_.distance(path_.pose(s), g);  // NaN if Log_I fails: never the best
            if (d < best) {
                best = d;
                sBest = s;
            }
        }
        if (!std::isfinite(best))
            return false;
        Vec6 e = Vec6::Zero();
        return newton(g, sBest, eta, e, nullptr);
    }
```

Why not Newton alone. φ_g has several roots on the circle, and Newton converges to whichever basin it starts in. Started from L/2 for the two example starts Ψ(0.1, ξ₀), it converges to wrong roots:

| Start pose | Right root | Root from L/2 | φ_g′ there | ‖ξ‖ there | Updates |
| --- | --- | --- | --- | --- | --- |
| Rigid body, ‖ξ₀‖ = 0.6245 | 0.1 | 5.614286 | +1.106 | 3.465 | 3 |
| Panda, ‖ξ₀‖ = 0.031225 | 0.1 | 0.484983 | +0.993 | 0.2463 | 4 |

The positive φ_g′ shows both wrong roots are local maxima of the distance along the path. Newton cannot tell a maximum from a minimum; it only finds zeros of φ_g.

Why 720 samples: with s = σθ, uniform samples in s are uniform in the curve parameter θ, and 720 samples are one every 0.5° of θ. The spacing is L/720 = 1.07e-3 for the Panda and 1.51e-2 for the rigid body. Both are far inside the basin of the right root; for the Panda start, the stationary point t* found by the test is 0.19 away.

Each sample costs one path pose and one `Metric::distance` (an inverse, a product, a `logSO3`), so the call takes about 150 µs: fine for a start, too slow for every cycle. A NaN distance (rotation angle π) is never chosen, because `d < best` is false for NaN. If every distance is NaN, `best` stays +∞ and the function returns `false`.

`globalProject` returns η only; a caller that also needs ξ calls `outputs(g, eta, ...)`. No program in the repository calls it yet. The examples start on the known pose Ψ(0.1, ξ₀) and call `reset(0.1)` (`src/panda_example.cpp:111`, `src/rigid_body_example.cpp:82`); the comment of `Controller::reset` names `globalProject` for any other start (`include/se3pf/controller.hpp:210-212`).

The seam test also covers it. For a pose at s = L − 2e-4 the closest sample is s = 0, and Newton steps back across the seam.

### JPsi: the body Jacobian of Ψ

`JPsi` returns the 6 × 6 matrix J_Ψ with Ψ(y)⁻¹ dΨ = (J_Ψ(y) dy)^ for y = (η, ξ₁, …, ξ₅). The controller needs its inverse in A(q) (eq:A).

```latex
J_\Psi(\eta, \xi) = \Bigl[\ \mathrm{Ad}_{\mathrm{Exp}_I(N\xi)^{-1}}\,\zeta_\gamma(\eta) + \Gamma(N\xi)\,N'(\eta)\,\xi \quad\Big|\quad \Gamma(N\xi)\,N(\eta)\ \Bigr]
```

The derivation, with E = Exp_I(e) and e = N(η)ξ:

```latex
\Psi^{-1} d\Psi = E^{-1}\gamma^{-1}\bigl(d\gamma\,E + \gamma\,dE\bigr)
 = \mathrm{Ad}_{E^{-1}}\bigl(\hat\zeta_\gamma\bigr)\,d\eta + \bigl(\Gamma(e)\,de\bigr)^{\wedge},
\qquad de = N'(\eta)\,\xi\,d\eta + N(\eta)\,d\xi
```

```cpp
// src/tube.cpp:318-333
    Mat6 Tube::JPsi(double eta, const Vec5& xi) const
    {
        Mat65 N, dN;
        frame(eta, N, &dN);
        const Vec6 e = N * xi;
        const Mat6 G = metric_.Gamma(e);

        // Differentiating Psi = gamma Exp_I(N xi): moving eta moves gamma with velocity zeta_gamma, seen from the
        // pose Psi through Ad_{Exp_I(N xi)^-1}, and turns N xi at the rate N' xi, which Exp_I maps through Gamma
        // (eq:Gamma). Moving xi changes N xi only:
        //   J_Psi = [ Ad_{Exp_I(N xi)^-1} zeta_gamma + Gamma(N xi) N' xi  |  Gamma(N xi) N ]
        Mat6 J = Mat6::Zero();
        J.col(0) = Ad(inverse(metric_.Exp(e))) * path_.velocity(eta) + G * (dN * xi);
        J.rightCols<5>() = G * N;
        return J;
    }
```

Column 0 is the η direction. Moving η moves γ with body velocity ζ_γ, which the pose Ψ sees through Ad_{E⁻¹}; it also turns the offset Nξ at the rate N′ξ, which Exp_I maps through Γ. Columns 1 to 5 are the ξ directions: they change Nξ only, by the columns of N, mapped through Γ.

`J.rightCols<5>() = G * N;` writes the 6 × 5 product into the last five columns of J. `J.col(0) = ...` writes the first column. Both assign into a block of J, and neither right-hand side reads J, so aliasing cannot occur.

At ξ = 0, Γ(0) = I and Exp_I(0) = I exactly, so J_Ψ(η, 0) = [ζ_γ(η) | N(η)] with zero error (measured exactly 0; the test bound is 1e-14). Against a central difference of Ψ with step 1e-6 along a random direction, the test measures 1.6e-9 (Panda), 9.4e-11 (ℓ = 1 m) and 6.6e-10 (rigid body), within the 1e-6 bound. Dropping the term Γ(Nξ)N′ξ changes column 0 by 2.2e-2 at the Panda start, so that test catches it.

The controller never forms J_Ψ⁻¹. It solves J_Ψ X = J_b with one LU factorization:

```cpp
// include/se3pf/controller.hpp:216-226

```

### Allocation-free and no-throw by design

The online functions follow three rules, so a 1 kHz loop can call them safely.

1. No heap. Every local is a fixed-size Eigen type (`Mat65`, `Vec6`, `Mat6`, `Pose`) on the stack; no `std::vector` is created. The spline's node vectors were allocated once in the constructor and are only read.
2. No exceptions. Failure is a value: `projectionCondition`, `outputs` and `globalProject` return `false`; `frame`, `Psi` and `JPsi` return NaN entries, which the controller's `allFinite` checks catch. An exception in the control loop would take unpredictable time, and leaving the tube is an expected event to handle, not a programming error.
3. Optional outputs are pointers with a `nullptr` default (`Mat65* dN`, `int* iterations`). Passing `nullptr` skips the work, and the default keeps simple calls short.

What each function does with bad input, as the tests check it:

| Input | `frame` | `Psi` | `JPsi` | `projectionCondition` | `outputs` | `globalProject` |
| --- | --- | --- | --- | --- | --- | --- |
| s = NaN, +∞ or −∞ | NaN entries | NaN entries | NaN entries | `false` | `false`, outputs untouched | not applicable |
| pose g with a NaN entry | not applicable | not applicable | not applicable | `false` | `false`, outputs untouched | `false`, `eta` untouched |
| relative rotation angle π | not applicable | not applicable | not applicable | `false` (Log fails) | `false` if hit during Newton | that sample is skipped |
| stationary point of φ_g | not applicable | not applicable | not applicable | `true` (φ′ ≈ 0 is a value) | `false` (φ′ below 1e-12 in magnitude) | `false` if hit |
