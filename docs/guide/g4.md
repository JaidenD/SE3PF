## Rewrite-from-blank drills

A rewrite drill deletes the body of one function, keeps its signature, and asks you to write it again from the paper until one named test command passes. The twelve functions below go from a two-line helper to the whole control cycle. For each one the blank was built in a scratch copy and the judging command was run against it: the "Blank" line says what that run showed.

### How to blank a function safely

Work in the drill copy of the mutation drills (its own `git init`), never in the project. Blanking means: keep the signature line and the braces, delete everything between them, and put in a body that compiles, warns about nothing, and returns an obviously wrong value.

```cpp
// src/se3.cpp:8-12 after blanking (your edit in the drill copy, not the file's text)
    Matrix3d hat(const Vector3d &w)
    {
        (void)w;
        return Matrix3d::Constant(std::numeric_limits<double>::quiet_NaN());
    }
```

The rules, and why each one matters:

- `(void)w;` marks the parameter as used. Without it `-Wextra` warns "unused parameter", and `tools/ci.sh` builds with `-DSE3PF_WERROR=ON`, where a warning is an error.
- Return NaN, not zero. Zero is often a correct value somewhere (ξ = 0 on the path, Ȧq̇ = 0 at rest), so a zero body can pass a test by accident; NaN fails every comparison `err < tol`.
- `Constant(...)` sets every entry: a fixed-size Eigen object declared without an initializer holds garbage.
- An out-parameter gets NaN too, unless the function's contract says it stays untouched on failure. A `bool` function writes NaN into its outputs and returns `false`, the code's own failure convention; `Controller::step` is the exception, because its contract is "false, and qdd unchanged" (Drill 12).
- In a header template such as `PeriodicHermite<T>`, `T` may be `double` or an Eigen type, and `T::Constant` does not exist for `double`. Multiply a node value instead: `y = std::numeric_limits<double>::quiet_NaN() * y_[0];` works for both.
- `std::numeric_limits` is in `<limits>`; Eigen's headers already include it.

Then build and run the judging command: it must fail now. If a test still passes with the blank in place, that test does not judge your function. The verification found three kinds of such tests:

- Tests that never call the function, e.g. "PeriodicHermite::centralDifferences is fourth order" for `eval`.
- Tests of failure behaviour, which a body that always fails passes: "PeriodicHermite::eval: a non-finite s gives NaN, never an out-of-range node" passes a NaN `eval`, and "Controller: a nearly singular A (sigma_min < 1e-9) is refused, for any System" passes a `step` that always returns `false` and leaves `qdd` alone.
- Tests that accumulate errors with `std::max`: `std::max(err, NaN)` returns `err`, because `err < NaN` is false, so the NaN never reaches the check (Drill 8 below).

Write your body, run the judging command until it passes, then the whole suite (`./build/tests`), then compare with the original: `git diff` in the drill copy shows exactly where your version differs.

### Drill 1: hat and vee on R³ (se3)

Spec: `hat(w)` is the skew matrix with `hat(w) * x == w.cross(x)` for every x, and `vee` reads ω back from a skew matrix.

```latex
\hat\omega = \begin{bmatrix} 0 & -\omega_3 & \omega_2 \\ \omega_3 & 0 & -\omega_1 \\ -\omega_2 & \omega_1 & 0 \end{bmatrix},\qquad \hat\omega\,x = \omega\times x,\qquad (\hat\omega)^\vee = \omega
```

```cpp
// include/se3pf/se3.hpp:6-7
    Matrix3d hat(const Vector3d& w);
    Vector3d vee(const Matrix3d& S);    // S skew-symmetric
```

Hints:

- Eigen's comma initializer `K << a, b, c, ...;` fills row by row, whatever the storage order.
- The test requires `vee(hat(w)) == w` exactly (`maxDiff(...) == 0.0`): read the three entries S(2,1), S(0,2), S(1,0), or average two exact negatives; nothing that rounds.
- Leave the se(3) overloads at `src/se3.cpp:98-112` alone: they call these two.

Test: `./build/tests "hat*"`. Blank: both test cases fail ("hat: skew-symmetric, hat(w) x = w cross x, vee inverts it" and "hat on se(3): [hat(omega) v; 0 0], and vee inverts it"). With `hat` alone blanked, 100 of the 132 test cases fail (101 with `vee` blanked too), because everything from `expSO3` up calls `hat`: blank one function at a time.

### Drill 2: expSO3, Rodrigues' formula (se3)

Spec: the rotation by |ω| about ω/|ω|, exact at ω = 0 and accurate to 1e-14 against Eigen's `AngleAxisd`.

```latex
\exp(\hat\omega) = I + \frac{\sin\theta}{\theta}\,\hat\omega + \frac{1-\cos\theta}{\theta^2}\,\hat\omega^2,\qquad \theta = \|\omega\|;\qquad \exp(\hat\omega) \approx I + \hat\omega + \tfrac12\hat\omega^2 \quad (\theta < 10^{-8})
```

```cpp
// include/se3pf/se3.hpp:9
    Matrix3d expSO3(const Vector3d& w);
```

Hints:

- At θ = 0 the closed form is 0/0 = NaN; the test also requires `expSO3(Vector3d::Zero())` to equal I exactly, which the series branch gives.
- The series I + ω̂ + ½ω̂² has error of order θ³; at θ below 1e-8 that is below 1e-24.
- Write `const Matrix3d K = hat(w);`, with the type, not `auto`: `auto K2 = K * K;` would store an unevaluated product expression, not a matrix.

Test: `./build/tests "expSO3*,logSO3*,Jr is*"`. Blank: all three fail ("expSO3: a rotation, agrees with Eigen, turns the right way, exp(0) = I", "logSO3 inverts expSO3, including tiny angles and angles near pi", "Jr is the derivative of expSO3; JrInv inverts it").

### Drill 3: Metric::Gamma, the derivative of Exp_I (metric, eq:Gamma)

Spec: Γ(ζ) maps a change δ of ζ to the body velocity of Exp_I(ζ): (Exp_I(ζ)⁻¹ D Exp_I(ζ)[δ])^∨ = Γ(ζ) δ. For the product metric, Exp_I(ζ) = (exp ω̂, v) (Example 1).

```latex
\Gamma(\zeta) = \begin{bmatrix} J_r(\omega) & 0 \\ 0 & \exp(\hat\omega)^\top \end{bmatrix},\qquad \zeta = (\omega, v)
```

```cpp
// include/se3pf/metric.hpp:24-25
            Mat6 Gamma(const Vec6& z) const;                        // derivative of Exp_I (eq:Gamma)
            Mat6 GammaInv(const Vec6& z) const;
```

Hints:

- Derive the lower block yourself: with g = (R, p) and p = v, the body velocity is (RᵀṘ, Rᵀṗ) = (J_r(ω) δω, Rᵀ δv). It is not I. Nor does J_l(ω) appear: J_l(ω) v is the translation of the screw exponential (Remark 1), which Exp_I is not.
- `Jr` is in se3; blocks are set with `G.block<3,3>(row, col) = ...;` on a `Mat6::Zero()`.
- Do not touch `GammaInv`: the test checks GammaInv·Gamma = I against your Γ.

Test: `./build/tests "Gamma is the derivative*"`. Blank: "Gamma is the derivative of Exp_I (eq:Gamma); GammaInv inverts it" fails.

### Drill 4: PeriodicHermite::eval (spline)

Spec: on interval k of the uniform grid (h = L/n, t = (s − s_k)/h in [0, 1)), return the cubic Hermite interpolant of the node values and node derivatives, and, if `dy` is not null, its derivative with respect to s.

```latex
y(s) = (2t^3 - 3t^2 + 1)\,y_k + (t^3 - 2t^2 + t)\,h\,y_k' + (-2t^3 + 3t^2)\,y_{k+1} + (t^3 - t^2)\,h\,y_{k+1}'
```

```latex
y'(s) = \frac{6t^2 - 6t}{h}\,y_k + (3t^2 - 4t + 1)\,y_k' + \frac{-6t^2 + 6t}{h}\,y_{k+1} + (3t^2 - 2t)\,y_{k+1}'
```

```cpp
// include/se3pf/spline.hpp:34-37
            // y = interpolant at s; if dy is not null, *dy = its derivative with respect to s. Online: no allocation,
            // no exceptions. A non-finite s gives NaN in every entry of y and *dy (the weights below are NaN), never
            // an out-of-range node index. Call build first (checked by an assert in Debug builds).
            void eval(double s, T &y, T *dy = nullptr) const
```

Hints:

- Wrap s into [0, L): `std::fmod` keeps the sign of s, so add L to a negative result.
- Clamp k to n − 1: mutation drill 6 shows that a tiny negative s, and the largest double below L for about 10 % of (L, n) pairs, give k = n otherwise.
- A NaN or infinite s must not reach `static_cast<int>`: converting NaN to int is undefined behaviour. Compute k from a safe x and make t NaN instead.
- `T` may be `double`: write `weight * y_[k]`, never `y_[k].something()`.
- The 1/h belongs only to the value terms of y′ (mutation drill 4 removes it from the first one).

Test: `./build/tests "PeriodicHermite*,Tube: N'*,Lift: q*' between*"`. Blank: 4 fail ("PeriodicHermite: fourth-order values, third-order derivatives", "PeriodicHermite: closes exactly, wraps s, works for Eigen types", "Tube: N' agrees with central differences of N (eq:frame-ode)", "Lift: q*' between the nodes is the derivative of the interpolant; eval wraps and rejects NaN"); 3 pass even blank, as explained above. A correct body must keep the NaN test passing too.

### Drill 5: ConingCircle::velocity and acceleration (path)

Spec: with θ = s/σ, return the unit-speed body velocity ζ_γ(s) and its s-derivative ζ_γ′(s), from the θ-curve R(θ) = R₀ R_z(θ) A R_z(−θ), p(θ) = c + r(cos θ, sin θ, 0).

```latex
\zeta_\gamma(s) = \frac{1}{\sigma}\begin{bmatrix} R_z(\theta)\,w_0 \\ R(\theta)^\top p'(\theta) \end{bmatrix},\qquad \zeta_\gamma'(s) = \frac{1}{\sigma^2}\begin{bmatrix} R_z(\theta)\,(e_3\times w_0) \\ R^\top p'' - \tilde\omega\times\tilde v \end{bmatrix},\qquad w_0 = A^\top e_3 - e_3
```

```cpp
// include/se3pf/path.hpp:24-32
            Vec6 velocity(double s) const override;
            Vec6 acceleration(double s) const override;

        private:
            Matrix3d attitude(double th) const;   // R(theta), shared by the three functions above
            Matrix3d R0_, A_;
            Vector3d c_, w0_;                     // w0 = A^T e3 - e3
            double r_;
            double sigma_;                        // constant speed in the metric: s = sigma * theta
```

Hints:

- p′ = r(−sin θ, cos θ, 0) and p″ = −r(cos θ, sin θ, 0); ω̃ and ṽ are the θ-velocities before dividing by σ.
- The −ω̃ × ṽ term is the derivative of Rᵀ: R′ = R hat(ω̃) gives d(Rᵀ)/dθ = −hat(ω̃) Rᵀ. Mutation drill 3 shows what happens without the right sign.
- `Rz` and `twist` are helpers in the anonymous namespace of `src/path.cpp:10-39`; you may use them.

Test: `./build/tests "coning circle*"`. Blank: both fail ("coning circle (Panda example, l = 0.1 m): reference values" and "coning circle: unit speed, consistent derivatives, closed").

### Drill 6: kernelVector, the generalized cross product (lift, Lemma 3)

Spec: for a 6 × 7 Jacobian of rank 6, the unit vector spanning its kernel, with the orientation det([xᵀ; J_b]) > 0; NaN if the rank is below 6.

```latex
n_j = (-1)^j \det\bigl(J_b \text{ without column } j\bigr),\quad j = 0, \dots, 6,\qquad x = \frac{n}{\|n\|},\qquad w^\top n = \det\begin{bmatrix} w^\top \\ J_b \end{bmatrix}
```

```cpp
// include/se3pf/lift.hpp:22
    Vec7 kernelVector(const Mat67& Jb);
```

Hints:

- Build each minor in a fixed-size `Mat6`: `M.leftCols(j) = Jb.leftCols(j); M.rightCols(6 - j) = Jb.rightCols(6 - j);` (run-time sizes, no allocation).
- Zero-based j: the sign is + for j = 0. The hand-made test expects J_b = [I | 0], whose rows are e₁…e₆, to give +e₇.
- Do not normalize away the NaN: for rank 5, n = 0 and n/|n| is NaN on purpose (the test checks it).

Test: `./build/tests "kernelVector*"`. Blank: both fail ("kernelVector: the orientation of the cross product on hand-made matrices", "kernelVector: a unit vector of ker J_b with the orientation of the generalized cross product").

### Drill 7: LiftRedundancy::evaluate (lift, eq:beta-flat, eq:dbeta)

Spec: β is the signed distance from the lift along the self-motion direction, and dβ its differential, where η itself depends on q through dη (row 0 of J_Ψ⁻¹J_b, passed in as `deta`).

```latex
\beta(q) = X(\eta)^\top\bigl(q - q^\star(\eta)\bigr),\qquad \mathrm d\beta(q) = X(\eta)^\top + \Bigl(X'(\eta)^\top\bigl(q - q^\star(\eta)\bigr) - X(\eta)^\top q^{\star\prime}(\eta)\Bigr)\,\mathrm d\eta(q)
```

```cpp
// include/se3pf/lift.hpp:134
            void evaluate(const Vec7& q, double eta, const Vec7& deta, double& beta, Vec7& dbeta) const override;
```

Hints:

- `lift_.eval(eta, qs, &dqs)` gives q* and q*′; `kernel_.eval(eta, X, &dX)` gives X and X′.
- dβ is a row; the code stores it as a `Vec7` column, so the bracket is a scalar times `deta`.
- On the lift the X′ term vanishes (q = q*), so check your sign with the off-lift test (mutation drill 16).
- The controller calls this every millisecond: fixed-size locals only, nothing that can throw.

Test: `./build/tests "LiftRedundancy*"`. Blank: both fail ("LiftRedundancy: beta = 0 and dbeta X = +1 on the lift", "LiftRedundancy: dbeta against a central difference of beta off the lift").

### Drill 8: RigidBody::integrate, RK4 on SE(3) (rigid body)

Spec: one RK4 step of length h with the wrench u held, for the attitude in exponential coordinates around the step's starting attitude R_k, so that R stays a rotation exactly.

```latex
R = R_k\exp(\hat\varphi),\quad \dot\varphi = J_r(\varphi)^{-1}\omega,\quad \dot p = R\,v,\quad \dot\zeta = M^{-1}\bigl(u - C(\zeta)\zeta\bigr),\qquad \varphi(0) = 0
```

```cpp
// include/se3pf/rigid_body.hpp:34-35
            // One RK4 step of length h with u held constant; updates g and zeta in place. R stays in SO(3).
            void integrate(Pose& g, Vec6& zeta, const Vec6& u, double h) const;
```

Hints:

- RK4 updates (φ, p, ζ), which live in vector spaces; build R = R_k exp(φ̂) once at the end. Adding increments to R directly would leave SO(3).
- In each stage, ṗ uses that stage's attitude R_k exp(φ̂_stage), not R_k (the closed-form test catches R_k: 6.4e-4 off).
- `acceleration(z, u)` already solves M ζ̇ = u − Cζ; `JrInv` is in se3. A small struct of the three rates per stage keeps the four stages readable.

Test: `./build/tests "RigidBody::integrate*"`. Blank: only "RigidBody::integrate with a constant input: force and torque enter with the right sign and scale" fails. The two others pass a NaN body: their errors are accumulated with `std::max`, which never takes the NaN. A no-op body (g and ζ unchanged) was tried too: then the closed-form test fails as well, but "free motion: energy and momenta conserved" still passes, since a body that does not move conserves everything. Your rewrite must pass all three.

### Drill 9: Tube::projectionCondition (tube, Proposition 1)

Spec: at a candidate foot point s, the error twist e_g(s), the projection condition φ_g(s) and its exact derivative, the function whose root Newton's method finds.

```latex
g_\mathrm{err} = \gamma(s)^{-1}g,\quad e_g(s) = \mathrm{Log}_I(g_\mathrm{err})^\vee,\quad \varphi_g(s) = \langle e_g, \zeta_\gamma\rangle_W,\quad \varphi_g'(s) = \langle e_g', \zeta_\gamma\rangle_W + \langle e_g, \zeta_\gamma'\rangle_W,\quad e_g' = -\Gamma(e_g)^{-1}\mathrm{Ad}_{g_\mathrm{err}^{-1}}\zeta_\gamma
```

```cpp
// include/se3pf/tube.hpp:73-75
            // e = e_g(s) = Log_I(gamma(s)^-1 g) (eq:projection-error), phi = phi_g(s) = <e, zeta_gamma(s)>_W
            // (eq:projection-condition) and dphi = phi_g'(s). False if Log_I fails or a value is not finite.
            bool projectionCondition(const Pose& g, double s, double& phi, double& dphi, Vec6& e) const;
```

Hints:

- First line: return `false` for a non-finite s. Newton may hand you a NaN guess, and the path would compute NaN poses.
- `metric_.Log` returns `false` at a rotation by π: pass that on.
- Use `metric_.GammaInv(e)`, never `metric_.Gamma(e).inverse()`, and `inverse(gErr)` (closed form), not `gErr.inverse()`.
- On the path, e = 0 and φ′ = −‖ζ_γ‖²_W = −1: the test checks that to 1e-9.

### Drill 12: Controller::step, one cycle of Algorithm 1 (controller)

Spec: one control cycle. Project from the prediction η̂, form ȳ̇ = A q̇ and Ȧq̇, build μ from the gains and the reference, solve q̈* = A⁻¹(μ − Ȧq̇), predict η̂ for the next cycle and fill `Status`.

```latex
\mu_\parallel = \partial_t\nu_d + \partial_\eta\nu_d\,\dot\eta - k_t(\dot\eta - \nu_d)\ \text{or}\ \ddot\eta_d - k_d(\dot\eta - \dot\eta_d) - k_p e_\eta,\qquad \mu_\pitchfork = -K_p\xi - K_d\dot\xi,\qquad \mu_\beta = -K_{p,\beta}\beta - K_{d,\beta}\dot\beta
```

```latex
\dot A\dot q \approx \frac{\bigl(A(c(h)) - A(c(-h))\bigr)\dot q}{2h},\quad h = 10^{-5},\qquad \ddot q^\star = A^{-1}\bigl(r(t/T)\,\mu - \dot A\dot q\bigr),\qquad \hat\eta \leftarrow (\eta + \dot\eta\,\Delta t) \bmod L
```

```cpp
// include/se3pf/controller.hpp:243-246
            // One control cycle (Algorithm 1) at time t with period dt: qdd receives qdd* = A^-1 (mu - Adot qdot).
            // False (and qdd unchanged) if the projection fails, A is nearly singular (sigma_min(A) < 1e-9) or a
            // result is not finite; a simulation then stops, the robot driver damps the arm to rest.
            bool step(const Config& q, const VecN& dq, double t, double dt, VecN& qdd, Status& st)
```

Hints:

- `st = Status();` first: one test puts garbage into `st` before the call (`st.ok = true`, `st.etaDot = st.beta = 1e300`) and checks that the step replaced it; for n = 6 nothing else ever writes `st.beta`.
- The two extra projections start from the η just found, not from η̂; skip them at rest but set Ȧq̇ to `VecN::Zero()`.
- e_η is `wrapSymmetric(eta - etaD, L)`: η_d is real-valued and may be loops away.
- The ramp multiplies μ only (mutation drill 19).
- Check σ_min(A) with `Eigen::JacobiSVD<MatN>(out.A).singularValues().minCoeff()` and refuse it with `if (!(sigmaMin >= 1e-9))`, which also refuses NaN. LU alone returns huge finite values for a nearly singular A.
- Write `qdd` only after every check has passed; no heap: no `MatrixXd`, no `std::vector`, no copies of the `std::function` (calling it is fine).

Test: `./build/tests "Controller*,simulate*"`. Blank (a body that sets `st = Status();`, leaves `qdd` untouched and returns `false`): 23 of 33 fail, all 14 closed loops among them; the 10 that pass test `outputs`, construction, `reset` and failure handling. A blank that writes NaN into `qdd` fails 25, because it breaks the contract "qdd unchanged" that "failure is false, not an exception, and leaves qdd unchanged" and the nearly-singular test check.
