## The mental model

The code computes, from the measured state (q, q̇), the acceleration q̈* that makes the outputs ȳ = (η, ξ, β) obey ȳ̈ = μ (β exists only for the Panda; the rigid body has ȳ = (η, ξ)). Everything expensive is computed once, before the first control cycle. Read it as two programs that share data: an offline builder that turns a closed path into splines, and a 1 kHz step that evaluates them.

### Offline: before the first control cycle

The `PandaExample` constructor (`src/panda_example.cpp:32`) runs the whole offline stage in about 25 ms in Release on an idle Ryzen 5 5600G. In order:

1. Metric. `Metric::product(0.01, 1.0)` (`src/metric.cpp:22`) builds W = diag(0.01 I, I), so l = 0.1 m. The constructor (`src/metric.cpp:12`) throws for any W not of the form diag(w_R I, w_p I), because Exp_I, Log_I and Γ are the closed forms of Example 1.
2. Path. `ConingCircle` (`src/path.cpp:45`) is γ in closed form in the curve parameter θ. `constantSpeed` (`src/path.cpp:29`) checks that |ζ̃(θ)|_W is the same, to a relative 1e-12, at 16 values of θ (it throws otherwise) and returns σ = 0.12256326. So s = σθ and L = 2πσ = 0.77008765.
3. Tube. `Tube::Tube` (`src/tube.cpp:154`) builds N₀(0) by Gram–Schmidt (`initialFrame`, `src/tube.cpp:34`) and transports it by RK4 on 2000 intervals (`transportRate`, `src/tube.cpp:23`). Then H = N₀(0)ᵀ W N₀(L) is projected onto SO(5) by an SVD. Φ = log H comes from its two rotation planes (0.161182 and 8.0e-5 rad). Finally N(s_k) = N₀(s_k) exp(−(s_k/L)Φ), with N′ from eq:frame-ode, at 2001 nodes. Both go into `PeriodicHermite<Mat65> N_`.
4. Lift. `Lift::Lift` (`src/lift.cpp:142`) solves for q*(s_k) at the 2001 nodes by projected Newton steps, each node started from the previous one. It checks closure (1.5e-13 rad), takes q*′ by fourth-order central differences and stores both in `PeriodicHermite<Vec7> q_`.
5. Kernel frame. `KernelFrame::KernelFrame` (`src/lift.cpp:243`) sets X(s_k) = `kernelVector(J_b(q*(s_k)))`, the normalized generalized cross product, and stores X and X′ the same way.
6. Redundancy output. `LiftRedundancy` (`include/se3pf/lift.hpp:127`) only stores references to the lift and the kernel frame; it evaluates β = X(η)ᵀ(q − q*(η)) on demand.
7. Starts. `startConfiguration` (`src/lift.cpp:306`) solves FK(q) = Ψ(0.1, ξ₀) together with the hyperplane X(0.1)ᵀ(q − q*(0.1)) = 0, which is β(q) = 0 because η = 0.1 there. `constrainedIK` needs 5 Newton updates; the self-motion start takes 4.

### Online: every control period

`Controller<System>::step` (`include/se3pf/controller.hpp:246`) is Algorithm 1. Each line below names what is computed, then the code that does it. The numbers are this guide's: the comments in the code use the paper's, with steps 1 to 6 and the first part of step 7 inside `outputs`, step 7 (continued) for Ȧq̇, step 8 for μ, and step 9 for q̈* and the prediction.

1. g = Π(q) and J_b(q): `System::output(q, &Jb)`, for the Panda `PandaArm::output` (`src/panda.cpp:34`).
2. (η, ξ) = Ψ⁻¹(g): `Tube::outputs` (`src/tube.cpp:283`), Newton's method on φ_g started at the prediction η̂, then ξ = N(η)ᵀ W e_g(η).
3. J_Ψ(η, ξ): `Tube::JPsi` (`src/tube.cpp:318`).
4. [dη; dξ] = J_Ψ⁻¹ J_b: one LU factorization of J_Ψ (`include/se3pf/controller.hpp:226`).
5. β and dβ: `RedundancyOutput::evaluate` (Panda only), which needs dη from step 4.
6. ȳ̇ = A q̇ (`include/se3pf/controller.hpp:256`), with A = [J_Ψ⁻¹ J_b; dβ] filled by steps 4 and 5.
7. Ȧq̇ by a central difference: steps 1 to 5 again at retract(q, q̇, ±1e-5), skipped when q̇ = 0.
8. μ from the gains and the tangential reference (`include/se3pf/controller.hpp:273-296`).
9. Refuse a nearly singular A (σ_min < 1e-9), then q̈* = A⁻¹(μ − Ȧq̇) by LU.
10. Prediction for the next cycle: η̂ = (η + η̇ Δt) mod L.

Steps 1 to 5, which fill A, are the function `Controller::outputs` (`include/se3pf/controller.hpp:216`). A moving step runs it three times and a step at rest once.

### Controller versus dynamics

The controller is purely kinematic: it returns q̈*, never a torque. It needs only Π, J_b and a curve through q (`retract`). So one class serves the rigid body, the Panda simulation, MuJoCo and later the robot.

```cpp
// include/se3pf/controller.hpp:302-310
                // Step 9 (the controller's part of eq:fb): qdd* = A^-1 (mu - Adot qdot). The LU factorization does
                // not see rank loss (a nearly singular A gives huge but finite values), so check sigma_min first.
                const double sigmaMin = Eigen::JacobiSVD<MatN>(out.A).singularValues().minCoeff();
                if (!(sigmaMin >= 1e-9))  // also NaN
                    return false;
                const VecN result = out.A.partialPivLu().solve(mu - Adq);
                if (!result.allFinite())
                    return false;
                qdd = result;
```

Each caller finishes eq:fb in its own way. The Panda simulation assumes an exact model, so q̈ = q̈*, and integrates the held acceleration exactly:

```cpp
// src/panda_example.cpp:196-198
            // The arm moves with qdd* held over [t, t + dt): exact for a constant acceleration.
            q += dt * qd + (0.5 * dt * dt) * qdd;
            qd += dt * qdd;
```

The rigid-body simulation holds the wrench u = M q̈* + Cζ (G = 0) for 2 ms, while `RigidBody::integrate` takes 4 RK4 substeps:

```cpp
// src/rigid_body_example.cpp:102-103
            // eq:fb with G = 0, held over [t, t + dt) (zero-order hold)
            const Vec6 u = M * qdd + body.coriolis(zeta);
```

The MuJoCo layer computes τ = M q̈* + C q̇ + G − f_passive, where f_passive = −D q̇ is the joint damping, with MuJoCo's own model (`MujocoPanda::exactStep`, `sim/mujoco_panda.cpp:211`). For the robot, the design doc plans τ = M q̈* + C q̇ with M and C from franka::Model, because the robot adds G itself; that driver is not in this repository yet. Because the controller never sees M, the tests can check A q̈* + Ȧq̇ = μ without any plant.

### Sizes of every object

All online objects have sizes fixed at compile time, so nothing in a step touches the heap. Below, n is 7 for the Panda and 6 for the rigid body. Inside `Controller`, `VecN` and `MatN` are `Vec<n>` and `Mat<n, n>`.

| Object | Paper | C++ type | Shape (Panda / rigid body) |
| --- | --- | --- | --- |
| configuration | q | `Config` = `Vec7` / `Pose` | 7 / 4 × 4 |
| velocity, acceleration, μ, Ȧq̇, ȳ̇ | q̇, q̈*, μ | `VecN` | 7 / 6 |
| pose, path point, tubular map | g, γ(s), Ψ(s, ξ) | `Pose` (= `Eigen::Matrix4d`) | 4 × 4 |
| body Jacobian | J_b | `Mat67` / `Mat6` | 6 × 7 / 6 × 6 (identity) |
| twists, pose error, path tangent | ζ, e_g, ζ_γ, ζ_γ′ | `Vec6` | 6 |
| tangential output, projection condition, redundancy | η, φ_g, φ_g′, β | `double` | 1 |
| transverse output and rate | ξ, ξ̇ | `Vec5` | 5 |
| normal frame and derivative | N, N′ | `Mat65` | 6 × 5 |
| holonomy and its logarithm | H, Φ | `Mat5` | 5 × 5 |
| metric, J_Ψ, Γ, Ad, ad | W, J_Ψ | `Mat6` | 6 × 6 |
| J_Ψ⁻¹ J_b (`top`) | rows dη, dξ | `Mat<6, n>` | 6 × 7 / 6 × 6 |
| lift, kernel frame, rest posture, dη, dβ | q*, q*′, X, X′, q_r | `Vec7` | 7 |
| decoupling matrix | A(q) | `MatN` | 7 × 7 / 6 × 6 |
| spline of N | N(s_k), N′(s_k) | `PeriodicHermite<Mat65>` | 2 × 2001 nodes, 0.96 MB on the heap |
| splines of q*, X | q*(s_k), X(s_k) | `PeriodicHermite<Vec7>` | 2 × 2001 nodes, 224 kB each |

The lift also keeps a plain copy of its node values (`Lift::nodes_`, 112 kB), which `KernelFrame` and `minimumCheck` read.

A `Controller<PandaArm>::OutputState` is 456 bytes and a `Status` 160 bytes, measured with `sizeof`. A moving step keeps three `OutputState`s (`out`, `plus`, `minus`) on the stack.

The units of ξ and η are those of W. N's columns are W-orthonormal, so a column that is pure rotation has |ω| = 1/l = 10 rad per unit.

At s = 0.1 the first three columns of N have Euclidean norms 9.9, 9.8 and 10.0, almost all of it rotation (|ω| = 9.87, 9.78 and 10.0). So ξ₁ = 0.02 on its own is about 0.2 rad of rotation.
