## What the tube does

The tube turns a pose g into the outputs (η, ξ) of Proposition 1. Offline it builds the periodic normal frame N(s) once; online it projects g onto the path and evaluates the body Jacobian J_Ψ. Everything lives in `include/se3pf/tube.hpp` (117 lines) and `src/tube.cpp` (434 lines).

### Offline and online

The work is split by when it runs. The split decides which functions may allocate memory or throw exceptions, and which must not.

| Stage | Functions | Runs | Cost (Release, measured) | Failure |
| --- | --- | --- | --- | --- |
| Offline | `Tube::Tube` (the five steps of Lemma 1) | once, before the first control cycle | 5.1 ms (Panda, ℓ = 0.1 m and ℓ = 1 m), 3.8 ms (rigid body) | throws |
| Offline | `estimateTubeRadius` | once, for the paper's numbers | 0.5 to 0.8 s | throws on bad options |
| Start only | `globalProject` | once per run, to find the first η | 150 µs (720 distance evaluations) | returns `false` |
| Online | `wrap`, `outputs`, `JPsi` (called by the controller every 1 kHz cycle); `frame`, `projectionCondition` (called inside them); `Psi` (online-safe, used offline for start poses) | every control cycle | `outputs` 1.5 µs, `JPsi` 0.5 µs, `Psi` 0.2 µs, `frame` with N′ 0.05 µs | returns `false` or NaN entries |

The controller calls `outputs` and then `JPsi` three times per step: at q and at the two points of the central difference for Ȧq̇ (`include/se3pf/controller.hpp:220`, `include/se3pf/controller.hpp:225`, `include/se3pf/controller.hpp:254`, `include/se3pf/controller.hpp:266-267`). At rest (q̇ = 0) the difference is skipped and it calls them once. The hidden timing test measures one `outputs` plus one `JPsi` at about 2 µs (1.6 to 2.0 µs over several runs), so the tube costs about 6 µs of a control step.

The types come from `include/se3pf/types.hpp`. `Vec5` and `Vec6` are columns of 5 and 6 doubles, `Mat5` is 5 × 5, and `Mat65` is 6 × 5, the shape of N. `Pose` is a 4 × 4 homogeneous matrix (`Eigen::Matrix4d`).

All are fixed-size Eigen types: their entries are stored inside the object, so a local variable of these types lives on the stack and never touches the heap.

### The public interface

The class declaration is short. Read it once in full before the details.

```cpp
// include/se3pf/tube.hpp:52-75
    class Tube {
        public:
            // Builds N(s) on gridIntervals uniform intervals; throws std::runtime_error if the construction fails.
            Tube(const Path& path, const Metric& metric, int gridIntervals = 2000);
            Tube(const Path&& path, const Metric& metric, int gridIntervals = 2000) = delete;  // no temporaries

            double length() const { return L_; }
            int gridIntervals() const { return n_; }
            const Path& path() const { return path_; }
            const Metric& metric() const { return metric_; }
            const TubeDiagnostics& diagnostics() const { return diag_; }

            double wrap(double s) const;  // s mod L, in [0, L)

            // N(s) (Lemma 1) and, if dN is not null, N'(s), by cubic Hermite interpolation of the node values.
            // A non-finite s gives NaN entries, so Psi and JPsi return NaN too (the caller checks allFinite).
            void frame(double s, Mat65& N, Mat65* dN = nullptr) const;

            // Psi(s, xi) = gamma(s) Exp_I(N(s) xi) (eq:Psi)
            Pose Psi(double s, const Vec5& xi) const;

            // e = e_g(s) = Log_I(gamma(s)^-1 g) (eq:projection-error), phi = phi_g(s) = <e, zeta_gamma(s)>_W
            // (eq:projection-condition) and dphi = phi_g'(s). False if Log_I fails or a value is not finite.
            bool projectionCondition(const Pose& g, double s, double& phi, double& dphi, Vec6& e) const;
```

```cpp
// include/se3pf/tube.hpp:77-99
            // (eta, xi) = Psi^-1(g) (Proposition 1): eta by Newton's method on phi_g from s = guess, then

            // Newton's method on phi_g (Online stage); e receives e_g(eta).
            bool newton(const Pose& g, double guess, double& eta, Vec6& e, int* iterations) const;
```

### TubeDiagnostics

`TubeDiagnostics` records what the construction of the normal frame found. The constructor fills it once (`src/tube.cpp:178-208`), and the tests read it by field name.

```cpp
// include/se3pf/tube.hpp:36-45

    struct TubeDiagnostics {
        int planes = 0;                              // rotation planes of H (two for both example paths)
        std::array<double, 2> angles = {0.0, 0.0};   // their rotation angles, largest first (0 if absent)
        double detH = 0.0;                           // det H
        double orthogonalityError = 0.0;             // max |H^T H - I|, before projecting H onto SO(5)
        double logError = 0.0;                       // max |exp(Phi) - H_r|, H_r the nearest rotation to H
        double skewError = 0.0;                      // max |Phi + Phi^T|
        double closureGap = 0.0;                     // max |N(s_n) - N(s_0)| on the node values (s_n = L)
    };
```

| Field | Panda, ℓ = 0.1 m | Panda, ℓ = 1 m | Rigid body | Test bound |

| `skewError` | 0 | 0 | 0 | 1e-12 |
| `closureGap` | 3.7e-11 | 1.1e-11 | 4.6e-12 | 1e-9 |

`skewError` is exactly zero, not merely small. Entry (j, k) of θ(v uᵀ − u vᵀ) is θ(v_j u_k − u_j v_k) and entry (k, j) is θ(v_k u_j − u_k v_j). Floating-point multiplication is commutative and fl(a − b) = −fl(b − a), so the two entries are exact negatives and Φ is antisymmetric bit for bit.

This holds because the build does not fuse a multiply and a subtraction into one FMA instruction (the Release flags are `-O3 -DNDEBUG`, no `-march`). With fused operations the symmetry could break at the rounding level, still far inside the test bound of 1e-12.

### RotationPlanes

`RotationPlanes` stores a rotation H of R⁵ as rotations in at most two orthogonal planes. It is how the tube takes the logarithm Φ of the holonomy and evaluates exp(−(s/L)Φ) at every node.

```cpp
// include/se3pf/tube.hpp:19-27
    struct RotationPlanes {
        int count = 0;  // number of planes, 0 to 2
        std::array<Vec5, 2> u = {Vec5::Zero(), Vec5::Zero()};
        std::array<Vec5, 2> v = {Vec5::Zero(), Vec5::Zero()};
        std::array<double, 2> theta = {0.0, 0.0};  // angles in (0, pi], largest first

        Mat5 log() const;          // Phi = log H, skew-symmetric
        Mat5 exp(double t) const;  // exp(t Phi)
    };
```

Plane i is spanned by the orthonormal pair (u_i, v_i), and H turns u_i towards v_i by the angle θ_i. On the remaining directions H is the identity. In formulas:

```latex
H u_i = \cos\theta_i\, u_i + \sin\theta_i\, v_i,\qquad H v_i = -\sin\theta_i\, u_i + \cos\theta_i\, v_i
```

```latex
\Phi = \log H = \sum_{i} \theta_i\,\bigl(v_i u_i^\top - u_i v_i^\top\bigr),\qquad
e^{t\Phi} = I + \sum_{i}\Bigl[(\cos t\theta_i - 1)\bigl(u_i u_i^\top + v_i v_i^\top\bigr) + \sin t\theta_i\,\bigl(v_i u_i^\top - u_i v_i^\top\bigr)\Bigr]
```

Check the sign once by hand: Φu = θ v(uᵀu) − θ u(vᵀu) = θ v, and Φv = −θ u. So Φ acts on (u, v) as θ times the 2 × 2 matrix [0 −1; 1 0], and exp(Φ)u = cos θ u + sin θ v, as required.

```cpp
// src/tube.cpp:61-78
    Mat5 RotationPlanes::log() const
    {
        Mat5 Phi = Mat5::Zero();
        for (int i = 0; i < count; ++i)
            Phi += theta[i] * (v[i] * u[i].transpose() - u[i] * v[i].transpose());
        return Phi;
    }

    Mat5 RotationPlanes::exp(double t) const
    {
        Mat5 E = Mat5::Identity();
        for (int i = 0; i < count; ++i) {
            const double c = std::cos(t * theta[i]), s = std::sin(t * theta[i]);
            E += (c - 1.0) * (u[i] * u[i].transpose() + v[i] * v[i].transpose())
               + s * (v[i] * u[i].transpose() - u[i] * v[i].transpose());
        }
        return E;
    }
```

The two members implement these two formulas term by term. Note that `exp(t)` does not call `log()`: both are built from the same (u_i, v_i, θ_i), so a bug in one does not show in the other. `exp(t)` costs one `cos` and one `sin` per plane and no matrix exponential, which is why step 5 can afford it at all 2001 nodes.

`exp(t)` is a one-parameter group. The test checks exp(0.3)exp(0.7) = exp(1.0) (bound 1e-14, measured 2.2e-16) and exp(−0.4) = exp(0.4)ᵀ (bound 1e-15, measured 0).

Why at most two planes: R⁵ splits into invariant planes and fixed lines, and 5 = 2 + 2 + 1. So a rotation of R⁵ has at most two planes and at least one fixed direction. Both example holonomies use both planes (`planes == 2`).

`count` says how many entries of the arrays are valid. The unused entries stay at their zero defaults, so `log()` and `exp()` loop only up to `count`. `rotationPlanes(H)`, the function that fills the struct, is explained with step 4 of the constructor in the next section.
