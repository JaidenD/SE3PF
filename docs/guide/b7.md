## Check yourself

These questions test whether you could have written the tube yourself. Answer each one from memory first, then check the answers below and the cited lines.

1. In `initialFrame`, which unit vector drops out for the rigid-body path and which for the Panda path, and why does the Panda's first column of N(0) equal 10 e₁?
2. Why does the constructor measure `closureGap` on `Y` before `N_.build`, and what would `frame(L)` return if you measured it there instead?
3. The Panda's holonomy has a second plane with θ = 8.0e-5. What closure gap results if that plane is dropped, and which tests fail?
4. Why is the fixed-direction threshold in `rotationPlanes` `1 - lambda(k) < 1e-12`? What happens with 1e-8, and what with 0?
5. Why does step 4 replace H by UVᵀ before taking the logarithm, and what does `logError` measure as a result?
6. Why is the transport integrated with exactly one RK4 step per grid interval, and what order of convergence does the closure gap show?
7. Derive φ_g′(s) = −1 for a pose g = γ(s) on the path, starting from the formula in `projectionCondition`.
8. Newton is started exactly at the root. What does `*iterations` hold, and why?
9. Why does `outputs` compute ξ as N(η)ᵀ W e_g(η) and not N(η)ᵀ e_g(η)? Which tube's tests would catch the missing W?
10. Started from L/2, Newton returns η = 5.614 for the rigid-body start pose. Is that a minimum or a maximum of the distance along the path, and how can you tell from the code's numbers?
11. Why does J_Ψ(η, 0) equal [ζ_γ(η) N(η)] with an error of exactly zero?
12. What does `Tube t(TumblingCircle(1.0, W), W);` do, and why does the deleted constructor need the default argument `= 2000`?
13. Without the lower-bound prefilter in `radiusPasses`, the rigid-body estimate is 0.149 instead of 1.93. Explain the mechanism.
14. Why does the rigid-body radius estimate change from 1.926 to 2.043 with seed 2, while the Panda's (ℓ = 0.1 m) stays at 0.125041?
15. What happens when `frame` receives s = NaN, and why does the spline set `x = 0` instead of computing `fmod(NaN, L)`?

### Answers

1. On the rigid body ζ_γ(0) = (e₁ + e₃ + e₅)/√3, so e₅ lies in the span of ζ_γ, e₁ and e₃ and its residual is 6.6e-16: it drops. On the Panda, ζ_γ(0) has a nonzero last entry, so ζ_γ, e₁, …, e₅ already span R⁶ and e₆ drops (residual 2.4e-16). The Panda's ζ_γ(0) has no ω_x, so e₁ is already W-orthogonal to it; its W-norm is √0.01 = 0.1, so normalizing gives 10 e₁ (`src/tube.cpp:34-55`).

2. `PeriodicHermite::build` overwrites node n with node 0 (`include/se3pf/spline.hpp:29-30`), and `frame(L)` wraps L to 0. Measured through `frame`, the gap would always be exactly zero. Only the node values `Y` before `build` show whether exp(−(s/L)Φ) really closed the frame (`src/tube.cpp:207-208`).

3. The gap becomes 7.8e-4, about θ × max |N| = 8e-5 × 10. The closure test (bound 1e-9, `tests/test_tube.cpp:237`) fails, and so do `planes == 2` and `logError < 1e-10` in the holonomy test (`tests/test_tube.cpp:207`; `logError` becomes 7.8e-5). The angle test fails too, because the second angle reads 0 instead of 8.0e-5 (`tests/test_tube.cpp:223`). The N′ test fails at node 0 (error 1.19), where its differences cross the seam. The frame-property tests still pass, because a dropped plane leaves N W-orthonormal and normal, with derivatives that match its values.

4. A truly fixed direction has 1 − λ of rounding size, about 1e-15; the Panda's small plane has 1 − cos θ = 3.2e-9. The threshold 1e-12 sits about three orders of magnitude from both. At 1e-8 the small plane would be dropped (gap 7.8e-4). At 0 a fixed direction whose eigenvalue rounds just below 1 would enter the plane branch with sin θ ≈ 1e-16 < 1e-9, go to the rotation-by-π branch, find no eigenvalue near −1 and throw; both `rotationPlanes` tests then fail that way, although the three tubes (1 − λ₅ < 0) would still build.

5. RK4 leaves H orthogonal only to about 3.5e-11, and `rotationPlanes` assumes an exact rotation: paired eigenvalues and Hu − cu inside the plane. H_r = UVᵀ is the nearest orthogonal matrix, with det +1 since det H > 0. `logError` then measures only the logarithm's accuracy, |exp(Φ) − H_r| = 8.1e-14, instead of the RK4 drift (1.8e-11 against the raw H).

6. One step per interval makes the integrator's nodes the spline's nodes, so nothing is interpolated, and RK4's O(h⁴) matches the cubic Hermite spline's O(h⁴). The closure gap falls by 16 per halving of h: 9.4e-9, 5.9e-10, 3.7e-11 for n = 500, 1000, 2000 on the Panda path.

7. On the path, g_err = γ(s)⁻¹γ(s) = I, so e = Log_I(I) = 0. Then Γ(0) = I and Ad_I = I, so e′ = −Γ(0)⁻¹ Ad_I ζ_γ = −ζ_γ. The second term ⟨e, ζ_γ′⟩_W vanishes because e = 0. So φ′ = ⟨−ζ_γ, ζ_γ⟩_W = −‖ζ_γ‖²_W = −1, since the path has unit speed in W.

8. It holds 1. The loop in `newton` always makes an update before it tests |φ| < 1e-10 (`src/tube.cpp:267-279`), so the count is the number of updates, from 1 to 20. The test at `tests/test_tube.cpp:449-455` checks exactly this.

9. At the root, e_g(η) lies in the normal space, so e_g(η) = N(η)ξ. Multiplying by N(η)ᵀW and using NᵀWN = I gives ξ; without W you get NᵀNξ, which is not ξ unless W = I. On the Panda tube (W = diag(0.01 I, I)) the error is 1.89; on the rigid-body tube (W = I) the two formulas give bit-identical results. Only the Panda tests catch it.

10. A maximum. φ_g(s) = −(d/ds) ½ dist(γ(s), g)², so a root with φ_g′ > 0 is a local maximum of the distance. At 5.614 the code gives φ′ = +1.106 and ‖ξ‖ = 3.465, against φ′ = −0.866 and ‖ξ‖ = 0.6245 at the right root 0.1. Newton finds zeros of φ_g and cannot tell the two apart; that is why `globalProject` starts from the closest of 720 samples.

11. With ξ = 0, e = N·0 = 0. `Exp_I(0)` is exactly I (the small-angle branch of `expSO3` returns I + 0 + 0), so Ad_{Exp_I(0)⁻¹} is exactly I. `Gamma(0)` is exactly I, so column 0 is ζ_γ + I·N′·0 = ζ_γ and the other columns are N. No rounding enters.

12. It does not compile: the temporary binds better to `const Path&&`, which is deleted. Without the default argument the deleted overload would need three arguments, so this two-argument call would match only `Tube(const Path&, const Metric&, int = 2000)` and compile silently. The tube would then keep a reference to a path destroyed at the end of the statement, and every later call would be undefined behaviour.

13. `Metric::distance` returns NaN when the relative rotation angle is within about 1e-6 of π, and `closer` counts a NaN as closer. A few far samples hit that by coincidence: 4 of 512 000 at ε = 0.2177. That ε then fails, and the bisection between 0.1088 and 0.2177 settles at 0.148569, where the next NaN appears just above. With the bound √λ_min dist_I ≥ ε, those far points never reach `Metric::distance`, because dist_I ≥ π there.

14. The rigid-body estimate is set by one random direction of seed 1 (number 13 of `dirs`, d = (−0.678, 0.132, 0.146, −0.402, 0.583)), which finds an intrusion that the ±eᵢ miss. Seeds 2, 3 and 4 do not hit that region, so they give the ±eᵢ value 2.043. The Panda with ℓ = 0.1 m is limited by the coordinate direction −e₄, which every set of directions contains.

15. `frame` passes s to `PeriodicHermite::eval`, which sets x = 0 for a non-finite s, so k = 0 is a valid index, and sets t to NaN. Every Hermite weight is then NaN, so N and N′ come back with NaN entries. Computing `static_cast<int>(NaN / h)` instead would be undefined behaviour and could read outside the node vectors (`include/se3pf/spline.hpp:39-46`); with the check removed, the non-finite test crashes with a segmentation fault (measured).
